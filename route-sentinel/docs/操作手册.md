# route-sentinel 网关操作手册

> 青岛地铁 ITP 平台用户分流网关 - 运维操作指南

## 一、系统概述

### 1.1 功能定位
route-sentinel 是青岛地铁 ITP 平台的**透明分流网关**，负责在旧系统和新系统并行期，根据用户注册状态将流量导向正确系统。

### 1.2 核心特性
- **零侵入**：乘客无感知，APP/设备侧无需改造
- **秒级生效**：路由变更通过 Actuator API 即时生效
- **安全回滚**：支持紧急全切新系统或恢复旧系统
- **可观测**：缓存命中率、路由状态实时监控

### 1.3 架构拓扑
```
乘客 APP/设备
    │
    ▼
Istio VirtualService (fep-app-vr)
    │
    ▼
route-sentinel (ns: itp, port: 9999)
    ├── TraceIdFilter: 透传/生成 traceId
    ├── BizDataExtractor: 提取 thirdUserId
    ├── UserRouteService: Caffeine 缓存判定
    └── UserRouteConfig: 路由匹配转发
         ├── legacy-route → 旧 ITP
         └── new-route → 新 ITP
```

## 三、日常操作

### 3.1 查看当前路由配置
```bash
# 列出所有路由
curl http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/gatewayroutes

# 或透过 NodePort
curl http://<node-ip>:<nodeport>/actuator/gatewayroutes
```

返回示例：
```json
[
  {
    "routeId": "legacy-route",
    "uri": "http://legacy-system:8080",
    "legacy": true
  },
  {
    "routeId": "new-route",
    "uri": "http://new-system:8080",
    "legacy": false
  }
]
```

### 3.2 查看缓存状态
```bash
curl http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/routecache
```

返回示例：
```json
{
  "hitCount": 12345,
  "missCount": 678,
  "hitRate": "94.81%",
  "size": 10234,
  "evictionCount": 0,
  "loadCount": 678,
  "loadFailureCount": 0,
  "totalLoadTime": 45000
}
```

**关键指标**：
- `hitRate < 90%`：警告，可能预热失败或用户激增
- `hitRate < 50%`：严重，缓存基本失效，全量打 Oracle

### 3.3 查看审计日志
```sql
-- 最近 10 条路由变更
SELECT route_id, action, before_uri, after_uri, operator, operate_tms, remark
FROM GATEWAY_ROUTE_CONFIG_AUDIT
ORDER BY operate_tms DESC
LIMIT 10;
```

## 四、路由管理

### 4.1 新增路由
```bash
curl -X POST http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/gatewayroutes/{routeId} \
  -H 'Content-Type: application/json' \
  -d '{
    "uri": "http://target-system:8080",
    "predicates": ["Path=/new-path/**"],
    "operator": "admin-name",
    "remark": "变更说明"
  }'
```

### 4.2 更新路由
```bash
curl -X POST http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/gatewayroutes/{routeId} \
  -H 'Content-Type: application/json' \
  -d '{
    "uri": "http://new-target:8080",
    "predicates": ["Path=/updated-path/**"],
    "operator": "admin-name",
    "remark": "修改目标地址"
  }'
```

### 4.3 删除路由
```bash
curl -X DELETE http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/gatewayroutes/{routeId} \
  -H 'Content-Type: application/json' \
  -d '{
    "operator": "admin-name",
    "remark": "删除原因"
  }'
```

### 4.4 谓词配置语法

#### Path（路径匹配）
```json
"predicates": ["Path=/ci/app/**"]        // 前缀匹配
"predicates": ["Path=/exact/path"]       // 精确匹配
```

#### Query（查询参数匹配）
```json
"predicates": ["Query=channel,alipay"]   // 参数值匹配
"predicates": ["Query=type"]             // 只检查存在
```

#### Header（请求头匹配）
```json
"predicates": ["Header=X-Device-Type,smart"]  // 值匹配
"predicates": ["Header=X-Channel"]             // 只检查存在
```

#### Method（HTTP 方法匹配）
```json
"predicates": ["Method=POST"]              // 单方法
"predicates": ["Method=GET,POST"]          // 多方法（OR 逻辑）
```

#### 组合规则（AND 逻辑）
```json
"predicates": [
  "Path=/ci/app/**",
  "Query=channel,alipay",
  "Method=POST"
]
```

## 五、流量切换操作

### 5.1 灰度发布流程
1. 部署网关 Pod
   ```bash
   kubectl rollout restart deploy/route-sentinel -n itp
   kubectl rollout status deploy/route-sentinel -n itp
   ```

2. 等待 Pod Ready
   ```bash
   kubectl get pod -n itp -l app=route-sentinel -w
   # 等待 STATUS=Running 且 READY=1/1
   ```

3. 注入路由
   ```bash
   # 注入 legacy-route
   curl -X POST http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/gatewayroutes/legacy-route \
     -H 'Content-Type: application/json' \
     -d '{"uri":"http://legacy-system:8080","predicates":["Path=/fep-app/**"],"operator":"deploy-script"}'

   # 注入 new-route
   curl -X POST http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/gatewayroutes/new-route \
     -H 'Content-Type: application/json' \
     -d '{"uri":"http://new-system:8080","predicates":["Path=/fep-app/**"],"operator":"deploy-script"}'
   ```

4. 修改 Istio VS 入口
   ```bash
   kubectl edit vs fep-app-vr -n itp
   # 将 default route 的 destination 改为 route-sentinel-svc:9999
   ```

### 5.2 紧急全切新系统
```bash
# 删除 legacy-route，所有流量走新系统
curl -X DELETE http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/gatewayroutes/legacy-route \
  -H 'Content-Type: application/json' \
  -d '{"operator":"emergency","remark":"紧急全切新系统"}'
```

### 5.3 回滚到旧系统
```bash
# 方法 1：恢复 legacy-route
curl -X POST http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/gatewayroutes/legacy-route \
  -H 'Content-Type: application/json' \
  -d '{"uri":"http://legacy-system:8080","predicates":["Path=/fep-app/**"],"operator":"rollback","remark":"恢复旧系统"}'

# 方法 2：修改 Istio VS 入口指回 fep-app
kubectl edit vs fep-app-vr -n itp
# 将 destination 改回 fep-app-svc:9101
```

## 六、监控告警

### 6.1 VictoriaLogs 查询

#### 查询网关日志
```
app="route-sentinel" | select timestamp, level, message
```

#### 查询缓存命中率
```
app="route-sentinel" AND "hitRate" | last 5m
```

#### 查询路由变更事件
```
app="route-sentinel" AND "路由变更事件" | last 1h
```

### 6.2 告警规则建议
| 指标 | 阈值 | 级别 | 处理 |
|------|------|------|------|
| hitRate | < 90% | 警告 | 检查缓存预热 |
| hitRate | < 50% | 严重 | 检查 Oracle 连通性 |
| loadFailureCount | > 0 | 严重 | 检查数据库连接 |
| 请求延迟 P95 | > 500ms | 警告 | 检查下游响应 |

## 七、故障排查

### 7.1 问题：用户进错系统
**排查步骤**：
1. 确认 `thirdUserId` 是否正确提取
   ```bash
   kubectl logs -n itp deploy/route-sentinel | grep "extractThirdUserId"
   ```
2. 检查 `USER_ITP_REG_INFO` 表
   ```sql
   SELECT * FROM USER_ITP_REG_INFO WHERE third_user_id = 'xxx';
   ```
3. 查看缓存命中率
   ```bash
   curl http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/routecache
   ```

### 7.2 问题：路由不生效
**排查步骤**：
1. 确认路由已注入
   ```bash
   curl http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/gatewayroutes
   ```
2. 检查审计日志
   ```sql
   SELECT * FROM GATEWAY_ROUTE_CONFIG_AUDIT WHERE route_id = 'xxx' ORDER BY operate_tms DESC;
   ```
3. 查看网关日志
   ```bash
   kubectl logs -n itp deploy/route-sentinel | grep "路由"
   ```

### 7.3 问题：网关 5xx 错误
**排查步骤**：
1. 检查 Actuator 落库是否成功
   ```bash
   curl -v http://route-sentinel-svc.itp.svc.cluster.local:9999/actuator/gatewayroutes
   ```
2. 检查数据库连通性
   ```bash
   kubectl run tmp -n itp --rm -it --image=oracle/instantclient -- bash
   sqlplus qditp/<password>@//172.20.222.3:1521/AFCITPDB
   ```

### 7.4 问题：入口没流量
**排查步骤**：
1. 检查 Istio VS 指向
   ```bash
   kubectl get vs fep-app-vr -n itp -o yaml
   ```
2. 检查 Envoy 配置
   ```bash
   kubectl exec -n itp <envoy-pod> -- /usr/local/bin/envoy-cmd config dump
   ```

## 八、性能调优

### 8.1 连接池配置
```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 30      # Oracle 并发连接数
      connection-timeout: 3000   # 连接等待超时
      leak-detection-threshold: 60000  # 连接泄漏检测
```

### 8.2 缓存配置
```java
Caffeine.newBuilder()
    .maximumSize(10_000)           // 最大缓存条目
    .expireAfterWrite(Duration.ofMinutes(5))  // TTL
    .recordStats()                 // 启用统计
    .build(this::loadLegacy);
```

```yaml
logging:
  level:
```

## 九、附录

### 9.1 数据库表结构
```sql
-- 路由配置表
CREATE TABLE GATEWAY_ROUTE_CONFIG (
    route_id    VARCHAR(64) PRIMARY KEY,
    uri         VARCHAR(512) NOT NULL,
    predicates  CLOB,
    order_no    NUMBER NOT NULL,
    created_tms TIMESTAMP DEFAULT SYSTIMESTAMP,
    updated_tms TIMESTAMP DEFAULT SYSTIMESTAMP
);

-- 审计日志表
CREATE TABLE GATEWAY_ROUTE_CONFIG_AUDIT (
    audit_id          NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    route_id          VARCHAR(64) NOT NULL,
    action            VARCHAR(16) NOT NULL,  -- CREATE/UPDATE/DELETE
    before_uri        VARCHAR(512),
    after_uri         VARCHAR(512),
    operator          VARCHAR(64),
    operate_tms       TIMESTAMP DEFAULT SYSTIMESTAMP,
    remark            VARCHAR(256)
);
```
