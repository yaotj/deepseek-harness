# ITP 解约接口改造方案

## 1. 改造范围

本次改造聚焦 ITP 解约相关的 3 个接口/入口：

| 序号 | 接口/入口 | 路径 | 改造说明 |
|------|-----------|------|----------|
| 1 | IF8A-06 请求解约 | `/ci/app/api/contract/dismissal` | 仅记录解约申请，T+4 日前不调用支付平台 |
| 2 | 定时任务执行解约 | 外部调度 | T+4 日扫描扣费失败订单，决定是否调用支付平台解约（本次仅提供接口调用约定，不实现定时任务本身） |
| 3 | IPD03 解约结果回调 | `/ci/app/receiveTerminationResult` | 接收支付平台回调，完成本地清理并通知 APP |

### 2.2 USER_ITP_REG_INFO 处理规则

`USER_ITP_REG_INFO` 表不维护"解约中"状态。所有 account-server 侧表操作均通过 RPC 调用完成，不直接操作其他服务数据库：

| 操作 | 处理方式 |
|------|----------|
| 请求解约（IF8A-06） | 不更新 `USER_ITP_REG_INFO` |
| 解约成功（IPD03） | 调用 `AccountClient.requestRemovePayChannel`，内部会判断并清空 `USER_ITP_REG_INFO` 中对应渠道签约字段 |
| 解约记录 | 由 `account-server` 在清理支付通道时同步写入 `USER_ITP_REG_LOG` |

### 2.3 依赖服务改造说明

本次改造主要落在 pay-sign-server，但以下两个依赖服务需要同步配合：

## 3. 接口一：IF8A-06 请求解约

### 3.1 接口信息

| 属性 | 值 |
|------|-----|
| 路径 | `/ci/app/api/contract/dismissal` |
| 方法 | POST |
| 调用方 | APP |
| 处理类 | `PaySignWorkflow.requestTermination()` |

### 3.2 改造点

| 改造项 | 原实现 | 新实现 |
|--------|--------|--------|
| 调用支付平台解约 | 请求后立即调用 | T+4 日后由定时任务调用 |
| 更新 `USER_ITP_REG_INFO` | 无 | 仍然不更新，解约中状态由 `APP_TERMINATION_REQUEST` 维护 |
| 新增解约申请记录 | 无 | 插入 `APP_TERMINATION_REQUEST`，状态为 `PENDING` |
| 重复申请校验 | 无 | 查询 `PENDING`/`SCANNING` 状态，拒绝重复申请 |

### 3.3 处理逻辑（修改后）

```java
@Transactional(rollbackFor = Exception.class)
public RequestTerminationRespDTO requestTermination(RequestTerminationReqDTO request, String signChannel) {
    RequestTerminationRespDTO response = new RequestTerminationRespDTO();

    try {
        // 1. 参数校验
        if (request == null || StringUtils.isBlank(request.getThirdUserId())) {
            fillError(response, PaySignErrorCodeEnum.INVALID_PARAM, "请求报文不能为空");
            writeLog("REQUEST_TERMINATION", null, null, null, signChannel, null, response);
            return response;
        }

        // 2. 校验用户是否已签约
        PaySignInfo signInfo = paySignInfoMapper.selectByUserAndVendor(
            request.getThirdUserId(),
            request.getPaymentVendor()
        );
        if (signInfo == null) {
            fillError(response, PaySignErrorCodeEnum.USER_NOT_SIGNED, "用户未签约");
            writeLog("REQUEST_TERMINATION", request.getThirdUserId(), request.getRequestSignSeq(),
                     request.getPaymentVendor(), signChannel, request, response);
            return response;
        }

        // 3. 校验是否已存在待处理解约申请
        // 查询条件：TERMINATION_STATUS IN ('PENDING', 'SCANNING')
        // PENDING: 已申请解约但尚未到达 T+4 日扫描
        // SCANNING: 已触发 T+4 日扫描并调用支付平台解约，等待回调结果
        // 以上两种状态均不允许重复申请解约
        AppTerminationRequest existRequest = terminationRequestMapper.selectPendingByUserId(request.getThirdUserId());
        if (existRequest != null) {
            fillError(response, PaySignErrorCodeEnum.ALREADY_TERMINATING, "用户正在解约中");
            writeLog("REQUEST_TERMINATION", request.getThirdUserId(), request.getRequestSignSeq(),
                     request.getPaymentVendor(), signChannel, request, response);
            return response;
        }

        // 4. 插入解约申请记录（状态=PENDING，通知状态=PENDING）
        AppTerminationRequest terminationRequest = new AppTerminationRequest();
        terminationRequest.setRequestSignSeq(request.getRequestSignSeq());
        terminationRequest.setThirdUserId(request.getThirdUserId());
        terminationRequest.setCardId(request.getCardId());
        terminationRequest.setCardType(request.getCardType());
        terminationRequest.setPaymentVendor(request.getPaymentVendor());
        terminationRequest.setTerminationStatus("PENDING");
        terminationRequest.setNotifyStatus("PENDING");
        terminationRequest.setNotifyRetryCount(0);
        terminationRequest.setRequestTime(LocalDateTime.now());
        terminationRequestMapper.insert(terminationRequest);

        // 5. 返回受理成功，不调用支付平台，不更新 USER_ITP_REG_INFO
        fillSuccess(response);
        response.setRequestSignSeq(request.getRequestSignSeq());
        writeLog("REQUEST_TERMINATION", request.getThirdUserId(), request.getRequestSignSeq(),
                 request.getPaymentVendor(), signChannel, request, response);
        return response;

    } catch (Exception e) {
        log.error("处理请求解约异常", e);
        fillError(response, PaySignErrorCodeEnum.SYSTEM_ERROR, PaySignErrorCodeEnum.SYSTEM_ERROR.getMsg());
        writeLog("REQUEST_TERMINATION", request != null ? request.getThirdUserId() : null,
                 request != null ? request.getRequestSignSeq() : null,
                 request != null ? request.getPaymentVendor() : null,
                 signChannel, request, response);
        return response;
    }
}
```

### 3.4 状态约束

1. 同一用户只能有一个处于 `PENDING` 或 `SCANNING` 状态的解约申请。
2. `PENDING` 状态下不调用支付平台解约。
3. `USER_ITP_REG_INFO` 在解约申请阶段不做任何更新。
4. **解约流水号约定**：`APP_TERMINATION_REQUEST.REQUEST_SIGN_SEQ` 与本次解约请求使用的签约流水号保持一致（复用原签约流水号），作为后续 `executeTermination`、IPD03 回调以及本地签约记录查询的唯一键。

## 4. 接口二：定时任务执行解约（接口约定）

> 说明：定时任务本身由外部系统实现，本次仅约定 pay-sign-server 对外暴露的内部接口。

### 4.1 外部定时任务职责

> **约定**：定时任务由外部系统实现，pay-sign-server 仅提供下方 3 个内部接口，不暴露查询待扫描记录的接口。

1. 外部定时任务自行扫描 `APP_TERMINATION_REQUEST`，查询 `REQUEST_TIME <= 当前时间 - 4 天` 且 `TERMINATION_STATUS = 'PENDING'` 的记录。
2. 对每条记录调用 pay-sign-server 内部接口，判断该用户是否存在扣费失败订单。
3. 根据返回结果：
   - 无扣费失败订单 → 调用执行支付平台解约接口。
   - 存在扣费失败订单 → 调用通知 APP 解约失败接口。

### 4.2 扣费失败订单查询 SQL 示例

```sql
SELECT COUNT(1) FROM GATE_TXN_PAY
WHERE THIRD_USER_ID = :thirdUserId
  AND SIGN_CHANNEL_CODE = :signChannelCode
  AND DEBIT_STATUS = 'FAIL'
  AND CREATE_TIME >= :requestTime
```

> `GATE_TXN_PAY` 表在 gate-txn-pay-server，pay-sign-server 通过 `GateTxnPayClient.hasFailedOrder` 查询，不直接操作其表。
> 
> 通过 `CREATE_TIME >= :requestTime` 限定只统计解约申请时间之后的扣费失败订单，避免历史失败订单影响解约判定。

### 4.3 提供的内部接口

| 接口 | 路径 | 用途 |
|------|------|------|
| 查询扣费失败订单 | `POST /internal/termination/checkFailedOrders` | 定时任务扫描前先调用，判断该用户是否存在扣费失败订单 |
| 执行支付平台解约 | `POST /internal/termination/execute` | 定时任务扫描无扣费失败订单后，调用该接口触发支付平台解约 |
| 通知 APP 解约失败 | `POST /internal/termination/notifyFailed` | 定时任务扫描存在扣费失败订单后，调用该接口通知 APP |

#### 4.5.4 处理逻辑

```java
@PostMapping("/checkFailedOrders")
public CheckFailedOrdersRespDTO checkFailedOrders(@RequestBody CheckFailedOrdersReqDTO request) {
    CheckFailedOrdersRespDTO response = new CheckFailedOrdersRespDTO();

    try {
        // 1. 参数校验
        if (request == null || StringUtils.isBlank(request.getThirdUserId())
                || StringUtils.isBlank(request.getPaymentVendor())
                || request.getRequestTime() == null) {
            fillError(response, PaySignErrorCodeEnum.INVALID_PARAM, "请求报文不能为空");
            return response;
        }

        // 2. 通过 RPC 调用 gate-txn-pay-server 查询扣费失败订单
        HasFailedOrderReqDTO hasFailedOrderReq = new HasFailedOrderReqDTO();
        hasFailedOrderReq.setThirdUserId(request.getThirdUserId());
        hasFailedOrderReq.setSignChannelCode(request.getPaymentVendor());
        hasFailedOrderReq.setRequestTime(request.getRequestTime());
        HasFailedOrderResult result = gateTxnPayClient.hasFailedOrder(hasFailedOrderReq);

        if (!"0000".equals(result.getRetCode())) {
            fillError(response, PaySignErrorCodeEnum.SYSTEM_ERROR, "查询扣费订单失败");
            return response;
        }

        response.setHasFailedOrder(result.isHasFailedOrder());
        fillSuccess(response);
        return response;

    } catch (Exception e) {
        log.error("查询扣费失败订单异常", e);
        fillError(response, PaySignErrorCodeEnum.SYSTEM_ERROR, "系统错误");
        return response;
    }
}
```

```java
@RestController
@RequestMapping("/internal/termination")
public class TerminationInternalController {

    @Autowired
    private TerminationInternalService terminationInternalService;

    @PostMapping("/execute")
    public BaseRespDTO executeTermination(@RequestBody ExecuteTerminationReqDTO request) {

```

```java
@Service
public class TerminationInternalServiceImpl implements TerminationInternalService {

    @Autowired
    private AppTerminationRequestMapper terminationRequestMapper;

    @Autowired
    private PaySignWorkflow paySignWorkflow;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public BaseRespDTO executeTermination(ExecuteTerminationReqDTO request) {
        BaseRespDTO response = new BaseRespDTO();

        try {
            // 1. 参数校验
            if (request == null || StringUtils.isBlank(request.getRequestSignSeq())) {
                fillError(response, PaySignErrorCodeEnum.INVALID_PARAM, "请求报文不能为空");
                return response;
            }

            // 2. 查询解约申请
            AppTerminationRequest terminationRequest = terminationRequestMapper
                .selectByRequestSignSeq(request.getRequestSignSeq());
            if (terminationRequest == null) {
                fillError(response, PaySignErrorCodeEnum.TERMINATION_REQUEST_NOT_FOUND, "解约申请不存在");
                return response;
            }

            // 3. 幂等性校验：已经是 SCANNING 或终态，直接返回成功
            String status = terminationRequest.getTerminationStatus();
            if ("SCANNING".equals(status) || "SUCCESS".equals(status) || "FAILED".equals(status)) {
                fillSuccess(response);
                return response;
            }

            // 4. 校验状态必须为 PENDING
            if (!"PENDING".equals(status)) {
                fillError(response, PaySignErrorCodeEnum.TERMINATION_REQUEST_NOT_FOUND, "解约申请状态不正确");
                return response;
            }

            // 5. 更新状态为 SCANNING，记录扫描时间
            terminationRequestMapper.updateStatus(request.getRequestSignSeq(), "SCANNING");
            terminationRequestMapper.updateScanTime(request.getRequestSignSeq(), LocalDateTime.now());

            // 6. 调用支付平台解约接口
            PaySignGatewayResponse gatewayResponse = paySignWorkflow.requestGatewaySimple(
                paySignProperties.getTerminationPath(),
                paySignWorkflow.buildDismissalBizData(request.getRequestSignSeq())
            );

            // 7. 仅记录流水，最终状态以 IPD03 回调为准
            paySignWorkflow.writeLog("EXECUTE_TERMINATION", request.getThirdUserId(), request.getRequestSignSeq(),
                    request.getPaymentVendor(), null, request, gatewayResponse);

            fillSuccess(response);
            return response;

        } catch (Exception e) {
            log.error("执行支付平台解约异常", e);
            throw new TerminationException("执行支付平台解约异常，requestSignSeq="
                + (request != null ? request.getRequestSignSeq() : null), e);
        }
    }
}
```

#### 4.6.4 分支处理说明

| 场景 | 处理 |
|------|------|
| 已经是 SCANNING/SUCCESS/FAILED 状态 | 幂等返回成功，不重复调用支付平台 |
| 状态更新为 SCANNING 后调用支付平台成功 | 返回成功，等待 IPD03 回调 |
| 状态更新为 SCANNING 后调用支付平台异常 | 抛出 `TerminationException`，触发 `@Transactional` 回滚，状态保持 PENDING，定时任务下次扫描重试 |

```java
@Override
@Transactional(rollbackFor = Exception.class)
public BaseRespDTO notifyTerminationFailed(NotifyTerminationFailedReqDTO request) {
    BaseRespDTO response = new BaseRespDTO();

    try {
        // 1. 参数校验
        if (request == null || StringUtils.isBlank(request.getRequestSignSeq())) {
            fillError(response, PaySignErrorCodeEnum.INVALID_PARAM, "请求报文不能为空");
            return response;
        }

        // 2. 查询解约申请
        AppTerminationRequest terminationRequest = terminationRequestMapper
            .selectByRequestSignSeq(request.getRequestSignSeq());
        if (terminationRequest == null) {
            fillError(response, PaySignErrorCodeEnum.TERMINATION_REQUEST_NOT_FOUND, "解约申请不存在");
            return response;
        }

        // 3. 幂等性校验：已失败则直接返回成功
        if ("FAILED".equals(terminationRequest.getTerminationStatus())) {
            fillSuccess(response);
            return response;
        }

        // 4. 校验状态必须为 PENDING
        if (!"PENDING".equals(terminationRequest.getTerminationStatus())) {
            fillError(response, PaySignErrorCodeEnum.TERMINATION_REQUEST_NOT_FOUND, "解约申请状态不正确");
            return response;
        }

        // 5. 更新解约申请表为 FAILED，并记录失败原因
        terminationRequestMapper.updateFailReason(
            request.getRequestSignSeq(),
            "FAILED",
            StringUtils.defaultString(request.getFailReason(), "存在扣费失败订单")
        );
        terminationRequestMapper.updateCompleteTime(request.getRequestSignSeq(), LocalDateTime.now());

        // 6. 设置通知状态为待通知
        terminationRequestMapper.updateNotifyStatus(request.getRequestSignSeq(), "PENDING", null, null);

        // 7. 异步通知 APP 解约失败
        asyncNotifyTerminationFailed(terminationRequest, request);

        fillSuccess(response);
        return response;

    } catch (Exception e) {
        log.error("通知APP解约失败异常", e);
        fillError(response, PaySignErrorCodeEnum.SYSTEM_ERROR, PaySignErrorCodeEnum.SYSTEM_ERROR.getMsg());
        return response;
    }
}
```

## 5. 接口三：IPD03 解约结果回调

### 5.1 接口信息

| 属性 | 值 |
|------|-----|
| 路径 | `/ci/app/receiveTerminationResult` |
| 方法 | POST |
| 调用方 | 支付平台 |
| 处理类 | `PaySignWorkflow.receiveTerminationResult()` |

### 5.2 回调状态说明

`ReceiveTerminationResultReqDTO.status` 字段取值：

| 值 | 含义 |
|----|------|
| `SUCCESS` | 支付平台解约成功 |
| `FAILED` | 支付平台解约失败 |

### 5.3 处理逻辑（修改后）

```java
@Transactional(rollbackFor = Exception.class)
public BaseRespDTO receiveTerminationResult(ReceiveTerminationResultReqDTO request, String signChannel) {
    BaseRespDTO response = new BaseRespDTO();

    try {
        // 1. 参数校验
        if (request == null || StringUtils.isBlank(request.getRequestSignSeq())) {
            fillError(response, PaySignErrorCodeEnum.INVALID_PARAM, "请求报文不能为空");
            return response;
        }

        // 2. 幂等性校验：已处理过的回调直接返回成功
        AppTerminationRequest terminationRequest = terminationRequestMapper
            .selectByRequestSignSeq(request.getRequestSignSeq());
        if (terminationRequest != null
                && ("SUCCESS".equals(terminationRequest.getTerminationStatus())
                    || "FAILED".equals(terminationRequest.getTerminationStatus()))) {
            fillSuccess(response);
            return response;
        }

        // 3. 校验解约申请存在且状态为 SCANNING
        if (terminationRequest == null || !"SCANNING".equals(terminationRequest.getTerminationStatus())) {
            fillError(response, PaySignErrorCodeEnum.TERMINATION_REQUEST_NOT_FOUND, "解约申请不存在或状态不正确");
            return response;
        }

        // 4. 判断解约结果
        boolean isSuccess = "SUCCESS".equals(request.getStatus());

        if (isSuccess) {
            // 5. 先调用 account-server RPC 清理支付通道并清空注册信息
            // requestRemovePayChannel 已复用现有接口，内部会：
            // 1) 删除 APP_USER_PAY_CHANNEL 指定渠道记录
            // 2) 若 USER_ITP_REG_INFO.CHANNEL = paymentVendor，清空 CHANNEL/THIRD_PAY_ID/REQ_CONTRACT_NO
            // 3) 插入 USER_ITP_REG_LOG 解约记录（需 account-server 侧扩展）
            boolean removeSuccess = removeAccountPayChannel(request.getThirdUserId(), request.getPaymentVendor(),
                                                            request.getCardId(), request.getCardType());
            if (!removeSuccess) {
                // 清理失败时抛出异常，触发事务回滚，状态保持 SCANNING
                // 支付平台会重试回调，幂等性校验保证不会重复清理
                throw new TerminationException("清理账户支付通道失败，requestSignSeq=" + request.getRequestSignSeq());
            }

            // 6. 查询签约记录
            PaySignInfo signInfo = paySignInfoMapper.selectBySeq(
                request.getRequestSignSeq(),
                request.getPaymentVendor()
            );
            if (signInfo == null) {
                // 清理已成功但本地无签约记录，视为该次回调无需再处理本地签约表
                log.warn("解约回调成功但本地签约记录不存在，requestSignSeq={}", request.getRequestSignSeq());
            } else {
                // 7. 删除指定渠道的签约记录
                paySignInfoMapper.deleteByUserAndVendor(request.getThirdUserId(), request.getPaymentVendor());
            }

            // 8. 写入签约流水日志
            PaySignRequest logRecord = new PaySignRequest();
            logRecord.setOperationType("RECEIVE_TERMINATION_RESULT");
            logRecord.setSignStatus("UNSIGNED");
            logRecord.setThirdUserId(request.getThirdUserId());
            logRecord.setPaymentVendor(request.getPaymentVendor());
            logRecord.setCardId(request.getCardId());
            logRecord.setCardType(request.getCardType());
            logRecord.setRequestSignSeq(request.getRequestSignSeq());
            logRecord.setRequestBody(JSON.toJSONString(request));
            paySignRequestMapper.insert(logRecord);

            // 9. 更新解约申请表为最终成功状态
            terminationRequestMapper.updateStatus(request.getRequestSignSeq(), "SUCCESS");
            terminationRequestMapper.updateCompleteTime(request.getRequestSignSeq(), LocalDateTime.now());

            // 10. 设置通知状态为待通知
            terminationRequestMapper.updateNotifyStatus(request.getRequestSignSeq(), "PENDING", null, null);

            // 11. 异步通知 APP 解约成功
            asyncNotifyTerminationResult(terminationRequest, signInfo, request);

        } else {
            // 12. 更新解约申请表为最终失败状态
            terminationRequestMapper.updateFailReason(
                request.getRequestSignSeq(),
                "FAILED",
                StringUtils.defaultString(request.getStatus(), "支付平台解约失败")
            );
            terminationRequestMapper.updateCompleteTime(request.getRequestSignSeq(), LocalDateTime.now());

            // 13. 设置通知状态为待通知
            terminationRequestMapper.updateNotifyStatus(request.getRequestSignSeq(), "PENDING", null, null);

            // 14. 异步通知 APP 解约失败
            asyncNotifyTerminationFailed(terminationRequest, request);
        }

        fillSuccess(response);
        return response;

    } catch (TerminationException e) {
        log.error("处理解约结果回调异常", e);
        throw e;  // 抛出业务异常，触发 @Transactional 回滚，由全局异常处理返回 9999
    } catch (Exception e) {
        log.error("处理解约结果回调异常", e);
        throw new TerminationException("处理解约结果回调异常，requestSignSeq="
            + (request != null ? request.getRequestSignSeq() : null), e);  // 包装后抛出，触发回滚
    }
}
```

### 5.4 与原实现的差异

| 对比项 | 原实现 | 新实现 |
|--------|--------|--------|
| 删除指定渠道签约记录 | ✅ | ✅ |
| 写入签约流水日志 | ✅ | ✅ |
| 清理支付通道 | ✅ | ✅ |
| 更新 ITP 注册信息 | 无 | 通过 `AccountClient` RPC 清空匹配渠道的签约字段并写入 LOG |
| 更新解约申请表 | 无 | ✅ 更新最终状态 |
| 幂等性校验 | 无 | ✅ 防止重复回调 |
| 异步通知 APP | ✅ | ✅ 保持现有逻辑 |
| 跨服务表操作 | 无 | ✅ 通过 RPC，不直接操作其他服务数据库 |
| 异常回滚 | 无 | ✅ `removeAccountPayChannel` 失败时回滚 |

### 5.5 异常处理说明

- `removeAccountPayChannel` 返回 `false` 时，抛出 `TerminationException`，触发 `@Transactional` 回滚。
- 回滚后状态保持 `SCANNING`，本地签约记录未被删除，支付平台会重试回调。
- 幂等性校验保证重复回调不会重复清理。
- 所有异常均包装为 `TerminationException` 抛出，由全局异常处理器统一返回 `9999` 响应给支付平台。

> **异常响应约定**：IPD03 回调方法内出现任何未预期的系统异常时，均通过抛出 `TerminationException` 触发事务回滚，并由 `@ControllerAdvice` 统一返回 `resultCode=9999` 的 `BaseRespDTO`，确保支付平台能收到明确失败响应并重试回调。

## 7. 解约申请表状态机

### 7.1 状态定义

| 状态值 | 状态名称 | 说明 | 负责入口 |
|--------|----------|------|----------|
| PENDING | 待处理 | 解约申请已受理，等待 T+4 日扫描 | IF8A-06 |
| SCANNING | 扫描中 | T+4 日扫描完成，无扣费失败订单，已调用支付平台解约 | 定时任务 |
| SUCCESS | 解约成功 | 支付平台解约成功，完成所有清理 | IPD03 |
| FAILED | 解约失败 | 存在扣费失败订单或支付平台解约失败 | 定时任务 / IPD03 |

### 7.2 状态流转图

```
INIT → PENDING → SCANNING → SUCCESS
              │            │
              │            ▼
              │          FAILED
              │            │
              └────────────┘
```

### 7.3 流转路径说明

| 流转 | 触发条件 | 负责入口 |
|------|----------|----------|
| INIT → PENDING | IF8A-06 请求解约 | IF8A-06 |
| PENDING → SCANNING | T+4 日扫描，无扣费失败订单 | 定时任务 |
| PENDING → FAILED | T+4 日扫描，存在扣费失败订单 | 定时任务 |
| SCANNING → SUCCESS | IPD03 回调 status=SUCCESS，且 account-server 清理成功 | IPD03 |
| SCANNING → FAILED | IPD03 回调 status=FAILED | IPD03 |

### 7.4 关键约束

1. **唯一性**：同一 `REQUEST_SIGN_SEQ` 只能有一个解约申请记录。
2. **幂等性**：重复回调直接返回成功。
3. **最终状态权威**：`SUCCESS`/`FAILED` 以 IPD03 回调结果为准。
4. **不可重复申请**：`PENDING` 或 `SCANNING` 状态下不允许重复申请解约。
5. **回调权威约束**：`APP_TERMINATION_REQUEST` 的最终状态以 IPD03 回调结果为准，定时任务仅触发调用支付平台，不直接设置最终状态。
