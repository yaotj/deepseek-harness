# IF8A-77 更换第三方渠道码默认支付方式 实现计划

## 1. 接口概述

| 项目 | 内容 |
|------|------|
| 接口编号 | IF8A-77 |
| 接口名称 | 更换第三方渠道码默认支付方式（新增） |
| 接口地址 | `/app/requestUpdateChannelDefaultContract` |
| 调用方式 | POST |
| 主要用途 | 更换第三方渠道码默认支付方式，主要用于其他城市 SDK |

### 1.1 请求参数

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| thirdUserId | String | 是 | 用户 ID |
| channel | String | 是 | 支付渠道 |
| cardIssueCode | String | 是 | 第三方渠道码 |
| regSignSeq | String | 是 | 签约流水号 |

### 1.2 应答参数

| 字段 | 类型 | 说明 |
|------|------|------|
| retCode | string | 返回码 |
| retMsg | string | 返回消息 |

## 2. 现有代码分析

### 2.1 fep-app 侧（BFF 层）

- **控制器**：`AppAccountController`（`/ci/app` 路径下）
  - 现有模式：`@PostMapping` + `@ModelAttribute CommonFormRequest` + `parseBizData()` 解析业务 DTO
  - 参考接口：`requestSetDefaultPayChannel`（IF8A-24）

- **Service 层**：
  - 接口：`AccountAppService`
  - 实现：`AccountAppServiceImpl`（纯 RPC 转发）

- **RPC 客户端**：`AccountClient`（继承 `ProxyWebClient`）
  - 使用 `postJsonAndGetResponse` 进行 JSON RPC 调用

### 2.2 account-server 侧（业务层）

- **控制器**：`RequestApplicationController`
  - 现有模式：`@PostMapping` + `@RequestBody`，直接委托给 Service

- **Service 层**：
  - 接口：`AccountApplicationService`
  - 实现：`AccountApplicationServiceImpl`
  - 参考实现：`requestSetDefaultPayChannel`（IF8A-24）

- **数据层**：
  - `UserItpRegInfoMapper`：包含 `updateDefaultPayChannelById`（仅更新 thirdPayId/channel/reqContractNo）
  - `UserPayChannelMapper`：仅包含 select/insert/delete，**缺少 update 方法**

### 2.3 关键发现

1. IF8A-24 通过读取 `USER_PAY_CHANNEL` 后更新 `USER_ITP_REG_INFO`；IF8A-77 因参数中直接携带 `regSignSeq`（对应 `reqContractNo`），无需读取支付通道即可直接更新。
2. `USER_PAY_CHANNEL` 表结构**不包含** `CARD_ISSUE_CODE` 字段，因此无法在该表中同步更新第三方渠道码。
3. `updateDefaultPayChannelById` 仅更新 `THIRD_PAY_ID/CHANNEL/REQ_CONTRACT_NO` 三个字段，若扩展该 SQL 会破坏 IF8A-24 的 null 安全特性，因此需要新增 Mapper 方法。
4. `COMPANION_FLAG` 字段用于标识用户类型：`Y`=同行票，`C`=第三方票。IF8A-77 专门针对第三方渠道用户（`COMPANION_FLAG='C'`）。
5. 签约信息存储在 pay-sign-server 的 `APP_PAY_SIGN_INFO` 表中，通过 `REQUEST_SIGN_SEQ` 可查询到 `PAY_ACCOUNT_ID`。

**（2）Service 实现**
- 文件：`account-server/src/main/java/com/chinasofti/huateng/account/service/impl/AccountApplicationServiceImpl.java`
- 新增业务逻辑：

  ```java
  @Override
  @Transactional(rollbackFor = Exception.class)
  public RequestUpdateChannelDefaultContractResult requestUpdateChannelDefaultContract(RequestUpdateChannelDefaultContractReqDTO request) {
      RequestUpdateChannelDefaultContractResult response = new RequestUpdateChannelDefaultContractResult();
      try {
          log.info("开始处理IF8A-77更换第三方渠道码默认支付方式, request={}", JSON.toJSONString(request));
          
          // 1. 参数校验
          String validMsg = validateUpdateChannelDefaultContractRequest(request);
          if (validMsg != null) {
              response.setRetCode(AccountErrorCodeEnum.INVALID_PARAM.getCode());
              response.setRetMsg(validMsg);
              log.warn("IF8A-77参数校验失败, request={}, msg={}", JSON.toJSONString(request), validMsg);
              return response;
          }

          String thirdUserId = request.getThirdUserId().trim();
          String channel = request.getChannel().trim();
          String cardIssueCode = request.getCardIssueCode().trim();
          String regSignSeq = request.getRegSignSeq().trim();

          // 2. 根据 thirdUserId、cardIssueCode 和 COMPANION_FLAG='C' 查询用户注册信息
          UserItpRegInfo regInfo = userItpRegInfoMapper.selectByThirdUserIdAndCardIssueCodeAndCompanionFlag(
                  thirdUserId, cardIssueCode, "C");
          if (regInfo == null || regInfo.getDelYn() == null || regInfo.getDelYn() != 1) {
              response.setRetCode(AccountErrorCodeEnum.NO_ACCOUNT_CARD.getCode());
              response.setRetMsg(AccountErrorCodeEnum.NO_ACCOUNT_CARD.getMsg());
              log.warn("IF8A-77未找到有效第三方渠道用户, thirdUserId={}, cardIssueCode={}", thirdUserId, cardIssueCode);
              return response;
          }

          // 3. 根据 regSignSeq 查询签约信息表，获取 PAY_ACCOUNT_ID
          PaySignInfo signInfo = paySignClient.querySignInfoBySeq(regSignSeq);
          if (signInfo == null || !StringUtils.hasText(signInfo.getPayAccountId())) {
              response.setRetCode(AccountErrorCodeEnum.INVALID_SIGN_DATA.getCode());
              response.setRetMsg("签约信息不存在或PAY_ACCOUNT_ID为空");
              log.warn("IF8A-77签约信息不存在, regSignSeq={}", regSignSeq);
              return response;
          }

          // 4. 更新 USER_ITP_REG_INFO：THIRD_PAY_ID / CHANNEL / REQ_CONTRACT_NO
          regInfo.setThirdPayId(signInfo.getPayAccountId());
          regInfo.setChannel(channel);
          regInfo.setReqContractNo(regSignSeq);
          int updated = userItpRegInfoMapper.updateChannelDefaultContractById(regInfo);
          if (updated <= 0) {
              response.setRetCode(AccountErrorCodeEnum.FAIL.getCode());
              response.setRetMsg(AccountErrorCodeEnum.FAIL.getMsg());
              log.warn("IF8A-77更新用户默认支付方式失败, thirdUserId={}, regInfoId={}", thirdUserId, regInfo.getId());
              return response;
          }

          response.setRetCode(AccountErrorCodeEnum.SUCCESS.getCode());
          response.setRetMsg(AccountErrorCodeEnum.SUCCESS.getMsg());
          log.info("IF8A-77更换第三方渠道码默认支付方式成功, thirdUserId={}, channel={}, cardIssueCode={}, regSignSeq={}, payAccountId={}",
                  thirdUserId, channel, cardIssueCode, regSignSeq, signInfo.getPayAccountId());
          return response;
      } catch (Exception e) {
          log.error("处理IF8A-77更换第三方渠道码默认支付方式异常, request={}", JSON.toJSONString(request), e);
          response.setRetCode(AccountErrorCodeEnum.SYSTEM_ERROR.getCode());
          response.setRetMsg(AccountErrorCodeEnum.SYSTEM_ERROR.getMsg());
          return response;
      }
  }
  ```

## 4. 业务规则与假设

### 4.1 参数校验规则
- 所有参数（thirdUserId、channel、cardIssueCode、regSignSeq）均不允许为空
- 校验失败返回错误码 `8001`（INVALID_PARAM）

### 4.2 用户有效性校验
- 必须存在满足以下条件的有效开户记录：
  - `THIRD_USER_ID` = 请求中的 thirdUserId
  - `CARD_ISSUE_CODE` = 请求中的 cardIssueCode
  - `COMPANION_FLAG` = 'C'（第三方渠道用户）
  - `DEL_YN` = 1
- 校验失败返回错误码 `8004`（NO_ACCOUNT_CARD）

### 4.3 签约信息校验
- 必须存在 `REQUEST_SIGN_SEQ` = regSignSeq 的有效签约记录
- 签约记录中的 `PAY_ACCOUNT_ID` 不能为空
- 校验失败返回错误码 `8014`（INVALID_SIGN_DATA）

### 4.4 数据更新策略
1. **USER_ITP_REG_INFO**：必须更新以下字段：
   - `THIRD_PAY_ID` = 签约信息表中的 `PAY_ACCOUNT_ID`
   - `CHANNEL` = 请求中的 channel
   - `REQ_CONTRACT_NO` = 请求中的 regSignSeq
2. 更新在 `@Transactional` 事务中执行，保证数据一致性

### 4.5 错误码定义

| 错误码 | 含义 | 触发场景 |
|--------|------|----------|
| 0000 | 成功 | 更新成功 |
| 8001 | 无效的参数 | 参数为空或格式非法 |
| 8004 | 没有账号卡片数据 | 用户未开户、已注销或非第三方渠道用户 |
| 8014 | 无效的签约数据 | 签约信息不存在或PAY_ACCOUNT_ID为空 |
| 9999 | 失败 | 数据库更新影响行数为 0 |
| 9001 | 系统内部错误 | 未捕获异常 |
