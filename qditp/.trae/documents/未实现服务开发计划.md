> 生成日期：2026-06-26

## 一、Summary

本项目（qd-itp）是一个青岛地铁 ITP（智能票务平台）微服务系统，当前已实现约 20+ 个接口，但仍有 **30+ 个接口未实现**。本计划按业务优先级和技术依赖关系，将未实现接口分为 4 个实施阶段，每个阶段包含具体的文件变更清单、代码模式和验证步骤。

**核心目标**：
1. 补齐高优先级核心业务接口（补站、交易记录、退款查询、行业数据推送、黑名单/退款通知）
2. 补充缺失错误码枚举
3. 按 Phase 2 路线图实现新增功能接口

#### 1.2 实现 IF8A-04 请求自助补站

**接口路径**：`POST /ci/app/requestExcessFare`

**请求参数**：

| 字段 | 类型 | 说明 |
|------|------|------|
| thirdUserId | string | 第三方用户id |
| cardId | String | 地铁会员卡号 |
| cardType | String | 卡类型编码 |
| upgradeAreaType | String | 01：补进站 02：补出站 |
| upgradeStationCode | String | 补进/出站编码 |
| upgradeReason | String | 更新原因预留 |
| upgradeDateTime | String | 更新操作时间 YYYYMMDDHHmmss |

**应答参数**：

| 字段 | 类型 | 说明 |
|------|------|------|
| retCode | string | 返回码 |
| retMsg | string | 返回消息 |

**业务逻辑**：
1. 验证用户注册状态（未注册返回 8004，解约审核中返回 8008）
2. 验证卡号与用户匹配（不匹配返回 8006）
3. 调用 BOM/ACC 执行补站操作（通过 online-server 或直接调用 ACC）
4. 更新 QRCodeStatus 状态（codeStatus: 80=补出站, 81=补进站）
5. 记录交易明细
6. 异步推送行业数据更新（IF8B-01）

**变更文件**：

|------|---------|

| `model/src/main/java/com/chinasofti/huateng/model/app/RequestExcessFareResult.java` | **新建**，包含 retCode/retMsg |
| `fep-app-server/src/main/java/com/chinasofti/huateng/fep/app/controller/FepAppController.java` | 新增 `@PostMapping("/requestExcessFare")` 方法，解析 CommonFormRequest → bizData，委托 AppService |

## 六、Implementation Notes

### 6.1 代码风格规范

- 所有接口方法加 Javadoc，标注规范编号（如 `IF8A-04`）
- Controller 层只做参数解析和委托，不包含业务逻辑
- Service 层实现业务逻辑，使用 `@Transactional(rollbackFor = Exception.class)`
- 参数校验在 Service 层开头进行，返回错误消息字符串，null 表示通过
- 异常捕获统一返回 `SYSTEM_ERROR("9001")`

### 6.2 日志规范

```java
log.info("IF8A-04 请求自助补站, 请求参数: {}", JSON.toJSONString(request));
log.warn("IF8A-04 参数校验失败, msg={}", validMsg);
log.error("IF8A-04 处理异常, request={}", JSON.toJSONString(request), e);
```

### 6.3 数据库变更原则

- 新增表需同步创建 `xxxMapper.java` + `xxxMapper.xml`
- 存量表新增字段需在对应 Entity 和 Mapper 中同步
- 所有 DML 操作需有日志或审计字段
