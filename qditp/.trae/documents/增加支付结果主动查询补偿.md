# 增加支付结果主动查询补偿

> 记录日期：2026-07-03  
> 涉及模块：alipay-pay-sign-server

---

## 一、当前状态分析

### 1.1 现有支付流程

```
fep-dev-server → alipay-pay-sign-server.requestPay()
    ↓
    1. 参数校验、签约查询、幂等检查
    2. 写入 ALIPAY_PAY_LOG（初始 payStatus=FAIL）
    3. 同步调用支付中心 requestPay
    4. 根据支付中心响应立即更新 payStatus（SUCCESS/FAIL）
    ↓
返回结果给 fep-dev-server
```

### 1.2 现有查询接口

`AlipayPaySignServiceImpl.payQuery()` 已实现支付结果查询功能：
- 调用 `payCenterClient.payQuery(bizDataMap)` 
- 查询支付中心 `/api/payment/payQuery` 接口
- 但**仅用于外部主动查询**，不更新本地 `ALIPAY_PAY_LOG` 状态

### 1.3 问题

| 问题 | 影响 |
|------|------|
| `requestPay` 同步调用支付中心，若网络异常/超时/支付中心返回失败，本地记录为 `FAIL` | 实际可能已扣款成功，但本地状态错误 |
| 无补偿机制 | 失败订单无法自动恢复，需人工干预 |
| 无重试机制 | 临时故障导致扣费失败 |
| 支付中心可能有异步回调，但项目未实现回调接收 | 依赖回调不如主动查询可靠 |

## 二、 Proposed Changes

### 2.1 扩展 AlipayPayLog 实体

**文件**：`alipay-pay-sign-server/src/main/java/com/chinasofti/huateng/alipay/paysign/entity/AlipayPayLog.java`

**新增字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `queryCount` | `Integer` | 已查询次数，防止无限重试 |
| `lastQueryTime` | `LocalDateTime` | 最后查询时间 |

**原因**：记录查询次数和最后查询时间，避免对已确定状态的订单重复查询。

### 2.2 扩展 Mapper 层

**文件**：`alipay-pay-sign-server/src/main/java/com/chinasofti/huateng/alipay/paysign/mapper/AlipayPayLogMapper.java`

**新增方法**：
```java
List<AlipayPayLog> selectPendingPayLogs(@Param("maxQueryCount") int maxQueryCount, 
                                        @Param("intervalMinutes") int intervalMinutes,
                                        @Param("limit") int limit);
int updatePayStatus(@Param("paySeq") String paySeq, 
                    @Param("payStatus") String payStatus, 
                    @Param("resultCode") String resultCode,
                    @Param("resultMsg") String resultMsg,
                    @Param("tradeNo") String tradeNo,
                    @Param("responseBody") String responseBody,
                    @Param("queryCount") int queryCount,
                    @Param("updateTime") LocalDateTime updateTime);
```

**文件**：`alipay-pay-sign-server/src/main/resources/mapper/AlipayPayLogMapper.xml`

**新增 SQL**：
- `selectPendingPayLogs`：查询 `payStatus != 'SUCCESS'`、`queryCount < maxQueryCount`、`lastQueryTime` 超过间隔时间 或 `lastQueryTime IS NULL` 的订单
- `updatePayStatus`：更新支付状态及相关字段

### 2.3 实现补偿 Service

**文件**：`alipay-pay-sign-server/src/main/java/com/chinasofti/huateng/alipay/paysign/service/impl/AlipayPaySignCompensationServiceImpl.java`（新建）

**核心逻辑**：
```java
public void compensateAlipayPayLogs() {
    // 1. 查询待补偿订单（分页，每次最多 100 条）
    List<AlipayPayLog> pendingLogs = alipayPayLogMapper.selectPendingPayLogs(5, 10, 100);
    
    for (AlipayPayLog payLog : pendingLogs) {
        try {
            // 2. 调用支付中心查询接口
            Map<String, Object> bizDataMap = new HashMap<>();
            bizDataMap.put("orderNo", payLog.getOrderNo());
            if (payLog.getTradeNo() != null) {
                bizDataMap.put("merchantOrderNo", payLog.getTradeNo());
            }
            
            PayCenterResponse payCenterResponse = payCenterClient.payQuery(bizDataMap);
            
            // 3. 处理响应
            if (payCenterResponse != null && Boolean.TRUE.equals(payCenterResponse.getSuccess())) {
                // 支付成功，更新本地状态
                String tradeNo = payCenterClient.getStringFromData(payCenterResponse, "channelOrderNo");
                updatePayLogSuccess(payLog.getPaySeq(), tradeNo, payCenterResponse);
            } else if (payCenterResponse != null) {
                // 支付中心返回明确失败，更新查询次数
                updatePayLogQueryCount(payLog.getPaySeq());
            }
        } catch (Exception e) {
            log.error("支付结果查询补偿异常, paySeq={}", payLog.getPaySeq(), e);
        }
    }
}
```

### 2.4 添加定时任务

**文件**：`alipay-pay-sign-server/src/main/java/com/chinasofti/huateng/alipay/paysign/task/AlipayPayCompensationTask.java`（新建）

**实现方式**：Spring `@Scheduled`

```java
@Component
public class AlipayPayCompensationTask {
    private final AlipayPaySignCompensationService compensationService;
    
    // 每 10 分钟执行一次
    @Scheduled(fixedRate = 10 * 60 * 1000)
    public void compensate() {
        compensationService.compensateAlipayPayLogs();
    }
}
```

**配置**：
```properties
# 补偿任务开关
alipay.compensation.enabled=true
# 补偿间隔（分钟）
alipay.compensation.interval=10
# 最大查询次数
alipay.compensation.max-query-count=5
# 查询间隔（分钟）- 两次查询之间的最小间隔
alipay.compensation.query-interval=10
```

### 2.5 修改 requestPay 流程

**文件**：`AlipayPaySignServiceImpl.requestPay()`

**变更**：
- 写入 `ALIPAY_PAY_LOG` 时，同时写入 `queryCount=0`、`lastQueryTime=null`
- 调用支付中心失败时，不立即标记为 `FAIL`，而是标记为 `PROCESSING`
- 增加 `PROCESSING` 状态表示"待补偿"

**新增状态常量**：
```java
private static final String PAY_STATUS_PROCESSING = "PROCESSING"; // 处理中/待补偿
private static final String PAY_STATUS_SUCCESS = "SUCCESS";
private static final String PAY_STATUS_FAIL = "FAIL";
```

### 2.6 数据库表变更

```sql
-- 增加查询次数和最后查询时间字段
ALTER TABLE ALIPAY_PAY_LOG ADD QUERY_COUNT NUMBER(10) DEFAULT 0;
ALTER TABLE ALIPAY_PAY_LOG ADD LAST_QUERY_TIME DATE;

-- 更新字段注释
COMMENT ON COLUMN ALIPAY_PAY_LOG.QUERY_COUNT IS '支付结果查询次数';
COMMENT ON COLUMN ALIPAY_PAY_LOG.LAST_QUERY_TIME IS '最后查询时间';
```

## 三、补偿流程时序

```
┌─────────────────────────────────────────────────────────────────────┐
│ 定时任务（每10分钟）                                                  │
│ AlipayPayCompensationTask.compensate()                              │
└─────────────────────────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 查询待补偿订单                                                       │
│ SELECT * FROM ALIPAY_PAY_LOG                                         │
│ WHERE DELETE_FLAG='0'                                               │
│   AND PAY_STATUS != 'SUCCESS'                                       │
│   AND QUERY_COUNT < 5                                               │
│   AND (LAST_QUERY_TIME IS NULL                                      │
│        OR LAST_QUERY_TIME <= SYSDATE - 10/1440)                     │
│ ORDER BY CREATE_TIME ASC                                            │
│ LIMIT 100                                                            │
└─────────────────────────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 遍历每条待补偿订单                                                    │
│ for (AlipayPayLog payLog : pendingLogs) {                           │
│     a. 调用支付中心 payQuery 接口                                     │
│     b. 更新 QUERY_COUNT = QUERY_COUNT + 1                           │
│     c. 更新 LAST_QUERY_TIME = NOW()                                 │
│                                                                     │
│     if (支付中心返回成功) {                                           │
│         更新 PAY_STATUS = 'SUCCESS'                                  │
│         更新 TRADE_NO / RESPONSE_BODY / RESULT_CODE / RESULT_MSG    │
│     }                                                               │
│ }                                                                   │
└─────────────────────────────────────────────────────────────────────┘
```

## 四、关键决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 定时任务实现方式 | Spring `@Scheduled` | alipay-pay-sign-server 无 Quartz 依赖，@Scheduled 更轻量 |
| 补偿频率 | 每 10 分钟 | 平衡实时性与系统负载 |
| 最大查询次数 | 5 次 | 避免无限重试，超过后需人工介入 |
| 查询间隔 | 10 分钟 | 避免对支付中心造成压力 |
| 失败状态处理 | 保持 FAIL，不自动变更为 SUCCESS | 只有支付中心明确返回成功才更新 |
| 幂等性 | 通过 orderNo + 乐观锁保证 | 防止并发更新 |

## 六、验证步骤

1. **编译验证**：`mvn clean compile -pl alipay-pay-sign-server -am -DskipTests`
2. **单元测试**：模拟支付中心返回失败，验证订单被标记为 `PROCESSING`
3. **定时任务验证**：启动服务，观察日志是否每 10 分钟执行补偿任务
4. **补偿逻辑验证**：
   - 插入一条 `PROCESSING` 状态的测试订单
   - 手动触发补偿任务
   - 验证调用支付中心查询接口
   - 验证订单状态被正确更新
5. **查询次数限制验证**：超过 5 次查询后，订单不再被补偿
6. **并发安全验证**：多实例部署时，同一订单不会被重复补偿

## 七、风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 定时任务多实例重复执行 | 同一订单被重复查询 | 使用分布式锁或数据库乐观锁 |
| 支付中心查询接口限流 | 大量订单同时查询导致限流 | 分页查询 + 间隔时间控制 |
| 查询次数耗尽后仍需处理 | 超过 5 次仍失败，订单状态不确定 | 提供管理接口人工触发查询 |
| 网络超时导致误判 | 查询超时但实际已成功 | 多次查询后再确定状态 |
