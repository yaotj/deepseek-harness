你是青岛地铁 ITP 互联网票务平台（qd-itp）的开发者。这是城市轨道交通 AFC 系统的互联网业务层，

## 二、几条最容易踩的硬约束

- **版本控制分两层，用错工具会以为「没改动」**：**Java 代码归 SVN**（`svn://130.251.101.176/qditp`），根 `svn:ignore` 排除 `docs` / `AGENTS.md` / `deploy` / `docker` / `scripts`；**提示词与文档层（`docs/` + `AGENTS.md`）归上一层 `qd/` 的 git 仓库**（同一目录里 `svn status` 与 `git status` 看到的是不同集合）。看代码 diff 用 `svn diff`，看文档 diff 用 `git diff`。本机 SVN 服务器不可达，提交需换有公司网络的环境。
- **Maven MUST 走 `mise exec -- mvn ...`**（裸 `mvn` 落 mise 全局默认 3.9.10、裸 `java` 落 25.0.1，均非项目 `qd/mise.toml` 指定的 Maven 3.8.7 / JDK 21）。
- **SQL / 持久层四条静默失效陷阱**（编译、单测、`xmllint` 全过，只在 Oracle 运行时炸）：SQL 正文 NEVER 写注释（Druid WallFilter 判注入）、NEVER `where 1=1` 打头、mapper XML 注释里 NEVER 两个连续减号、mapper 参数 MUST 显式 `jdbcType`。完整清单与修法读 `docs/architecture/mybatis-oracle-runtime-traps.md`。
- **`@Transactional` 方法内 NEVER 发起 RPC / 网络调用**，NEVER 提交异步通知任务。
- **NEVER 升级 `model` / `rpc` 的版本号**（被 20+ 个模块 pom 引用），只 `mvn install`。
- **镜像 tag 等于 pom `<version>`，每次部署 MUST 升版本号末位 +1**，NEVER 同 tag 覆盖（`rollout restart` 不会重新拉取，节点已缓存该 tag 的镜像层）。
- **判断线上真实地址 / 版本 MUST 查 K8s Deployment env 与 image tag**，NEVER 只看仓库 properties 或 pom；**判断某模块是否「在用」MUST 查集群 Deployment/Pod 实况**，NEVER 只凭仓库有代码就当线上在跑（collect-pay 已下线、collect-ticket 从未上线，均属此类）。
- **完成判据 MUST 可观察**：改了构建相关 ⇒ `mise exec -- mvn -o clean test-compile` 通过；改了提示词 / 文档 ⇒ `lint-prompts.py` ERROR 0。
- 🔴 **任何「grep 出来 0 条」的结论 MUST 换 `rg` 或 `grep -E` 复验后才敢采信**（历史事故：检索写法不当导致把「文档里有」误判成「文档里没有」）；另注意 `rg -r` 是 REPLACE、不是 recursive。
- **否定约束 MUST 配对正向替代**：写 `NEVER` / 「禁止」/ 「不得」时 MUST 同时给出可执行的替代做法（形如 `NEVER X → 改用 Y`）。

## 三、改完 MUST 回写（这一步不可省）

本仓库提示词是全项目唯一的架构事实源，**过期表述仍以 MUST/NEVER 的语气继续指挥后续改动，而编译与单测都发现不了**。改动涉及 **类名 / 方法名 / URL / 端口 / 状态取值 / 数据表 owner** 时 MUST 同步回写：业务域事实 → `docs/business/<业务域>.md`；跨域归属 / 边界变化 → `docs/domain/README.md`；部署 / 环境事实 → `docs/ops/` 对应文档；架构决策 → `docs/domain/decisions.md` 追加 ADR（先用 `grep -n '^#\{2,3\} ADR-D'` 查已用编号）。**同一事实散落三处一起改、标注日期 + ADR 号、改名保留旧名交叉引用、NEVER 新增行号引用**等细则读 `docs/提示词/工程与文档规范.md` §六「回写义务」。

**如果你无法自行写入这些文件**（比如工具没有写权限），MUST 在回复末尾列出「本次改动需要回写哪些文件的哪些条目」，交给用户或 workbuddy 落盘。**NEVER 只改代码不提示回写。**

## 四、提交前跑一次提示词自检

```
python3 docs/提示词/lint-prompts.py           # ERROR 必须清零才提交
```

它把提示词体系**三层**的腐烂规则变成机械检查（历史补丁句 / 旧 `sys_job` 编号被当现状引用 / `.md` 间断链 / 常驻预算 / 单行超长 / 新增源码行号引用；技能层 `qditp-*` 默认同查、不设存量基线，任何行号引用即 ERROR）。`--fix` / `--deep` / 基线机制等细节读 `docs/提示词/工程与文档规范.md` §一。**NEVER 用「我记得改过了」代替它。**

> **为什么这道自检不可省——上下文腐烂（context rot）**：提示词是指令而非代码，过期表述仍以 `MUST` / `NEVER` 语气继续指挥后续改动，而编译与单测都发现不了。改写提示词时 MUST 以「污染 / 分心 / 混淆 / 冲突」四类退化为校验清单。

  字面重复的条目只留一句 + 指针，细节信任真源文件。
