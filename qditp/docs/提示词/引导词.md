> **用法**：本项目的事实源在仓库里，但只有 workbuddy 会自动加载它。用 comate / trae 等工具时，
> **把下面 `--- 引导词正文开始 ---` 到 `--- 引导词正文结束 ---` 之间的内容整段复制到对话开头**，
> 即可让那个工具读到同一份事实、并承担同样的回写义务。

你是青岛地铁 ITP 互联网票务平台（qd-itp）的开发者。这是城市轨道交通 AFC 系统的互联网业务层，

## 二、几条最容易踩的硬约束

- **版本控制是 SVN 不是 git**（`svn://130.251.101.176/qditp`）。本机 SVN 服务器不可达，
  提交需换有公司网络的环境。`qditp/` 的上一层 `qd/` 里有个旁挂 git 仓库是陈旧快照，
  **NEVER 用任何 git 命令判断改动前长什么样**。
- **Maven MUST 走 `mise exec -- mvn ...`**（裸 `mvn` 会落到系统 Maven 3.9.9）。
- **NEVER 在 SQL 正文中写注释、NEVER 写 `where 1=1` 打头**：Druid WallFilter 会判注入，
  语句静默失效，编译与单测都发现不了，只在 Oracle 运行时炸。
- **mapper XML 注释里 NEVER 出现两个连续减号**（XML 规范禁止，会导致整个服务启动失败）。
- **mapper 写语句参数 MUST 显式写 `jdbcType`**，否则传 null 时报「无效的列类型: 1111」。
- **`@Transactional` 方法内 NEVER 发起 RPC / 网络调用**，NEVER 提交异步通知任务。
- **NEVER 升级 `model` / `rpc` 的版本号**（被 21 个模块 pom 引用），只 `mvn install`。
- **镜像 tag 等于 pom `<version>`，每次部署 MUST 升版本号末位 +1**，NEVER 同 tag 覆盖
  （`rollout restart` 不会重新拉取，节点已缓存该 tag 的镜像层）。
- **判断线上真实地址/版本 MUST 查 K8s Deployment env 与 image tag**，
  NEVER 只看仓库 properties 或 pom。
- **判断某模块是否「在用」MUST 查集群 Deployment/Pod 实况（是否部署、是否 0 副本）**，
  NEVER 只凭仓库有代码就当线上在跑（collect-pay 已下线、collect-ticket 从未上线，均属此类）。
- **完成判据 MUST 可观察**：改了构建相关 ⇒ `mise exec -- mvn -o clean test-compile` 通过；
  改了提示词 / 文档 ⇒ `lint-prompts.py` ERROR 0。
- 🔴 **本机 `grep` 是 toybox 不是 BSD/GNU：`\|` / `\s` / `\b` 会静默返回 0 结果**（不报错、exit 0、无提示）。
  多关键词 MUST 写 `grep -rEn "A|B"` 或用 `rg`；POSIX 类用 `[[:space:]]`。
  **任何「grep 出来 0 条」的结论，只要用了这三种写法，MUST 换 `-E` 或 `rg` 复验才敢采信。**

## 三、改完 MUST 回写（这一步不可省）

本仓库提示词是全项目唯一的架构事实源。**过期表述仍以 MUST/NEVER 的语气继续指挥
后续改动，而编译与单测都发现不了。**

改动涉及 **类名 / 方法名 / URL / 端口 / 状态取值 / 数据表 owner** 时 MUST 同步回写：

- 业务域事实 → `docs/business/<业务域>.md`
- 跨域归属 / 边界变化 → `docs/domain/README.md`
- 部署 / 环境事实 → `docs/ops/` 对应文档
- 架构决策 → `docs/domain/decisions.md` 追加 ADR（**先用 `grep -n '^#\{2,3\} ADR-D'` 查已用编号**）

四条要求：
1. **同一事实常散落三处**（`AGENTS.md` §2.2.1 + `docs/business/<域>.md` + `docs/architecture/*.md`），
   改 MUST 三处一起改，否则必然分叉。
2. 每条 **MUST 标注改动日期与 ADR 号**。
3. **改名 MUST 保留旧名做交叉引用**，否则后续按旧名检索会误判成文档自相矛盾。
4. **行号会漂，NEVER 依赖行号**，MUST 按类名 / 方法名定位；
   **写文档 / 改文档时 NEVER 新增 `Xxx.java:NNN` 形式引用**（存量债务 2026-10-13 已清零、基线为空 ⇒ 新引用直接 ERROR）。

**如果你无法自行写入这些文件**（比如工具没有写权限），MUST 在回复末尾列出
「本次改动需要回写哪些文件的哪些条目」，交给用户或 workbuddy 落盘。
**NEVER 只改代码不提示回写。**

## 四、提交前跑一次提示词自检

```
python3 docs/提示词/lint-prompts.py           # ERROR 必须清零才提交
python3 docs/提示词/lint-prompts.py --fix      # 自动删「本处此前写 X 已过期」类补丁句
```
它把提示词体系**三层**的腐烂规则变成机械检查：历史补丁句、旧 `sys_job` 编号被当现状引用、
`.md` 文档间断链、常驻提示词超预算、单行超长、**新增源码行号引用**
（docs 层存量按文件汇总成 WARN、基线外新增报 ERROR，2026-10-13 已全量清零；**技能层 `qditp-*` 默认同查、不设存量基线**，任何行号引用即 ERROR，`--no-skills` 可跳过；
`--deep` 把每条引用与源码树核对）。**NEVER 用「我记得改过了」代替它。**
