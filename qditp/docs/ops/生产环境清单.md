## 五、部署顺序

依赖方向：安全/公共能力 → 业务核心 → 接入层 → 后台。

```
1. acc-security-server            # 无依赖，其他密码运算的前提
2. para-server, blacklist-server, key-server, industry-data-server
3. account-server
4. ticket-server, pay-sign-server, gate-txn-pay-server
5. daily-ticket-server, collect-pay-server, collect-ticket-server
6. alipay-account-server, alipay-pay-sign-server
7. fep-app-server, fep-dev-server, fep-acc-server, fep-alipay-server
8. acc-es-server
9. web-server + web
```

⚠️ `scripts/batch-deploy.sh` 的 `ALL_SERVICES` 清单**不能直接用于生产**：
- 含仓库内不存在的 `wallet-server`、`online-server`
- 缺 daily-ticket-server、alipay-account-server、alipay-pay-sign-server、fep-acc-server、fep-alipay-server、web-server
- 首次全量部署前 **MUST** 按上表更新该脚本

### P1 — 依赖存在但 URL 键完全缺失

`service.*.url` 缺失时 `rpc` 会落到硬编码默认服务名，而这些名字与生产集群实际 Service 名不一致，**集群内 DNS 解析不到**，属静默失败（不会启动报错）：

| 调用方 | 缺失的键 | 落到的默认值 | 集群实际服务名 |
|---|---|---|---|
| `ticket-server` | `service.paySign.url` | `pay-sign-service` | `pay-sign-server` |
| `fep-app-server` | `service.collectPay.url` | `collect-pay-service` | `collect-pay` |
| `pay-sign-server` | `service.gateTxnPay.url` | `gate-txn-pay-service` | `gate-txn-pay-server` |

上线核对时 **MUST** 把「键缺失」与「键值错配」当成两类问题分别检查，**NEVER** 只 grep 已有的 `service.*.url` 行。
