# 青岛地铁 ITP 平台 · 第三方配合配置清单

> 范围：扫描全仓 `**/application.properties`、`**/application.yml` 及 `deploy/k8s/**` 中的 env 覆盖值，
> 提取所有「需要第三方配合」的配置项。所谓「第三方配合」指以下任一类：
> 1. **第三方提供凭证**：商户号 / AppId / 私钥 / 公钥 / 对称密钥 / 签名密钥（多为空值，待填）。
> 2. **第三方提供接入点**：其网关域名 / IP（多数已硬编码，需对方保障可达）。
> 3. **需第三方登记回调**：我方公网回调地址（`58.56.166.170:48000`）须由对方系统登记并放行入站。
> 4. **需对方开通防火墙**：我方出向访问其系统、或对方入向访问我方回调，均需网络侧配合。
> 5. **FTP 文件交换**：卡池 / 参数 / 对账 / ES 报表等文件落地，需对方提供 FTP 账号与目录。
>
> 数据基准：properties 默认值为代码中写死或 `${ENV:default}`；实际部署值以 `deploy/k8s/10-deployments/*.yaml`
> 与 `deploy/k8s/05-secret-template.yaml` 的 env 覆盖为准。⚠️ 多数为**测试环境**覆盖值。

   （`pay.center.private-key= MIIEvAIB...`）与 `jhm.key= fedf5g#@$(*&d390y3hcn`，与其它模块走 Secret 注入的口径不一致。

   若 Secret 实际为空，会回退到硬编码值——存在「以为已抽离、实则仍硬编码」的风险，建议统一只保留 Secret 注入。

3. **测试地址须上生产前替换**：多处 `dtcustomer.bestonepay.com/testngbackV2/...` 在代码/注释中明确标注
   「上生产前 MUST 换」（collect-pay 的 `notice-app-*`、pay-sign 的 `app.notify.*`、ticket 的 `app.notify.industry-data-url`、
   gate-txn-pay 的 `wallet.app-gateway-url`）。这些是**第三方环境切换点**，上线清单须逐项核对替换为生产域名。

4. **`itpb.svc` vs `itp.svc` 命名空间不一致**：`key-server`、`industry-data-server` 默认的 `service.security.url`

5. **占位符未填**：`collect-pay-server` 的 `pay.center.gateway-url=https://pay-gateway.example.com/api` 为占位符，
   上生产前 MUST 替换为真实支付中心网关。

   `172.20.211.23:30xxx` / `172.20.211.200:30xxx`。属内部服务发现，不计入第三方，但环境切换时须整体校验。

## 六、使用建议

- **对外沟通表**：把「二 / 四」两节直接作为与支付中心、支付宝、微信、ACC、地铁钱包、各 FTP 提供方的对接确认单，
  逐行确认「域名/IP 可达、账号密码、回调 URL 已登记、防火墙已开」。
- **上线核对表**：把「三 / 五」两节作为生产发布前的必填/必查项，尤其空白密钥与 `testngbackV2` 测试地址替换。
- **真值来源**：properties 是代码默认，`deploy/k8s/05-secret-template.yaml` + `10-deployments/*.yaml` 是当前实际生效值；
  生产环境以红岛生产 Deployment 的 env 为准（测试环境 `172.20.211.23` 覆盖值不可直接套用到生产）。
