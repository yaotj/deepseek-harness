# 用户分流网关操作手册（红岛生产）

> 面向运维 / 业务操作人员。说明红岛入口的「用户分流网关」是干什么的、怎么查、怎么切换、怎么回滚。
> 本手册只讲「怎么用」，不展开内部实现与排障细节。

## 一、这个网关是干什么的

红岛入口有一个**用户分流网关**（route-sentinel）。它的唯一职责：

> 对 TVM / BOM 设备域的订单类请求，**按「这个用户是不是新 ITP 用户」分到不同后端**。

- **新 ITP 用户** → 转发到 **face-pay（新 ITP）**，正常办理业务。
- **旧用户** → 转发到一个**占位地址**（无效地址），请求失败、不提供服务。

也就是说：**红岛当前只对「新 ITP 用户」开放设备域订单服务，旧用户的这类请求会被拒绝。**

## 二、怎么判断「新用户 / 旧用户」

看请求里的用户标识 `thirdUserId` 是否在名单表 **`USER_ITP_REG_INFO`** 里：

- **表里有记录 → 新 ITP 用户**；
- **表里没记录（或查询异常）→ 旧用户**（查询失败时按旧用户处理，保证旧用户不会被误放进新系统）。

名单变动后，网关有约 **5 分钟缓存**，最迟 5 分钟生效；重启网关立即生效。

## 三、分流规则（两张核心路由）

| 路由名 | 面向 | 转发到 | 结果 |
|---|---|---|---|
| `face-pay-split-route` | 新 ITP 用户 | face-pay（新 ITP） | 正常办理 |
| `legacy-route` | 旧用户 | **占位地址**（无效） | 请求失败、被拒绝 |

另有两条与分流无关、保持默认即可：

| 路由名 | 面向 | 转发到 |
|---|---|---|
| `fep-app-route` | `/fep-app/**`（APP 域） | fep-app |
| `face-pay-default-route` | 其余 `/itptvm/**`、`/itpbom/**` | face-pay |

> 实际生效值以网关实时查询为准（见「四、查看当前路由」），上表是目标策略。

## 四、受分流影响的接口（7 条）

只有下面 7 条设备域接口走分流网关，其余端点不经过它：

```text
/itpbom/ci/bom/notiTakeTicketResult
/itpbom/ci/bom/notiTakeTicketFailResult
/itpbom/ci/bom/requestTakeTicketAuth
/itpbom/ci/bom/requestCardDataAnalyse
/itpbom/ci/bom/requestUpdateCardData
/itptvm/ci/tvm/requestTakeTicketAuth
/itptvm/ci/tvm/requestCardDataAnalyse
```

## 五、日常操作

> 所有操作都在红岛跳板机 `hd-linux` 上执行；改动**立即生效**（落库 + 网关热重载），不需要重启任何服务。

### 1. 查看当前路由

```bash
ssh hd-linux 'POD=$(kubectl get pods -n itpb -l app=route-sentinel -o jsonpath="{.items[0].metadata.name}");
kubectl exec -n itpb "$POD" -c route-sentinel -- curl -s localhost:8080/actuator/gatewayroutes'
```

返回里看每个路由的 `uri`：
- `face-pay-split-route` 应为 `http://face-pay-server-internal-svc.itpb.svc:8080`；
- `legacy-route` 应为占位地址（如 `http://legacy-disabled.invalid:8080`）。

### 2. 把「旧用户」切到占位地址（拒绝服务）

```bash
ssh hd-linux 'POD=$(kubectl get pods -n itpb -l app=route-sentinel -o jsonpath="{.items[0].metadata.name}");
kubectl exec -n itpb "$POD" -c route-sentinel -- curl -s -X POST localhost:8080/actuator/gatewayroutes/legacy-route \
  -H "Content-Type: application/json" \
  -d "{\"uri\":\"http://legacy-disabled.invalid:8080\",\"predicates\":<原样保留第1步查到的数组>,\"operator\":\"<操作人>\",\"remark\":\"旧用户切占位地址\"}"'
```

> `predicates` 数组必须**原样带上**（从第 1 步查询结果里整段复制），不能漏，否则分流路径会丢。

### 3. 把「旧用户」切回 face-pay（恢复服务）

把上面命令里的 `uri` 改成 `http://face-pay-server-internal-svc.itpb.svc:8080`，其余不变。

### 4. 切换「新用户」落点（D11 上线后）

D11 新系统就绪后，把 `face-pay-split-route` 的 `uri` 改成 D11 的真实地址（同样 `predicates` 原样带上）。

### 5. 验证

改完用第 1 步重新查，确认 `uri` 已变成目标值；再用一条设备域请求实测，确认返回符合预期（新用户正常、旧用户被拒）。

### 6. 回滚

把 `uri` 改回上一个值即可（第 2/3/4 步的逆操作）。每次改动都会写入审计表 `GATEWAY_ROUTE_CONFIG_AUDIT`，可追溯谁在什么时间改了什么。

## 六、注意事项（红线）

1. **这是生产配置，改前必须确认**。尤其「旧用户切占位地址」会让所有旧用户的设备域订单请求失败，确认这是预期（红岛只服务新 ITP 用户）再改。
2. **`predicates` 必须原样带上**，漏了会丢分流路径。
3. **占位地址用一个明显不存在的域名**（如 `legacy-disabled.invalid`），不要填真实存在的地址，否则旧用户会被错误地路由到真实系统。
4. **名单以 `USER_ITP_REG_INFO` 表为准**：新增 / 移除新用户在该表操作，网关约 5 分钟内自动生效。
5. 网关自身故障时的应急：把入口 `fep-app-vr` 那 7 条精确路由临时改回直连 face-pay，让流量绕过网关（属应急预案，本手册不展开）。
