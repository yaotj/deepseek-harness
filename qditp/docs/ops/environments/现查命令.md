# 测试环境现查命令

> **定位**：进测试环境操作前必跑的 3 条核查命令。任何涉及 `fep-app-vr` VirtualService / route-sentinel / 相关业务 Service 的操作前，**MUST 先跑这 3 条**核对实时状态。
> **配套文档**：
> - [test-istio-ingress.yaml](test-istio-ingress.yaml) — VS fep-app-vr 完整 YAML（含部署 patch 命令）
> - [测试环境.md](测试环境.md) — 环境概览 + 路由索引

## ① VS fep-app-vr 全量

核对 15 条路由的前缀 / rewrite / 目标 / 端口。操作前跑，操作后跑一次对比。

```bash
ssh k8s-master "kubectl get vs fep-app-vr -n itp -o yaml --show-managed-fields=false"
```

## ② Service 实时名+端口

核对 Service 名随机后缀（`hr32k`/`748lq`/`wracu`/`rec8g`/`pfufrl`/`route-sentinel-*`）与 targetPort。**部署 patch 前必跑**，patch 里的 host 必须是实时名。

```bash
ssh k8s-master "kubectl get svc -n itp | grep -E 'fep-app|fep-dev|fep-acc|fep-alipay|face-pay|route-sentinel|para-server'"
```

## ③ SCG 内部路由（route-sentinel actuator）

核对 DB `GATEWAY_ROUTE_CONFIG` 里 `legacy-route` / `face-pay-split-route` 的当前 URI。**2026-10-22 未现查，待补**。

```bash
ssh k8s-master "kubectl exec -n itp $(kubectl get pods -n itp -l app=route-sentinel -o name | head -1) -- curl -s http://127.0.0.1:8080/actuator/gatewayroutes"
```

## 使用纪律

1. **任何涉及 fep-app-vr / route-sentinel 的操作前 MUST 按 ①→②→③ 顺序跑**
2. **Service 名随机后缀每次发版可能漂移**，patch 命令里的 host MUST 用 ② 的实查值替换
3. **操作后 MUST 再跑 ① 核验**，并回填 `docs/ops/environments/test-istio-ingress.yaml` 的 `last-sync` 日期
4. **NEVER 凭记忆或上一轮现查值直接操作**——K8s 资源随时可能被其他人的 patch 改走
