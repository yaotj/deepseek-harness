# 测试环境（test）

> 状态：在用。当前对接新华三（H3C）底座，ns `itp`，k8s-master 跳板。

## 集群底座

- 集群名 `k8s02`（PaaS 控制台管理），Kubernetes **v1.28.6**、containerd **1.7.11**、OS H3Linux 1.1.0。
- 节点 7 个：3 control-plane（`.21` / `.22` / `.23`）+ 3 worker（`.24` / `.25` / `.26`）+ 1 网关节点 `.200`（`k8s02-gateway-866a2`）。
- istio **1.24.6**（`istio-system`：istiod / jaeger / kiali / grafana），ns `itp` 带 `istio-injection=enabled` ⇒ 每个业务 Pod `2/2`（业务 + envoy sidecar）。
- 业务 Pod 会调度到 control-plane / gateway 节点（实测 `daily-ticket` / `fep-dev` / `security-server` / `victoria-logs` 都落在 `.200`）。
- 完整底座盘点（节点 / 工作负载 / 网络 / 密钥 / 存储 / 外部依赖）**逐项现查**，权威快照见 `docs/ops/K8S迁移清单.md` §1.1~§1.6（2026-09-22 实测，数字会漂移 MUST 重新查）。

## 工作负载

- 24 个业务 Deployment + `victoria-logs`（唯一 StatefulSet，带 PVC）+ `database`（BYOK database MCP，非 Oracle）。完整清单见 `docs/ops/K8S迁移清单.md` §1.2。
- 单副本强约束：`recon-server` / `web-admin` / `face-pay-server` / `collect-pay` 的定时任务无分布式锁，**MUST 单副本**（双跑会重复扣费/投文件，详见 `docs/ops/environments/跨环境共性.md`）。
- 多副本例外：`fep-dev-server` 2026-10-21 起 `replicas: 3`（配 hostname 反亲和），核查依据——源码无 `@Scheduled` / 无进程内缓存与静态态、四个 IF1A 接口均为无状态转发或纯回包，且不在上面单副本清单内。
