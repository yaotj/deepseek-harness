## 三、综合管理台入口（走 istio hostPort，非 Kong 48000）

综管台**不走** Kong `48000` 入口（那里 `/` 和 `/web-server/` 都是 404）。它走 istio ingressgateway 的 **hostPort 8081**。

**地址（二选一，节点 IP 随 Pod 漂移，当前为这两个）：**
- `http://172.120.2.28:8081/`（前端 UI，实测 200 ✅）
- `http://172.120.2.29:8081/`（前端 UI，实测 200 ✅）
- 后端反代 `http://172.120.2.28:8081/web-server/` 当前实测 **503**（疑似 web-admin 链路未完全打通，待查；前端 UI 本身可加载）

> 8081 由 `manage-gw`（port 8081）承载，`/`→前端 `web-frontend-twcm6-svc:31919`，`/web-server/`→后台 `web-admin-gfbh6-svc:31943`。
> ⚠️ hostPort 只绑在跑 ingressgateway Pod 的节点上（当前 `172.120.2.28` / `172.120.2.29`）；Pod 换节点后旧 IP 立即失效，属临时/排障通道，不宜作为对外长期固定入口。

## 四、当前已知问题（2026-10-26 路由已修复，剩余 503 为后端应用层）

**路由层（`fep-app-vr` destination）已于 2026-10-26 全部修正为红岛 `itpb` 真实服务名**（原 7 条 prefix 指向测试环境服务名 ⇒ 持续 503）。修正后实测：
- ✅ `/fep-app/`、`/fep-acc/`、`/fep-alipay/` → **403**（链路打通，后端鉴权拒绝=正常）
- ❌ `/fep-dev/`、`/itpagm/`（fep-dev-server）、`/itptvm/`、`/itpbom/`（face-pay-server）、`/para-server/`（para-server）→ **仍 503**

**剩余 503 已定位为后端应用自身返回（非路由）**：直连这些 Pod IP`:8080` 探活同样返回 503，而 envoy 端点均 `healthy`，故根因在应用层（可能刚重启未就绪 / 依赖未配置好 / 根路径无 handler），**需另立项排查应用，不在路由修复范围**。

**7 条 exact 仍指 `route-sentinel-svc`（红岛未部署 ⇒ 必 503）**：因 `route-sentinel` 在红岛 `itpb` 不存在（`kubectl get svc` 确认 NotFound），且架构拍板"7 条 exact 恒指 route-sentinel，NEVER 指 face-pay"，本次未改动。两条路（需业主决策）：
- **A. 部署 `route-sentinel` 到红岛**（保持架构，TVM/BOM 的 CI 精确路径走 SCG 分流）；
- **B. 临时删掉 7 条 exact**，让 `/itptvm/`、`/itpbom/` 前缀兜底（文档允许的 SCG 回滚方式，快速让 TVM/BOM 通）。

## 六、现查命令（自行复核用，跳板 `hd-linux`）

```bash
# 路由定义（确认 destination 服务名是否已换成红岛值）
kubectl get vs fep-app-vr -n itpb -o yaml --show-managed-fields=false
kubectl get vs manage-vr   -n itpb -o yaml --show-managed-fields=false

# 真实 Service 名 + 端口
kubectl get svc -n itpb | grep -E 'fep-app|fep-dev|fep-acc|fep-alipay|face-pay|route-sentinel|para-server|web-admin|web-frontend'

# 入口各前缀实时返回码（从 Kong 48000）
for p in /fep-app/ /fep-dev/ /fep-acc/ /fep-alipay/ /itptvm/ /itpbom/ /itpagm/ /para-server/; do
  code=$(curl -s -o /dev/null -m 8 -w '%{http_code}' http://172.120.2.26:48000$p)
  echo "$p -> $code"
done

# 综管台（istio hostPort 8081，节点 IP 随 Pod 漂移，先取实际节点）
kubectl get pod -n istio-ingress -o wide        # 看 NODE
curl -s -o /dev/null -m 8 -w '%{http_code}' http://<节点IP>:8081/
```

## 七、温馨提示

- **这是红岛生产环境，与测试环境（`58.56.166.170:48000`）完全两套地址，切勿混用。**
- Kong `48000` 是业务对端统一入口；综管台走独立的 istio `8081` 通道，两套并存。
- `8081` 节点 IP 随 ingressgateway Pod 漂移（当前 `172.120.2.28` / `172.120.2.29`），长期对外请优先用 Kong `48000` 入口。
- 对外回调地址（支付中心 / 支付宝 / APP / 设备侧）MUST 同步改为 `172.120.2.26:48000` 前缀，NEVER 沿用测试 `58.56.166.170`。
