## 本机 USB 网卡（AX88179B，`en9`）插口决定可达区（2026-10-19 实测）

| 插口网段 | 能通 | 不通 |
|---|---|---|
| `172.120.249.x`（出口区） | 仅本网段网关 | K8s 控制区 `.2` / 业务区 `.110` 全不通（防火墙隔离、无跨区三层路由） |
| `172.120.2.x`（K8s 控制区） | `hd-linux` 22 / 31920 | — |
| `172.120.110.x`（业务区） | 前端 31919 / VL 31920 | — |

**可达性自检**（插好口后先跑三项、全 OK 再拉集群实况）：

```
ifconfig en9 | grep inet
nc -z -G 5 172.120.2.13 22
nc -z -G 5 <业务节点 172.120.110.x> 31919
```

**办公网（en0，`192.168.3.1`）→ 生产网**（2026-10-19 临时排查）：ICMP 通、TCP 全拦（22/80/443/31919/31920 都 `nc` 超时、`curl` 5s 超时）——红岛入口防火墙只放 ICMP 管理探测、不放 TCP 业务出站。恢复全可达三条路：① 换插到 K8s 控制区口、② 找网络侧在办公网→生产网防火墙上放 TCP、③ 走红岛运维堡垒机跳板。

## 生产库 HDTPDB（Oracle RAC 19c）

| 项 | 值 | 备注 |
|---|---|---|
| 集群形态 | Oracle RAC 19c 双节点（裸金属 浪潮 TS860M7，`oracleitp01` / `oracleitp02`） | 版本 19.30.0.0.260120 + RU 38629535 |
| 集群 VIP | `172.120.110.25` | 节点业务口 `.21` / `.22`，私网互联 `.125.21` / `.22` |
| 端口 | `1521` | |
| **服务名** | **`hditpdb`** | 部署方案明确「需使用服务名连接」，**NEVER 用 SID** |
| CDB / SID | CDB `itpcdb`，实例 SID `itpcdb1` / `itpcdb2` | |
| JDBC URL | `jdbc:oracle:thin:@//172.120.110.25:1521/hditpdb` | `//` = 服务名方式 |
| 用户 / Schema | 4 个分域应用账号（方案 A 逻辑分库） | `QDITP_USER` / `QDITP_TXN` / `QDITP_RIDE` / `QDITP_PLAT`，各有独立表空间（`ITP_USER_TS` / `ITP_TXN_TS` / `ITP_RIDE_TS` / `ITP_PLAT_TS`）与独立临时表空间 |
| 口令 | 各账号口令**不同、MUST 现查**（`QDITP_USER`=`itp!#usr4726` / `QDITP_TXN`=`itp!#txn8153` / `QDITP_RIDE`=`itp!#rd2947` / `QDITP_PLAT`=`itp!#plt6308`） | **NEVER 外传 / 截图 MUST 打码**；已授权 `CREATE SESSION/TABLE/VIEW/SYNONYM/SEQUENCE/PROCEDURE/TRIGGER/MATERIALIZED VIEW` + `UNLIMITED TABLESPACE` |
| 字符集 | **`ZHS16GBK`** | 长字段按 `MAX_STRING_SIZE=EXTENDED`（32k）口径 |

**PDB 连接要点**：
- MUST 用 Service name `hditpdb` 连接；**NEVER 用 SID**（`itpcdb1`/`itpcdb2` 或 CDB 服务名）—— 能连上但看不到业务表
- JDBC URL 两种写法：`@//host:port/service`（正确）vs `@host:port/service`（无 `//`，按 SID 解析，ORA-12514 高发）
- RAC VIP 已由集群维护故障切换，**NEVER 直连单节点 IP**

RAC 三库（`hdmlcdb` / `hdaccdb` / `hditpdb`）均为 CDB+PDB 架构，业务对象在 PDB 里。
