# 各模块事实清单（qd-itp，2026-10-15 采集）

> 采集方式：本地 SVN 工作副本（r1286）+ k8s-master `kubectl -n itp` 实况。
> **以集群 `kubectl` 为准**，本清单为某一时刻快照；版本/端口/任务编号 MUST 现查（`docs/提示词/工程与文档规范.md` §五）。
> 集群内 Deployment 名 ≠ 模块目录名 ≠ Service 名，三处名称经常不一致，下表逐项对齐。

## 0. 采集口径说明

- **模块目录**：仓库根下的源码目录（如 `face-pay-server/`）。
- **Deployment 名**：K8s 集群 `-n itp` 下的 Deployment（`kubectl get deployment`）。
- **镜像前缀**：Harbor `os-harbor-svc.default.svc.cloudos:443/itp/<镜像名>`；镜像名取自模块 pom `<image.prefix>`，**不等于模块目录名**（如 `fep-app-server` 镜像是 `fep-app`、`alipay-pay-sign-server` 镜像是 `alipay-pay-sign`）。
- **Service 名**：`<Deployment 名>-<随机后缀>-svc`（jkube 生成，随机后缀可变）。
- **NodePort**：K8s Service 对外端口（调用方用 `172.20.211.23:<NodePort>`）；**targetPort = 容器内应用真实监听端口**（= 代码 `server.port` / `SERVER_PORT`）。
- **application.name**：`spring.application.name`（VictoriaLogs 检索 `app` 字段用它，不一定等于 Deployment 名）。

## 3. 名称/端口易错点（NEVER 混淆）

1. **模块目录名 ≠ Deployment 名 ≠ 镜像名前缀**：
   - `fep-app-server`（目录）→ `fep-app`（Deployment）→ `itp/fep-app`（镜像）。
   - `alipay-pay-sign-server`（目录）→ `alipay-pay-sign-server`（Deployment）→ `itp/alipay-pay-sign`（镜像，少 `-server`）。
   - `account-server`（目录）→ `account`（Deployment）→ `itp/account-server`（镜像，Deployment 反而更短）。
   - 用 `deploy-to-harbor.sh <模块目录名>` 时，脚本内部按 `JAR_MAP` 映射出镜像名；**镜像名错会 `ImagePullBackOff`**（2026-10-15 alipay-pay-sign 1.1.60 实测）。
2. **Service port ≠ server.port ≠ NodePort**：Service `port`（集群内调用方用）= 常常直接是 NodePort 号；`targetPort` = 容器应用真实监听端口。改端口只改 `targetPort`，NEVER 改 `port`/调用方。
3. **容器端口与代码默认值可能不一致**（被 Deployment env 覆盖）：`trans-query-server` 代码默认经 `SERVER_PORT` env = 9113；`key-server` **实测监听 9103**（env `server.port=8080` 是 2026-09 503 修复前的历史残留，实际无效，Service targetPort 已对齐 9103）。
4. **同名 8080 的多个模块**：`alipay-account` / `alipay-pay-sign` / `fep-alipay` / `collect-pay` / `acc-es` / `security-server` / `web-admin` 应用都监听 8080，但**各自独立 Pod 无冲突**；压测/调试 MUST 走 `172.20.211.23:<NodePort>` 区分。
5. **`spring.application.name`（VictoriaLogs `app` 字段）≠ Deployment 名**：`key-server`→`key`、`blacklist-server`→`blacklist`、`pay-sign-server`→`pay-sign`、`fep-dev`→`fep-dev`、`fep-app`→`fep-app`、`fep-alipay`→`fep-alipay`。VictoriaLogs 检索 MUST 用 app 名，不能用 Deployment 名。
6. **VictoriaLogs**：`victoria-logs-pbi6a-svc.itp.svc:30032`（targetPort 9428）。

## 5. 副本与运行态（采集时刻）

- 全部业务 Deployment `replicas=1`、`ready=1/1`（单副本，无横向扩展）。
- **分布式锁约束**：单副本 ⇒ `@Scheduled` 定时任务天然不重入；MUST 保持单副本，NEVER 横向扩容到 >1（否则无锁任务重复执行，见 AGENTS.md §业务约束「无 Redis/MQ，幂等靠唯一索引」）。
- 非业务 Deployment（`details-v1`/`productpage-v1`/`ratings-v1`/`reviews-v1/2/3`/`kennethreitz-httpbin`）是测试/样例负载，与 ITP 业务无关，可忽略。

## 7. 维护

- 本清单是**某时刻快照**；线上版本/端口会随每次部署变动。
- 判断「线上到底跑哪版」MUST `kubectl -n itp get deployment <d> -o jsonpath='{.spec.template.spec.containers[0].image}'`，NEVER 信 `deploy/k8s/` 里的 yaml（manifest 只作模板，常与集群脱节）。
- 新增/改动模块后，MUST 回填本清单对应行 + 核对 Service 随机后缀是否变化。
