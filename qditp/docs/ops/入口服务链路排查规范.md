# 入口服务链路排查规范

**适用范围：** qd-itp 项目内所有服务（本规范重点聚焦入口服务 `fep-*` 和 `face-pay-server`）  
**不在范围：** `itp-gateway`（前置网关入口）  
**排查工具：** VictoriaLogs（`http://victoria-logs-pbi6a-svc.itp.svc:30032`）  
**核心字段：** `traceId`

---

## 一、入口服务清单

| 服务 | VictoriaLogs `app` 字段 | NodePort | 主要职责 |
|------|------------------------|----------|----------|
| `fep-app-server` | `fep-app` | 30010 | APP 端主入口（查询、下单、支付） |
| `fep-dev-server` | `fep-dev` | 30009 | 设备端/闸机入口 |
| `fep-alipay-server` | `fep-alipay` | 30020 | 支付宝渠道入口 |
| `fep-acc-server` | `fep-acc-server` | 30030 | 账户类入口 |
| `face-pay-server` | `itpagm` | 30025 | APP 取票/人脸支付入口 |

> ⚠️ `face-pay-server` 在 VictoriaLogs 中的 `app` 字段为 `itpagm`，这是由模块内 `appName` 系统属性决定的，查询时请勿使用 `app:face-pay-server`。

## 二、排查前提：拿到 traceId

### 2.1 最理想：前端/客户端直接给出 traceId

如果接口响应头里带出了 `traceId`，或者客户端日志/截图里有 `traceparent`，直接跳到第三章。

### 2.2 次理想：只有用户号 + 报错时间

```bash
# 假设 thirdUserId=00522980，在 16:10 左右报错
# 先在入口服务里定位请求
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d 'query=_time:10m AND (app:fep-app OR app:fep-dev OR app:fep-alipay OR app:fep-acc-server OR app:itpagm) AND 00522980' | \
  head -20
```

从 `FirstFilter` 日志中提取 `traceId`：

```json
{
  "_msg": "receive request url=/ci/app/requestOrder ... traceparent=00-4592bdd7adc8e316605785c949252aae-...",
  "traceId": "4592bdd7adc8e316605785c949252aae"
}
```

### 2.3 最次：只有大概时间

```bash
# 按入口服务 + 时间 + URL 模糊搜索
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d 'query=_time:10m AND app:fep-app AND requestOrder' | \
  head -20
```

## 四、为什么有些日志没有 traceId？

 VictoriaLogs 中部分日志的 `traceId` 为空，这**不一定是 bug**，需要区分场景：

### 4.1 正常情况（无需处理）

| 场景 | 原因 | 示例 logger |
|------|------|-------------|
| **应用启动阶段** | traceId 依赖 HTTP 请求上下文，启动时尚未收到请求 | `CustomLoggingConfiguration`、`DruidDataSource`、`DefaultMvcConfigurer` |
| **定时任务/后台线程** | Quartz 任务、Druid 连接池销毁线程等没有 HTTP 入口 | `CustomMeterRegistry`、`TaskController`、`Druid-ConnectionPool-Destroy` |
| **异步 Reactor 错误回调** | WebClient 的 reactor 线程可能丢失 MDC 上下文 | `InternalMicroHttp` 的 `webClient request failed`（来自 `reactor-http-epoll-*`） |

> 这些日志没有 traceId 是正常的，因为它们本身就不属于某一次 HTTP 请求。

### 4.2 异常情况（需要处理）

如果某个服务的 **HTTP 请求日志**（`FirstFilter.receive request`）也没有 traceId，或者大量日志都没有 traceId，需要检查该 Deployment 的 tracing 三行成组是否完整：

```bash
kubectl -n itp get deploy <服务名> -o jsonpath='{range .spec.template.spec.containers[0].env[*]}{.name}{"\n"}{end}' | grep -E 'management|spring.autoconfigure|VLOGS_URL'
```

必须同时存在：
- `management.tracing.enabled=true`
- `management.tracing.sampling.probability=0`
- `spring.autoconfigure.exclude=org.springframework.boot.actuate.autoconfigure.tracing.otlp.OtlpAutoConfiguration`
- `VLOGS_URL=http://victoria-logs-pbi6a-svc.itp.svc:30032`

2026-10-14 排查时发现 `account`、`ticket-server`、`para-server`、`alipay-pay-sign-server`、`blacklist-server`、`alipay-account-server`、`face-pay-server` 的 live Deployment 曾缺失部分 env，已通过 `kubectl set env` 补全。

## 五、问题定界原则

| 现象 | 结论 | 处理方 |
|------|------|--------|
| 日志只到入口服务 `FirstFilter`，没有出向 `InternalMicroHttp` | 问题在入口服务内部（参数校验、业务异常） | 本团队 |
| 入口服务已发出请求，下游返回 500/超时/异常 | 问题在下游服务 | 本团队继续排查（qd-itp 项目内所有服务均在管理范围） |
| 入口和下游都有同一 traceId，但下游返回业务错误码 | 需看具体错误码；可能是入参/数据问题 | 本团队内部协同入口侧与下游服务 |
| `face-pay-server` 直接对外接口报错 | 问题在人脸支付模块 | 本团队 |
| 同一请求在多个服务日志时间差过大 | 网络/调用耗时问题 | 视情况协调基础设施或下游 |

## 六、典型排查案例

### 案例 1：用户报“APP 下单失败”

```bash
# 1. 在 fep-app 找 requestOrder 相关日志，取最近 ERROR 或业务失败
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d 'query=_time:30m AND app:fep-app AND requestOrder AND (ERROR OR 8001 OR 失败)' | \
  head -10

# 2. 拿到 traceId 后全链路追踪
tid=<traceId>
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d "query=_time:10m AND traceId:$tid"

# 3. 判断问题在哪一侧
# - 如果 fep-app 日志里有出向调用 face-pay-server，且 face-pay-server 返回了错误 → 转 face-pay 侧
# - 如果 fep-app 自己校验失败（如签名、userId 缺失）→ 本团队修
```

### 案例 2：用户报“查询账单失败”

```bash
# 入口是 fep-app，下游是 trans-query-server（非本团队管理）
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d 'query=_time:30m AND app:fep-app AND requestTransStatistics AND (ERROR OR 失败)' | \
  head -10

# 拿到 traceId 后，确认 fep-app 是否成功发出请求、trans-query 是否返回异常
tid=<traceId>
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d "query=_time:10m AND traceId:$tid"
```

## 七、建议：响应头返回 traceId

为了提升排查效率，建议所有入口服务在响应头中返回 `traceId`。这样用户/前端报 bug 时可以直接提供，无需再通过时间反查。

### 6.1 实现方案

在 `resource/micro/web/src/main/java/com/chinasofti/huateng/micro/web/filter/FirstFilter.java` 的 `doFilter` 中，增加响应头：

```java
import jakarta.servlet.http.HttpServletResponse;

@Override
public void doFilter(ServletRequest servletRequest, ServletResponse servletResponse, FilterChain filterChain)
        throws IOException, ServletException {
    try {
        // ... 原有逻辑 ...
        filterChain.doFilter(servletRequest, servletResponse);
    } finally {
        if (servletResponse instanceof HttpServletResponse) {
            String traceId = MDC.get("traceId");
            if (traceId != null && !traceId.isEmpty()) {
                ((HttpServletResponse) servletResponse).setHeader("x-trace-id", traceId);
            }
        }
    }
}
```

> 注意：`FirstFilter` 在 `resource/micro/web` 共享模块中，修改后会影响所有依赖 `web` 的服务（包括本团队管理的 5 个入口服务，以及下游服务）。这是安全且通用的增强。

### 6.2 验证响应头

```bash
curl -I http://172.20.211.23:30010/actuator/health
# 期望看到：x-trace-id: <traceId>
```

## 八、常用 VictoriaLogs 查询

```bash
# 1. 某入口服务最近 10 分钟日志
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d 'query=_time:10m AND app:fep-app'

# 2. 按 traceId 查全链路
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d 'query=_time:10m AND traceId:<traceId>'

# 3. 只看 ERROR
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d 'query=_time:30m AND level:ERROR AND (app:fep-app OR app:fep-dev OR app:fep-alipay OR app:fep-acc-server OR app:itpagm)'

# 4. 只看自己管理服务的 DEBUG（排查 MyBatis/SQL）
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d 'query=_time:30m AND level:DEBUG AND (app:fep-app OR app:fep-dev OR app:fep-alipay OR app:fep-acc-server OR app:itpagm)'

# 5. 某个用户最近请求
curl -s http://10.100.183.227:30032/select/logsql/query \
  -d 'query=_time:30m AND app:fep-app AND <thirdUserId>'
```

## 九、职责边界

- **本团队管理范围**：qd-itp 项目内所有服务，包括入口服务（`fep-*`、`face-pay-server`）及下游服务（account、ticket-server、trans-query、blacklist-server、para-server、alipay-pay-sign、gate-txn-pay、web-admin 等）。
- **不在本团队管理范围**：`itp-gateway`（前置网关）。网关侧问题（如路由丢失、traceId 未透传）需协调网关 owner。
- **本团队职责**：保证项目内所有服务生成 `traceId`、写入 MDC、通过 WebClient 透传、日志进入 VictoriaLogs；定位到问题服务后内部闭环处理。
- **协作方式**：若问题确认在 `itp-gateway`，向其提供请求时间、URL、入口侧日志及 `traceparent` 样本。
