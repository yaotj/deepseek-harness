# 对账文件上传：命名与替换说明（运营版）

> 适用页面：综管台 → 交易管理 → **对账文件上传**（`/trans-operation/recon-upload-file`）
> 生效环境：测试环境已生效；红岛/辽阳东随对应发版生效。
> 技术口径与实现约束见 [`../business/recon.md`](../business/recon.md) §「综管台「对账文件上传」的命名与替换约束」。

## 一、文件名必须按下面两种格式之一来起

不符合格式的文件**上传会被直接拒绝**，不会落库、也不会落盘。

### 1. 我方（ITP）生成的对账文件

```
ITP.<类别>.<账期>
```

| 类别 | 这份文件是什么 | 示例 |
|---|---|---|
| `EXP` | 单边交易明细 | `ITP.EXP.20261105` |
| `PAY` | 统计汇总 | `ITP.PAY.20261105` |
| `BUS` | 商业优惠汇总 | `ITP.BUS.20261105` |
| `DETAIL` | 多日计次票明细 | `ITP.DETAIL.20261105` |
| `TXNDIFF` | 对账差异明细 | `ITP.TXNDIFF.20261105` |

- 账期是 **8 位真实日期**（年月日），例：`20261105`。`2026110`（少一位）、`20261399`（13 月）都会被拒。
- 类别只能是上面五个之一，大小写敏感（`itp.pay.20261105` 会被拒）。
- **可以不带后缀**（推荐，与投递给 ACC 的文件名完全一致）；也可以带 `.csv` / `.txt` / `.xls` / `.xlsx`。
  带其他后缀（如 `.zip`）会被拒。

### 2. 渠道方给我们的日账单

```
reconciliation-bill-<账期>[.后缀]
```

示例：`reconciliation-bill-20261105.csv`

- 中间那段必须是账期日期，**不能写成 `date`**（`reconciliation-bill-date.csv` 会被拒）。

### 常见被拒的名字

| 你传的名字 | 为什么被拒 | 改成 |
|---|---|---|
| `对账.xls` | 不属于任何一套格式 | `ITP.PAY.20261105.xls` |
| `ITP.PAY.202611.csv` | 账期只有 6 位 | `ITP.PAY.20261105.csv` |
| `ITP.PAY.20261105.zip` | 后缀不在允许清单 | 解压后传里面的 `.csv` |
| `ITP.PAY.20261105.csv.gz` | 双后缀 | 只保留一层后缀 |
| `reconciliation-bill-date.csv` | 中间段不是日期 | `reconciliation-bill-20261105.csv` |

## 二、页面上选的「对账日期」必须和文件名里的账期一致

选文件后弹窗会自动带出文件名里的账期。**如果你手动改了这个日期，让它和文件名不一致，上传会被拒**，
提示形如「对账日期 20261106 与文件名账期 20261105 不一致」。

这一条是为了防止「文件是 5 号的账，记录挂在 6 号」——那种数据事后对不上账，也没法回溯。

## 三、同一个账期、同一类文件，系统里只保留一份；再传就是替换

- 再次上传同名同账期的文件 = **替换**，列表里这一类这一天的记录只有一条（不会越传越多）。
- 提示语会写明「**已替换同账期同类对账文件**」，看到这句就说明替换成功。
- **旧文件不会被删掉**：它会在服务器上改名成

  ```
  ITP.PAY.20261105.csv.replaced-20261106143012
  ```

  即「原文件名 + `.replaced-<替换时刻>`」，留在同一个目录里。需要找回上一版时，联系运维按这个规则取回。
- 如果旧文件因为权限/磁盘原因没能留存改名，**本次上传会直接中止并提示**，不会出现「新版写进去、旧版悄悄没了」。

## 四、上传被拒时怎么排查

| 提示 | 处理 |
|---|---|
| 文件名不符合对账命名约定 | 按第一节改名后重传 |
| 对账文件后缀仅支持 xlsx、xls、csv、txt（也可不带后缀） | 去掉或换掉后缀 |
| 对账日期不能为空，且必须与文件名里的账期一致 | 在弹窗里选日期（选文件后会自动带出） |
| 对账日期 X 与文件名账期 Y 不一致 | 二者改成同一天 |
| 文件大小不能超过 50MB | 拆分或压缩前确认后缀仍合规 |
| 旧对账文件留存失败，本次上传已中止 | 稍后重试；持续出现请联系运维查目录权限 |
| 该账期的同类对账文件刚刚已被上传 | 有人同时在传同一天的同类文件，刷新列表确认以哪一版为准 |

## 五、规则生效之前已经传上去的文件

上线前已存在的记录（例如早期传的 `对账.xls`）会保留，列表里「文件类别」一列显示 **历史命名**。
它们**仍可下载、可删除**，只是不参与新的「一账期一类一份」规则。

建议的处理方式：按第一节的格式改名后重传一份，再把历史那条删掉。

## 六、一句话记住

> **`ITP.类别.8位日期`** 或 **`reconciliation-bill-8位日期`**，
> 弹窗里的对账日期选成同一天，
> 同一天同一类再传就是覆盖（上一版自动留存，不丢）。
