# 支付宝开户开发计划

> 参考：地铁APP 开户接口 IF8A-01 (`/ci/app/requestApplication`)
> 目标：支付宝出行 `/channel/requestApplication`（规范 3.69 支付宝出行-开卡申请(新增)）

---

## 一、原开户流程（地铁APP）

### 1.1 入口
- **路径**：`POST /ci/app/requestApplication`
- **Controller**：`RequestApplicationController`
- **Service**：`AccountApplicationServiceImpl.requestApplication()`

### 1.2 处理流程

```text
接收 RequestApplicationReqDTO
    ↓
校验参数（thirdUserId、cardType、msisdn）
    ↓
检查用户是否已开户（UserItpRegInfoMapper.selectActiveByThirdUserId）
    ↓
分配卡号（CardPoolService.allocateNextCard）
    ↓
构建 UserItpRegInfo → INSERT
构建 UserItpRegLog → INSERT
    ↓
调用 ticketClient.registerRideStatus 注册乘车状态
    ↓
返回 cardId、cardType、signType、sign
```

### 1.3 关键字段映射

| 请求字段 | 表字段 | 说明 |
|---------|--------|------|
| `thirdUserId` | `USER_ITP_REG_INFO.THIRD_USER_ID` | 第三方用户ID |
| `cardType` | `USER_ITP_REG_INFO.CARD_TYPE` | 卡类型（经过 CardTypeMapping 转换） |
| `msisdn` | `USER_ITP_REG_INFO.MSISDN` | 手机号 |
| `channel` | `USER_ITP_REG_INFO.CHANNEL` | 支付通道编码 |
| `thirdPayId` | `USER_ITP_REG_INFO.THIRD_PAY_ID` | 支付账户ID |
| `reqContractNo` | `USER_ITP_REG_INFO.REQ_CONTRACT_NO` | 第三方签约流水号 |
| `cardIssueCode` | `USER_ITP_REG_INFO.CARD_ISSUE_CODE` | 发卡渠道代码 |
| `userName` | `USER_ITP_REG_INFO.USER_NAME` | 姓名 |
| `userId` | `USER_ITP_REG_INFO.USER_ID` | 身份证号 |

## 二、支付宝开户设计

### 2.1 接口定义（规范 3.69）

| 项目 | 说明 |
|------|------|
| **接口地址** | `POST /channel/requestApplication` |
| **接口说明** | 支付宝出行申请开卡 |
| **Controller** | `account-server` 新增 `FepAlipayTripRequestApplicationController` |
| **Service** | `AccountApplicationServiceImpl.alipayTripRequestApplication()` |
| **DTO** | `AlipayTripRequestApplicationReqDTO`（已有） |
| **响应** | `AlipayTripRequestApplicationRespDTO`（已有） |

### 2.2 请求字段（规范表 141）

| 字段 | 类型 | 说明 |
|------|------|------|
| `thirdUserId` | String | 第三方用户ID，格式化后的用户标识 |
| `cardType` | String | 卡片类型，如：02 |
| `msisdn` | String | 用户手机号码 |
| `extend1` | String | 扩展字段1 |
| `extend2` | String | 扩展字段2（可选） |
| `cardIssueCode` | String | 发卡渠道代码 `0007` 支付宝出行 |

### 2.3 响应字段（规范表 142）

| 字段 | 类型 | 说明 |
|------|------|------|
| `retCode` | String | 返回码 |
| `retMsg` | String | 返回消息 |
| `cardId` | String | 卡片ID/逻辑卡号，开卡成功后返回 |

## 三、字段映射关系

### 3.1 支付宝 → 内部字段映射

| 支付宝 DTO | 内部字段 | 映射规则 | 说明 |
|-----------|---------|---------|------|
| `thirdUserId` | `THIRD_USER_ID` | 直接映射 | 第三方用户ID |
| `cardType` | `CARD_TYPE` | `CardTypeMapping.toIssueCardType()` | 卡类型编码转换 |
| `msisdn` | `MSISDN` | 直接映射 | 手机号 |
| `extend1` | `EXTEND1` | 直接映射 | 扩展字段1 |
| `extend2` | `EXTEND2` | 直接映射 | 扩展字段2 |
| `cardIssueCode` | `CARD_ISSUE_CODE` | 直接映射 | 发卡渠道代码（0007） |
| — | `CHANNEL` | **固定值** | 支付宝渠道编码（待确认） |
| — | `THIRD_PAY_ID` | **固定值或空** | 支付账户ID（待确认） |
| — | `REQ_CONTRACT_NO` | **固定值或空** | 签约流水号（待确认） |
| — | `USER_NAME` | **空** | 支付宝开户不涉及姓名 |
| — | `USER_ID` | **空** | 支付宝开户不涉及身份证号 |

### 3.2 与原开户字段差异

| 字段 | 原开户（地铁APP） | 支付宝开户 | 处理方式 |
|------|-----------------|-----------|---------|
| `channel` | 请求传入 | 无 | 固定为支付宝渠道编码 |
| `thirdPayId` | 请求传入 | 无 | 固定为空或支付宝标识 |
| `reqContractNo` | 请求传入 | 无 | 固定为空 |
| `userName` | 请求传入 | 无 | 固定为空 |
| `userId` | 请求传入 | 无 | 固定为空 |
| `extend1` | 有 | 有 | 直接映射 |
| `extend2` | 有 | 有 | 直接映射 |
| `cardIssueCode` | 有 | 有 | 直接映射（支付宝固定 0007） |

## 四、Service 层实现设计

### 4.1 接口定义

```java
/**
 * 支付宝出行-开卡申请。
 * <p>
 * 参考 IF8A-01 请求开户，支付宝渠道独立处理。
 * 固定 channel = 支付宝渠道编码，不涉及签约信息。
 * </p>
 */
RequestApplicationResult alipayTripRequestApplication(AlipayTripRequestApplicationReqDTO request);
```

### 4.2 处理流程

```text
接收 AlipayTripRequestApplicationReqDTO
    ↓
校验参数（thirdUserId、cardType、msisdn、cardIssueCode）
    ↓
检查用户是否已开户（支付宝渠道）
    ↓
分配卡号（CardPoolService.allocateNextCard）
    ↓
构建 UserItpRegInfo（channel 固定为支付宝）
    ↓
构建 UserItpRegLog
    ↓
调用 ticketClient.registerRideStatus 注册乘车状态
    ↓
返回 cardId、cardType
```

### 4.3 关键逻辑

1. **渠道隔离**：通过 `channel` 字段区分支付宝和地铁APP开户
2. **卡号分配**：复用现有 `CardPoolService`
3. **ticket-server 联动**：复用现有 `ticketClient.registerRideStatus`
4. **不涉及签约**：支付宝开户不关联支付签约信息

## 五、与 ticket-server 交互

### 5.1 注册乘车状态请求

```java
RegisterRideStatusReqDTO request = new RegisterRideStatusReqDTO();
request.setThirdUserId(regInfo.getThirdUserId());
request.setCardId(regInfo.getCardId());
request.setCardType(regInfo.getCardType());
request.setMsisdn(regInfo.getMsisdn());
request.setCardIssueCode(regInfo.getCardIssueCode());
request.setChannel(regInfo.getChannel());        // 固定支付宝渠道
request.setThirdPayId(regInfo.getThirdPayId());  // 空或支付宝标识
```

### 5.2 响应处理

- 如果 ticket-server 返回成功，继续完成开户流程
- 如果 ticket-server 返回失败，回滚事务（`TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()`）

## 六、Controller 层设计

### 6.1 account-server 新增 Controller

```java
@RestController
@RequestMapping("/channel")
public class FepAlipayTripRequestApplicationController {
    @Autowired
    private AccountApplicationService accountApplicationService;

    @PostMapping("/requestApplication")
    public AlipayTripRequestApplicationRespDTO requestApplication(@RequestBody AlipayTripRequestApplicationReqDTO request) {
        log.info("接收到支付宝出行-开卡申请报文: {}", request);
        return accountApplicationService.alipayTripRequestApplication(request);
    }
}
```

### 6.2 路径对齐

| 服务 | Controller | 路径 |
|------|-----------|------|
| account-server（地铁APP） | `RequestApplicationController` | `/ci/app/requestApplication` |
| account-server（支付宝） | `FepAlipayTripRequestApplicationController` | `/channel/requestApplication` |
| fep-app-server | `FepAlipayTripController` | `/channel/requestApplication`（转发） |

## 八、待确认事项

| 序号 | 待确认项 | 当前建议 | 影响 |
|------|---------|---------|------|
| 1 | `channel` 固定值 | 开户阶段无此字段，建议固定为支付宝渠道编码（如 `03` 或自定义） | 影响 UserItpRegInfo.CHANNEL 字段 |
| 2 | `thirdPayId` 取值 | 开户阶段无此字段，可能为空，后续签约时更新 | 影响 UserItpRegInfo.THIRD_PAY_ID |
| 3 | `reqContractNo` 取值 | 开户阶段无此字段，可能为空，后续签约时更新 | 影响 UserItpRegInfo.REQ_CONTRACT_NO |
| 4 | `cardType` 映射 | 支付宝是否使用相同映射规则（如 `02` → `0441`） | 影响 CardTypeMapping.toIssueCardType() |
| 5 | `cardIssueCode` 固定值 | 规范中明确为 `0007` 支付宝出行 | 直接映射即可 |
| 6 | 是否需要支持重复开户 | 地铁APP已支持返回已开户信息 | 支付宝同样需要 |
| 7 | 错误码规范 | 规范中未明确，建议复用地铁APP错误码 | 影响返回 retCode |

## 十、风险点

| 风险 | 说明 |  mitigation |
|------|------|-------------|
| `channel` 编码不一致 | 支付宝渠道编码需与支付平台、签约模块保持一致 | 统一使用 `SignChannelEnum.ALIPAY` 或约定编码 |
| 卡池资源不足 | 支付宝用户可能在地铁APP已开户，卡号冲突 | 复用现有卡池分配逻辑 |
| ticket-server 兼容性 | 支付宝开户需注册乘车状态，需确认 ticket-server 支持 | 复用现有 `registerRideStatus` 接口 |
| 数据隔离 | 支付宝用户与地铁APP用户需通过 `channel` 隔离 | UserItpRegInfo 已包含 `channel` 字段 |
