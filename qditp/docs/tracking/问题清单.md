## IT-076 Web 前端 Nginx 代理配置在发版后失效

| 项 | 值 |
|---|---|
| 状态 | 已修复代码，待发版验证 |
| 严重度 | 高 |
| 发现 | 2026-11-18 |
| 处理 | `frontend_release.py` 发版后自动更新 configmap（`update_nginx_configmap`） |

**现象**：前端访问 `/para-server/*` 等接口 404（后端 NodePort 直连正常）。

**根因**：CloudOS 发版时新建 configmap `websyspresetweb-version-{version}` 是默认配置（无反代段），覆盖手工 patch 的代理配置；nginx.conf 里原用宿主机 IP `172.20.211.23:300xx`，pod 内不可达。

**修复**：
1. `web/nginx.conf` 全部 proxy_pass 改为 k8s service 短名（如 `para-server-internal:8080`）；
2. `frontend_release.py` 升级核验后调 `update_nginx_configmap()`，通过 kubectl apply 把 `web/nginx.conf` 写入新 configmap。

**验证**：`curl http://172.20.211.23:30029/para-server/page/risk/graylist` 曾短暂 HTTP 200；4 次发版中脚本因 k8s-master SSH 超时未实际写入，需在网络稳定后重发验证。

**关联**：Web 应用 UUID `63b73616dce8475486a7997ed6759a5b`；`setting_file_id` 用于 WAR 包不适用；nginx 配置走 ConfigMap 通道，与「应用包升级」是两条独立通道。
