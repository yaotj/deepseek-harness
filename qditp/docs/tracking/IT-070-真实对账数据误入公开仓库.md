# IT-070 真实对账数据误入公开 GitHub 仓库（数据安全）

## 1. 背景 / 现象
- 发现时间：2026-11-16 09:10（推送对账文档 commit 时）
- 发现渠道：推送自查——GitHub 远端警告 `File a15cfa18… is 77.82 MB`（GitHub LFS 阈值 50MB）+ `gh repo view` 确认 `yaotj/deepseek-harness` **PUBLIC**
- 影响范围：根级目录 `各商户号订单明细0928/`（仓库根，非 qditp/ 内）18 个被跟踪文件，含 78MB「9.28-卖出交易-支付宝.xls」（blob `a15cfa18…`）、21MB「9.28收-建行.xlsx」、微信后付费/预付费收退款 CSV、支付宝对账汇总表与 `_分析结果/`，均为 2026-09-28 真实交易/对账数据
- 现象：该目录由历史提交 `ccbc60d504`（sync SVN r1291 + 更新本地修改）引入且**仍在 HEAD 树**；任何能访问公开仓库者可取得全部原件

## 2. 根因分析
- 排查过程：`git log --find-object=a15cfa18…` → `ccbc60d504` 引入；`git ls-files`（仓库根视角）确认 18 个文件仍被跟踪；`git check-ignore` 确认无任何忽略规则覆盖该目录
- 根因结论：① 根 `.gitignore` 无真实数据排除规则（第 5 节只覆盖 `**/deploy/data/` 库导出）；② sync 提交未区分交付物与真实数据；③ 仓库长期 PUBLIC 无暴露面管理

## 3. 方案对比
| 方案 | 思路 | 优点 | 缺点 | 风险 |
|---|---|---|---|---|
| A HEAD 移出 + gitignore 护栏 | `git rm -r --cached`（保留本地文件）+ 根 `.gitignore` 加 `各商户号订单明细*/` | 可逆、零破坏、防再犯 | 历史旧版仍可 clone 取得，暴露未消除 | 低 |
| B 仓库转私有 | 业主凭 yaotj 账号 `gh repo edit yaotj/deepseek-harness --visibility private` | 立即收敛暴露面 | 已 fork/clone 的副本不受影响 | 低（可逆） |
| C 历史清除 + 强推 | `git filter-repo --path 各商户号订单明细0928/ --invert-paths --force` + 强推 + `git reflog expire` | 彻底删除历史全部版本 | 破坏性：所有既有 clone 失效；GitHub 侧缓存短期可能仍可达 | 高，MUST 业主书面授权 |
| D 只登记 | 仅加索引行 | 零成本 | 暴露持续 | — |

## 4. 决策与结论
- 选定方案：**A 已执行**（2026-11-16，本 commit）；**B / C 待业主裁决**——gh 当前凭据为 `entropy-collab` 账号（无 yaotj 仓库写权限，`gh repo edit` 404），B 无法代执行；C 为破坏性操作，按 §5.0 纪律 MUST 业主书面批准
- 决策理由：A 是可逆收口，符合「真实数据 NEVER 入库」纪律；B/C 改变仓库暴露面与全量历史，属业主权限边界
- 数据敏感性定级（是否含 PII / 金融数据、是否须按公司安全流程上报）**MUST 由数据 owner 裁决**，本仓不单方定论
- 关联：本地文件全程保留未删除；`qditp/docs/testing/itp-acc/samples/`（152MB）已由 `b906ad4b` 提交的分层 `.gitignore` 排除，不在本文范围
