# IT-103 补款后黑名单未清除（地铁App 渠道解黑被支付宝通知阻塞）

## 1. 背景 / 现象

- 发现时间：2026-11-23（代码与根因由上一会话产出；本会话完成部署与端到端验证）
- 发现渠道：用户反馈
- 影响范围：`blacklist-server` 解黑链路（`sys_job` 325 解黑补偿 / `sys_job` 230 自动解除 / `/release-card-if-settled` 实时解黑共用同一段投递逻辑）
- 现象描述：乘客补款结清后，APP 首页仍提示「刷新后可正常乘车」（黑名单未清）。测试库中 6 条卡长期停在 `STATUS='RELEASING'` + `CHANNEL_SYNC_STATUS='FAILED'`，`CHANNEL_SYNC_RETRY` 累计到 20~878 次：

|---|---|---|---|---|

| 58 | 0426090949000542 | 01 | 01 | auto-release-job |

## 2. 根因分析

- 排查过程：`SYS_JOB_LOG` 连续失败 + 服务端日志 `渠道不可达 IllegalStateException: 支付宝渠道未拿到支付中心结论: 调用支付中心黑名单通知接口失败`；对照 `BLACKLIST.CHANNEL_CODE` 全为 `01`。
- 根因结论：`BlacklistChannelSyncService.deliverReleaseRow()` 对**所有渠道**的解黑行都调 `AlipayBlacklistNotifyPort.notifyBlackListChange()`（→ `alipay-pay-sign-server` → 支付中心）。但渠道口径是 `01`=地铁App、`02`=支付宝（同 `BlacklistAutoReleaseService` 常量与 §三 渠道路由）：
  - `01` 的黑名单由 ITP 自身生效：判黑走 `queryBlackList` 查 `BLACKLIST` 主表，HCE 票种（0442/0443）另由 `sys_job` 355 生成 `PRM.0013.9700.<版本>` 全量文件 —— **不需要、也不应依赖支付宝通道**；
  - `02` 才需要实时通知支付宝。
  测试环境支付中心该通知接口不可达 ⇒ `01` 的解黑行恒 `FAILED`，而两阶段解除只在 `RpcOutcome.Ok` 时才 `completeRelease`，于是行永久留在 `RELEASING`，`queryBlackList` 判黑恒命中。

## 3. 方案对比

| 方案 | 思路 | 优点 | 缺点 | 风险 |
|---|---|---|---|---|
| A | 保持现状，等支付中心接口可用 | 不改代码 | `01` 卡解黑永久依赖无关通道；支付中心故障即乘客无法乘车 | 高 |
| B（选定） | `deliverReleaseRow()` 按 `CHANNEL_CODE` 分流：`01` 直接 `completeRelease` 收口、跳过支付宝通知；`02` 及未知渠道保持原逻辑 | 与既有渠道语义一致（复用 `BlacklistAutoReleaseService` 的 `01`/`02` 口径）；不触碰通知与状态机 | 需注意 `99` 未知渠道仍走原路径（保持现状，不在本单放宽） | 低 |
| C | 把 `01` 的 `channelCode` 在加黑入口改写为 `02` | 少一处分支 | 与 IT-087 已裁决的「`channelCode` 按真实渠道落、NEVER 在解除侧猜渠道」冲突 | 高 |

## 4. 决策与结论

- 选定方案：**B**（`blacklist-server` 2.0.51，`BlacklistChannelSyncService#deliverReleaseRow`）。
- 决策理由：解黑的业务前提是「欠费已结清」（`BLACK_CAUSE='01'` 自动解除 / 人工解除），本地主表删行即对所有 ITP 入向生效；`01` 渠道不存在需要支付宝侧同步的事实，把它挂在支付宝通道上等于给地铁侧乘客引入一个无关的外部依赖（IT-087 已确认拉码拦截靠本地黑名单、`CHANNEL_SYNC_STATUS` 只是出向旁路）。
- 影响范围：仅解黑投递分支；`02` 与 `99` 路径逐字未动；加黑方向（`deliverAddRow`）未动（见 §5 遗留）。
- 代码：`blacklist-server/src/main/java/com/chinasofti/huateng/blacklist/service/impl/BlacklistChannelSyncService.java`；版本 `2.0.50 → 2.0.51`。
