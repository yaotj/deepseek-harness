# IT-004 综管台部门管理：修改部门报「系统接口405异常」（前端接口路径拼写错误）

> 本处理文档对应 `docs/tracking/问题清单.md` 索引表中 `IT-004` 一行。
> 流程：先在索引表加一行 → 再建本处理文档 → 处理完回填索引「状态 / 处理情况 / 更新」。

## 1. 背景 / 现象

- 发现时间：2026-10-15（业主反馈）
- 发现渠道：用户反馈 —— 「修改若依科技名字报错：系统接口405异常」
- 影响范围：综管台「系统管理 → 部门管理」的**修改部门**（含改部门名称、上级部门、显示排序、负责人、电话、邮箱、状态）全部不可用；新增、删除、查询不受影响。
- 现象描述：在部门管理里点「修改」，改完「若依科技」的名称点确定，前端弹出错误提示 **「系统接口405异常」**，改动不落库。

## 2. 根因分析

- **报错文案溯源**：`web/src/utils/request.js:118` 把真实 HTTP 状态码拼进文案 ——
  `message = "系统接口" + message.substr(message.length - 3) + "异常"`。
  故「系统接口405异常」= **浏览器真实收到 HTTP 405 Method Not Allowed**，不是后端业务码。
  （后端 `GlobalExceptionHandler` 的 `HttpRequestMethodNotSupportedException` 分支返回的是 Spring 原生 message，与本文案无关。）
- **定位**：`web/src/api/system/dept.js` 第 40 行 `updateDept` 的 URL 拼错 ——

  ```js
  // 错误
  url: '/web-serve/system/dept',   // 缺 "r"
  // 正确（同文件其余 5 个接口均为该写法）
  url: '/web-server/system/dept',
  ```

- **为什么是 405 而不是 404**（关键，也是该 bug 潜伏两个月的唯一原因）：
  `/web-server/*` 是网关/nginx 明确代理到后端的 location，而 `/web-serve/*` **不匹配任何代理规则**，落进前端静态资源的 catch-all location（`try_files ... /index.html`）。
  - 静态 location 对 **GET/HEAD** 会回退返回 `index.html` ⇒ **HTTP 200**，请求"看起来成功了"，只是拿回一坨 HTML；
  - 对 **PUT/POST/DELETE** 等非 GET 方法，nginx 直接判 **405 Not Allowed**，请求根本到不了后端。
  这解释了为何只有「修改」（PUT）暴露问题，而没人早点发现。
- **实测复现**（测试环境 `172.20.211.23:30029`）：

  | 请求 | 结果 |
  |------|------|
  | `PUT /web-serve/system/dept` | **405** ← 与业主报错一致 |
  | `GET /web-serve/system/dept` | 200（响应体为 `index.html`，SPA 回退，假成功） |
  | `PUT /web-server/system/dept` | 200（经 istio-envoy 进入后端，`content-type: application/json`） |
  | `GET /web-server/system/dept/list` | 200（`content-type: application/json`，后端路由成立） |

- **引入时间**：`git log -S` 定位到提交 `eed643c`（2026-08-14，message "commit"）—— 该提交把 `addDept` 从 `/system/dept` 改成 `/web-server/system/dept`（正确），但 `updateDept` 改成了 `/web-serve/system/dept`（少一个 `r`）。**潜伏约两个月**，`1.2.29` / `1.2.30` / `1.2.31` 三个发布包均含此错。
  ⚠️ 排查教训：核对旧包时若 zip 内路径带 `dist/` 前缀，用 `unzip -p 'static/js/*.js'` 会**静默零命中**（假阴性）。必须用 `unzip -p '*static/js/*.js'` 或先 `unzip -l` 看结构。本次一度据此误判「1.2.29 不含该错误」，已纠正。
- **根因结论**：前端接口路径拼写错误 + nginx 静态 location 对非 GET 方法返回 405 的组合，导致「修改部门」全链路不可用。

## 3. 方案对比

| 方案 | 思路 | 优点 | 缺点 | 风险 |
|------|------|------|------|------|
| 方案A | 只改前端 URL 为 `/web-server/system/dept` | 一行修复、与同文件其余 5 个接口写法一致、零后端改动 | 无 | 低 |
| 方案B | 同时在 nginx 增补 `/web-serve/` 的兜底重写 | 能兜住同类手误 | 引入不该存在的路由别名，掩盖错误、增加排障噪声，且违背"路径唯一" | 中 |
| 方案C | 在 nginx 把静态 location 的 405 改成 404 | 报错码更"准确" | 未修根因，且 405→404 同样不可读，属治标 | 中 |

## 4. 决策与结论

- 选定方案：**方案A**（一行修复；不引入路由别名、不改 nginx）。
- 决策理由：错误本身是纯前端拼写，同文件其余 5 个接口（list / exclude / get / add / del）写法均正确，说明是孤立手误，不需要动部署层。
- 落地改动：`web/src/api/system/dept.js` 第 40 行 `'/web-serve/system/dept'` → `'/web-server/system/dept'`。
- 同类问题排查（已做）：统计 `web/src` 全部 API 一级前缀分布 —— `/web-serve` 全仓仅此 1 处，其余（`/web-server` 115、`/para-server` 16、`/para` 6、`/account-server`、`/card-pool-server` …）均为合法服务名，**无同类拼写错误**。
- 影响范围 / 关联模块：仅 `web`（综管台前端）。后端、数据库、其他服务零改动。
