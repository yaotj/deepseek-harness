# IT-021 红岛网关路由表缺失

> 本处理文档对应 `docs/tracking/问题清单.md` 索引表中 `IT-021` 一行。

## 1. 背景 / 现象

- 发现时间：2026-10-26
- 发现渠道：自查（route-sentinel 发布红岛前的部署可行性评估）
- 影响范围：route-sentinel 在红岛 `itpb` 的首次部署；连带影响 `fep-app-vr` 7 条 SCG exact 路由的落地
- 现象描述：
  红岛生产库 `QDITP_PLAT` schema **不存在** `GATEWAY_ROUTE_CONFIG` 与 `GATEWAY_ROUTE_CONFIG_AUDIT` 两张表。
  两者是 route-sentinel 的路由配置主表与审计表，`GatewayRouteRepository` 的启动兜底加载、
  Actuator 增删改落库、审计留痕全部依赖它们。缺表时网关的行为**按代码版本分两段**（2026-10-27 更新）：
  - **1.0.1（红岛 2026-10-26 首发镜像）——fail-fast，无降级**：`UserRouteService.preload()`（`@PostConstruct`）
    启动预热 `SELECT DISTINCT third_user_id FROM user_itp_reg_info` 一旦异常即 catch 后仍
    `throw new IllegalStateException` → Spring 初始化中断 → 容器 **CrashLoopBackOff**（2026-10-26 红岛实测，
    堆栈见本单 §7）。「降级为空路由跑着」在 1.0.1 不成立。
  - **1.0.2 起（2026-10-27 仓库改动）——preload 改为降级启动**：预热失败只 `log.error`，缓存留空、
    首个查询按需回源（回源失败 fail-safe 走旧 ITP）；`reloadSplitPaths`（失败置空）与 `loadLegacy`
    的运行期 fail-safe 不变。网关能起来，但 `GATEWAY_ROUTE_CONFIG` 缺失时路由仍为空 →
    7 条分流路径 404，Actuator 变更无法落库。

## 2. 根因分析

- 排查过程：
  1. `docs/ops/environments/scripts/migration/domain_map.py` 的 `PLAT` 定义**已包含**
     `GATEWAY_ROUTE_CONFIG` 与 `GATEWAY_ROUTE_CONFIG_AUDIT`（该文件第 8-10 行注明是
     「manifest 缺口裁决」补录的）；
  2. 但 `20261017_schema_plat.sql` 实际 `CREATE TABLE` 只有 **68** 张，两张网关表**均未建**；
  3. 差集核算：`domain_map.PLAT`（100 张）− `schema_plat.sql` 实建（68 张）= **45 张未建**，
     其中包含这两张网关表（另有 `AGM_DEVICE_STATUS` 及 42 张 TVM/BOM/RuoYi 相关表，同属同类缺口）；
  4. 全部 17 个迁移 SQL 中 `GRANT ... GATEWAY_ROUTE_CONFIG` 命中数 = **0**；
  5. 账号侧：迁移只建了 `itp_ro`（`CREATE SESSION, CREATE SYNONYM` + 对
     `QDITP_USER.USER_ITP_REG_INFO` 的只读授权），**没有任何可写网关账号**——
     而 Actuator 需要对 `GATEWAY_ROUTE_CONFIG` 做 INSERT/UPDATE、对审计表做 INSERT。
- 根因结论：
  红岛「按域分库」迁移把网关表判定归 PLAT 域（域映射已更新），但**建表脚本与授权脚本没有同步补齐**，
  属于「域映射已改、物料未跟上」的迁移物料缺口。网关在测试环境用的 `QDITP` 单 schema 直连，
  迁到红岛后 schema 前缀与账号模型都变了，这两处未随迁移物料一起调整。

## 3. 方案对比

| 方案 | 思路 | 优点 | 缺点 | 风险 |
|------|------|------|------|------|
| 方案A | DBA 在红岛 `QDITP_PLAT` 建两张表 + 建可写账号 | 与按域分库既定口径一致；网关代码零改动 | 需 DBA 介入；建表脚本前缀需从 `QDITP.` 改 `QDITP_PLAT.`；账号口令须现查 | 低（只新增对象，不动存量） |
| 方案B | 沿用 `itp_ro`，只给它补 `GATEWAY_ROUTE_CONFIG` 写权限 | 改动最小，不新增账号 | `itp_ro` 语义是「只读账号」，补写权限破坏语义；`USER_ITP_REG_INFO` 的「绝不写」契约是分库计划明文要求 | 中（削弱分域隔离的可审计性） |
| 方案C | 网关不落库，纯内存配置（`GATEWAY_ROUTE_CONFIG` 空表 + 启动不加载） | 改动最小 | Actuator 变更即丢，重启回退；与既有设计（落库 + 审计留痕）冲突 | 高（丢失变更历史，违反既有设计） |

## 4. 决策与结论

- 选定方案：**方案A**
- 决策理由：
  - `AGENTS.md` §5.D「数据迁移 / 拆库 / 按域分库」明确要求按既有域归属推进，不为省事改语义；
  - `docs/ops/数据库按域分库计划.md` 的分域原则是「强耦合表同库、跨库只读授权」，
    网关对 `USER_ITP_REG_INFO` 保持只读（`itp_ro` 契约不变），对**自己拥有的**
    `QDITP_PLAT.GATEWAY_ROUTE_CONFIG` 具备写权限——两者用**不同账号**即可共存；
  - 方案 B 会把 `itp_ro` 从「只读」变成「可写」，与分库计划的明文约束冲突，且后续审计难以区分
    「网关误写用户注册表」这类异常；方案 C 牺牲了变更留痕，不可接受。
- 影响范围 / 关联模块：
  - route-sentinel（红岛首次部署前置条件）
  - `QDITP_PLAT` schema（新增 2 张表 + 1 个可写账号）
  - `fep-app-vr` 7 条 SCG exact 的落地依赖此表（`legacy-route` 路由从库表加载）
- 待人工裁决 / 需现场确认：
  1. **建表**：`route-sentinel/src/main/resources/sql/gateway-route-config-schema.sql`
     的 schema 前缀 `QDITP.` MUST 改为 `QDITP_PLAT.`；分区子句
     （`PARTITION BY LIST (ROUTE_ID)` 两个值域、`PARTITION BY RANGE (OPERATE_TMS)`
     起始分区 `P_202610`）在红岛需按当期月份调整，且 `P_NEW` 分区值域是 `new-route`，
     而**实际路由 id 是 `face-pay-split-route`**（见 `docs/business/route-sentinel.md`）——
     照抄会直接插不进新路由，MUST 一并裁决；
  2. **账号**：需 DBA 新建一个网关专用可写账号（或明确裁决走方案 B 并记录理由）；
     口令 MUST 现查，NEVER 写进仓库 / 文档；
  3. **建表与授权 MUST 先在测试库演练**（AGENTS.md §5.D），NEVER 直接在生产库执行 DDL。

### 4.1 账号最终裁决（2026-10-28 更新，覆盖 §4「待人工裁决 2」）

- **裁决**：route-sentinel 单数据源账号 **复用 `QDITP_PLAT`**（口令 `itp!#plt6308`，仓库真源见 `跨环境共性.md` §3.1），**不再新建方案A 专用可写账号**。
- **理由**：
  - `QDITP_PLAT` 默认 schema 即 `QDITP_PLAT`，网关两表建在该 schema 后非限定名 `gateway_route_config` / `gateway_route_config_audit` 直接解析、可读写，无需额外授权；
  - 唯一缺口是 `USER_ITP_REG_INFO` 跨域只读——迁移只给 `itp_ro` 建了同义词，未给 `QDITP_PLAT` 建；补一条
    `GRANT SELECT ON QDITP_USER.USER_ITP_REG_INFO TO QDITP_PLAT` + `CREATE SYNONYM QDITP_PLAT.USER_ITP_REG_INFO FOR QDITP_USER.USER_ITP_REG_INFO` 即可（已写入 `20261028_route_sentinel_gateway_hongdao.sql` Step 2/3）；
  - 复用既有账号 = 零新增账号面、口令走仓库真源，比新建专用账号更省且同样满足「PLAT 写 + USER 只读」的双域约束；
  - `itp_ro` 仍不满足（无网关表、不能写审计），排除。
- **前置（DBA 侧，IT-021 解封第 2 件）**：DBA 先跑 `20261028_route_sentinel_gateway_hongdao.sql` 建齐对象，运维再注入 env（解封第 3 件）。
- **修正点（相对 route-sentinel 自带 schema SQL）**：脚本前缀 `QDITP.`→`QDITP_PLAT.`；LIST 分区值域 `new-route`→补 `face-pay-split-route` + `DEFAULT`（实际路由 id 是 `face-pay-split-route`，原 `new-route` 会导致新路由 ORA-14400 插不进）。
