# IT-079 云闪付签约平台返系统内部错误但本地落 SIGNED，扣款 3910014

> 本处理文档对应 `docs/tracking/问题清单.md` 索引表中 `IT-079` 一行。

## 1. 背景 / 现象
- 发现时间：2026-11-19 10:31（复核订单 GT20261118115843625000508 时连带发现）
- 发现渠道：自查（对账 APP 乘车记录汇总时追查未扣款订单）
- 影响范围：测试环境；卡 `0426090949000508`（用户 00523018，测试号 19900001231）的 0.04 元扣款卡 FAIL；重档依据＝**跨系统契约不一致**（ITP 与支付平台签约状态分叉）
- 现象描述：
  1. 2026-11-18 10:08:40 该用户通过 APP 完成云闪付（07）签约：pay-sign `/requestSignInfo` 调支付平台，平台**同步返回 `9001/系统内部错误`**（`APP_PAY_SIGN_REQUEST` OP=SIGN 记录为证）；
  2. 15ms 后 fep-app 又向 pay-sign `/ci/app/receiveSignResult` 上报 `status=SUCCESS, payAgreementNo=6218409001102733703`，pay-sign 落 `APP_PAY_SIGN_INFO` SIGNED；
  3. 11:58 乘车出站生成订单 GT20261118115843625000508（4 分，0441 二维码票 99% 折），扣款走 `paymentVendor=07`；
  4. 支付平台扣款接口持续返回 `9001/未查到相关信息[3910014]`——**平台侧查无此签约**；11-18 当日 10 次自动重试 + 11-19 01:00 批量重试（第 11 次）全部 FAIL；
  5. GATE_TXN_PAY `DEBIT_STATUS=FAIL`、`PAY_TXN_DETAIL.PAY_STATUS=RETRY`；`DEBIT_NEXT_RETRY_TIME=2026-11-19 13:00:03` 预计仍失败。

## 2. 根因分析
- 排查过程（traceId `16941532472941648aab5dd8e472638e` 及签约 trace，VL 全量还原）：
  - 签约：`fep-app IF8A-16 → pay-sign /requestSignInfo → 支付平台`（10:08:34→10:08:40，平台返 9001/系统内部错误）；随后 `fep-app → pay-sign /ci/app/receiveSignResult` 携带 SUCCESS + 协议号（来源待与平台/渠道确认：平台异步通知 or 测试桩回执）；
  - 扣款：pay-sign `REQUEST_PAY 调用支付平台` bizData 含 `requestSignSeq=0052301801524730 / paymentVendor=07`，平台返 `3910014`；全库 VL 搜 `3910014` 仅本订单 50 条命中，无其它渠道/用户先例；
  - 旁证：同批 01:00 批量重试 4 笔中，03/支付宝一笔（GT20261118151450268000531）成功受理，证明非支付宝渠道重试链路本身通畅；`industryDetail.channelAgreementNo=""` 为全渠道统一硬编码（`ticket-server AlipayIndustryDetailAssembler:94`），成功单同样为空，排除该字段因素。
- 根因结论：**签约在支付平台侧未有效建立**（平台签约接口返系统内部错误），ITP 却依据 receiveSignResult 落了 SIGNED → 两侧签约状态分叉；平台扣款按签约关系查找不到 → 3910014。ITP 侧 `PaymentVendorEnum` 缺 UNION_PAY 的缺陷（IT 记忆 §2026-11-19 修复项）只是历史遮罩，修复后错误原样暴露，属**平台侧/渠道侧问题**。

## 3. 方案对比
| 方案 | 思路 | 优点 | 缺点 | 风险 |
|------|------|------|------|------|
| A. 平台侧修复签约 | 支付平台核查 6218409001102733703 签约记录与「系统内部错误」原因，修复后由 13:00 批量重试自然补扣 | 治本；ITP 零改动 | 依赖第三方排期；时点不可控 | 平台若查无签约，需用户重新签约 |
| B. 用户重新签约 07 | APP 侧解约（需先解 8010 解约申请不存在的卡单，见记忆 §11）后重签，重试链路补扣 | ITP 内可闭环 | 用户操作；解约链路有已知缺陷 | 重签若再遇平台系统内部错误则复发 |
| C. ITP 侧兜底改单 | 人工将本单置成功/免单 | 快速消横幅 | 掩盖数据真相；对账缺口 | 资金不一致，禁用 |

## 4. 决策与结论
- 选定方案：**A 为主、B 为备**；C 禁用。
- 决策理由：签约关系真源在支付平台，ITP 不能单方面改口；先由平台核查修复，平台侧无进展再走重新签约。
- 影响范围 / 关联模块：pay-sign（签约受理/结果回执）、fep-app（IF8A-16 回执转发）、支付平台（第三方）；解约清理受 8010 卡单阻塞（PENDING 收口问题，见 IT 记忆 §11）。

## 5. 验证与回滚
- 验证方式 / 结果：平台修复后触发一轮批量重试（web-server `行程扣费重试` job），观察 `GATE_TXN_PAY.DEBIT_STATUS` → SUCCESS、`PAY_TXN_DETAIL.PAY_STATUS` → SUCCESS 且 `PAY_TIME` 落值；APP 横幅「存在未扣费订单」消失。
- **2026-11-19 平台取证（复刻 PayGatewayClient 报文直调 BestOnePay 测试网关，商户号 JOPJ490HLK9Z + RSA2）**：
  - `/contract/queryResult`（seq 0052301801524730）：平台持有 `payAgreementNo=6218409001102733703 / payUserId=PZAg8+...`，但 `status=UNSIGNED`（同步签约失败后平台侧关闭）；
  - `/contract/creditQuery`：`已解约，不能进行咨询`；`/payment/payQuery`：`未找到数据`；
  - `/contract/requestContractConfig`（paymentVendor=07）：**正常**返回银联 SDK 参数（appId 05487011…/scope upapi_contract/planId e59da2f6…/merId 105053241110003）→ 平台 07 渠道配置存在；
  - `/contract/contract` 重放：原 seq `已关闭,请重新生成签约流水`；新 seq + 旧 authCode `不合法的授权code，或已过期`；token/payUserId/mobilePhone 模式均 `授权code不能为空` → **服务端无法绕过 authCode 完成签约**（authCode 与银联真实校验、一次性）。
  - 当日 10:53 手动提前重试一轮（`DEBIT_NEXT_RETRY_TIME` 前移后调 `/internal/gate-txn-pay/debit/retry/default`）：平台返 `{"code":600,"msg":"操作失败"}`（原 3910014），协议仍 UNSIGNED，扣款再败；`DEBIT_RETRY_TIMES=2`，下次自动重试 22:53。
- 根因收敛：**云闪付签约必须由用户在云闪付 APP 内经 SDK 完成并产生新 authCode**，平台 contract 才能建 SIGNED 协议；异步通知落 ITP（APP_PAY_SIGN_INFO + APP_USER_PAY_CHANNEL.REQ_CONTRACT_NO 自动更新为新 seq）后，后续批量重试自动命中新协议补扣成功。ITP 侧链路（枚举修复/签约登记/通道行/扣款解析）已全部就绪。
- 回滚预案：无代码改动；若重签路径执行，先按 IT 记忆 §11 人工推进 8010 卡单（手工 markPendingSuccess + 补发通知/渠道同步，或重建解约申请）。
