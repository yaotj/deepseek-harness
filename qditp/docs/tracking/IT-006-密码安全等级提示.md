# IT-006 综管台密码设置缺安全等级提示（密码策略仅靠人工记忆，无强度反馈）

> 本处理文档对应 `docs/tracking/问题清单.md` 索引表中 `IT-006` 一行。
> 流程：先在索引表加一行 → 再建本处理文档 → 处理完回填索引「状态 / 处理情况 / 更新」。

## 1. 背景 / 现象

- 发现时间：2026-10-15
- 发现渠道：用户反馈 —— 「用户登录密码设置时需要安全等级提示，具备大小写字母，数字，符号」
- 影响范围：综管台（`web`）**所有「设置密码」输入点**共 4 处 —— 用户管理「新增用户」、用户管理「重置密码」、
  个人中心「修改密码」、注册页（当前不可达，见下）。不影响登录页（登录是校验既有密码，不做强度约束）。
- 现象描述：设置密码时**没有任何强度提示**，用户不知道系统要求什么、也不知道自己输入的口令强不强；
  密码是否合规完全靠人工记忆与口头约定。

## 2. 根因分析

- 综管台基于 RuoYi 底座，**原生就没有密码强度组件**：`type="password"` 输入框旁无任何策略提示或强度反馈。
- 排查中发现一处**残留半成品**：`views/system/user/index.vue` 里其实已经存在一段「强度条」DOM，
  但它引用了仓库内**全仓未定义**的 `getStrengthLevel()` / `getStrengthText()`（模板渲染即抛错），
  且它使用的 CSS 类在样式表里**没有任何定义** —— 属"写了半截、从未可用"的死代码。
  这与 IT-001 / IT-005 是同一类问题模式：**仓库里"看起来有"的东西实际不生效**。
- 另有一处**策略冲突**：`sys_config` 的 `sys.user.initPassword = '123456'`（6 位纯数字，0 类字符），
  该值会在「新增用户」时**自动预填**到密码框。若直接上强度校验，会把「新增用户」这条主流程卡死。
- 约束：业主要求**只做前端提示**，不做后端强制校验 —— 故不动 `web-server`（web-admin）任何 Java 代码。

## 3. 方案对比

| 方案 | 思路 | 优点 | 缺点 | 风险 |
|------|------|------|------|------|
| 方案A | 新建**共享策略模块** `utils/password.js` + **共享组件** `components/PasswordStrength`，4 处统一接入 | 一处定义无漂移；规则与提示文案可被复用/单测；与 IT-005「一处定义」的教训一致 | 需新增 2 个文件并改 3 个页面 | 低 |
| 方案B | 每个页面各写一套强度逻辑 | 改动局部 | 4 份副本必然漂移；后续改策略要改 4 处 | 中 |
| 方案C | 后端 `UserController`/`SysUserServiceImpl` 加强校验 | 防绕过（脚本直接调接口） | 与业主明确选择「只做前端提示」冲突；且会卡住历史数据 | 中 |

## 4. 决策与结论

- 选定方案：**方案A**（业主经确认选择：复杂度＝至少 3 类 + 最短 8 位；校验范围＝只做前端提示；
  重置密码交互＝改成带强度条的对话框；初始密码冲突＝改配置为合规初始密码）。
- **密码策略（唯一真源 `web/src/utils/password.js`）**：
  - 长度 **8–20 位**；
  - 字符类别取「大写字母 / 小写字母 / 数字 / 特殊符号」四类中的**至少 3 类**；
  - 强度分级：满足「≥3 类 **且** ≥8 位」＝**强**；满足 ≥2 类＝**中**；其余＝**弱**。
- 落地改动：
  1. **新增 `web/src/utils/password.js`**（策略唯一真源）：导出 `PASSWORD_MIN_LENGTH=8`、
     `PASSWORD_MAX_LENGTH=20`、`PASSWORD_MIN_CLASSES=3`、`checkPasswordChars`、`countPasswordChars`、
     `getPasswordStrength`、`PASSWORD_POLICY_HINT`、`validatePasswordPolicy`、`passwordPolicyValidator`。
     注意**未复用** `utils/validate.js` 的 `validLowerCase`/`validUpperCase` —— 那两个是**整串匹配**（`/^[a-z]+$/`），
     语义是"整串都是小写"，与"包含小写"不同，直接复用会误判。
  2. **新增 `web/src/components/PasswordStrength/index.vue`**：3 段强度条 + 强/中/弱文字 +
     四类字符清单（实时打勾）+ 策略说明行。
  3. **`views/system/user/index.vue`**：
     - 修掉原有的死代码强度条，改为 `<password-strength :password="form.password" />`；
     - 新增用户密码规则挂 `passwordPolicyValidator`；
     - **「重置密码」由 `$prompt` 弹窗改为 `<el-dialog>` 对话框**（`$prompt` 无法承载强度条），
       内含「新密码 + 确认密码」双输入、强度条与一致性校验。
  4. **`views/system/user/profile/resetPwd.vue`**（个人中心改密）：加强度条 + 策略校验。
  5. **`views/register.vue`**（注册页）：同步加强度条 + 策略校验。
     —— 该页当前**不可达**（`sys.account.registerUser = false`），属**防御性统一**，避免日后开放注册时漏改。
  6. **`web-server/sql/ry_20250522.sql` 与 `ry_20250522_oracle.sql`**：种子行
     `sys.user.initPassword` 由 `'123456'` 改为 **`'Itp@2026Init'`**，描述同步注明策略要求。
  7. **数据库 `SYS_CONFIG`**（测试环境）：`sys.user.initPassword` 由 `123456` 改为 `Itp@2026Init`
     （12 位、4 类，自检**符合**策略）。
- 影响范围 / 关联模块：仅 `web`（综管台前端）+ 一条 `sys_config` 数据行；**web-admin 后端零改动**。
