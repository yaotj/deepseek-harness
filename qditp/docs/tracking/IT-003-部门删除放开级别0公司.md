# IT-003 综管台部门管理：级别 0 的公司可删除（级联删除子树 + 清空用户部门归属）

> 本处理文档对应 `docs/tracking/问题清单.md` 索引表中 `IT-003` 一行。

## 1. 背景 / 现象

- 发现时间：2026-10-15（业主再次提出，文字与 2026-10-09 同）
- 发现渠道：业主需求 + 2026-10-12 周报遗留待办「第 7 项：删除含子部门/用户的公司是否加防护」
- 影响范围：综管台「系统管理 → 部门管理」的删除行为
- 现象描述：级别 0 的公司「若依科技」界面上已能看到删除按钮，但点删除**必被后端拒**：`SysDeptController.remove` 先返回「存在下级部门,不允许删除」、再返回「部门存在用户,不允许删除」。

## 2. 根因分析

- 前端：`web/src/views/system/dept/index.vue` 删除按钮只受 `v-hasPermi="['system:dept:remove']"` 控制、已无 `parentId != 0` 限制 —— **该部分已达要求**，且随 `1.2.30` 于 2026-10-15 15:29 在测试环境生效（线上 chunk 与本机构建逐字节一致）。
- 权限点：`SYS_MENU` 1019 `system:dept:remove` 存在，已授予 role 2 / role 100；role 1 走 `PermissionService` 全体放行 ⇒ 按钮可见性无问题。
- 后端：两道拦截是 **RuoYi 基线代码**（`SysDeptController.remove`，该文件自导入后从未改动）⇒ 按钮能点、删除必失败，这是业主实际卡住的点。
- 数据现状（AFCITPDB 现查 2026-10-15）：唯一级别 0 公司「若依科技」(`DEPT_ID`=100)；**按 `del_flag='0'` 口径**其可见子树为 101 深圳总公司 / 103 研发部门 / 104 市场部门 / 105 测试部门，共 **4 个后代部门**；另有直属用户「张玉强」(113)。⚠️ `102/106/107/108/109` 早已是 `del_flag='2'` 的历史软删除数据，**NEVER 按「9 个后代」理解**。`SYS_USER` 中「张三一」(120) 的 `dept_id` 为 NULL ⇒「用户无所属部门」是本系统既有合法状态。

## 3. 方案对比

| 方案 | 思路 | 优点 | 缺点 | 风险 |
|------|------|------|------|------|
| 方案A | 保持拦截（现状），靠人工先移用户、逐个删子部门 | 零风险 | 级别 0 公司事实上删不掉，需求不达 | 低 |
| 方案B | 只放开「有下级部门」（级联删子树），有用户仍拒 | 较保守 | 「若依科技」仍有直属用户，仍删不掉 | 中 |
| 方案C | **两道都放开**：级联删整棵子树 + 把子树内用户 `dept_id` 置空 | 级别 0 公司可直接删，需求闭环 | 删除影响面大 | 中（逻辑删除，可回滚） |

## 4. 决策与结论

- 选定方案：**方案C**（2026-10-15 业主拍板）
- 落地改动：
  - `SysDeptMapper` + `SysDeptMapper.xml`：新增 `selectDeptAndDescendantIds`（按祖先串取子树，`INSTR` 写法与既有 `selectChildrenDeptById` 一致，仅取 `del_flag='0'`）、`deleteDeptByIds`（批量逻辑删除）。
  - `SysUserMapper` + `SysUserMapper.xml`：新增 `clearDeptIdByDeptIds`（`dept_id` 置 NULL、`update_time=SYSDATE`）。
  - `ISysDeptService` / `SysDeptServiceImpl`：新增 `deleteDeptCascade`，在 `@Transactional(rollbackFor = Exception.class)` 内**先清用户部门归属、再整体软删子树**，NEVER 出现「部门删了用户还挂着」的中间态。
  - `SysDeptController.remove`：去掉两道 `warn` 拦截；**MUST 保留 `checkDeptDataScope`（数据权限校验）**，否则普通角色可越权删除数据范围外的部门。
  - `web/src/views/system/dept/index.vue`：删除确认框在「有下级部门」时明确提示影响范围（下级部门一并删除、相关用户部门归属被清空）。
- 影响范围 / 关联模块：`web`（综管台前端）+ `web-server`（web-admin / web-system）。仅限部门删除路径，未触碰用户、角色、菜单逻辑。
- 有意保留：`hasChildByDeptId` / `checkDeptExistUser` 两个方法不删（基线 API，当前无调用点）。**恢复原保护只需在 `SysDeptController.remove` 加回两个 `if` 分支**，策略回滚成本为一行级。
