# IT-083 风险规则命中自动加黑定时任务（黑名单直拉规则组）

## 一、背景与目标

「黑名单直拉规则组」（现网 groupId=65，组名跨环境稳定）只收规则定义即「列入黑名单」的直拉规则：
000003 最大允许单边交易数（7 天 ≥3 次）、000002 出站规则（重复出站 ≥3 次）。
当前规则阈值已配（RISK_LIMIT_VALUE=3，用户 2026-11-19 裁定），但「命中 → 拉黑」无自动化链路，
全靠人工看风控记录后手工加黑。本任务补齐该链路。

## 二、方案

调度链完全沿用现有模式：

```
SYS_JOB(job_id=425, 0 5/10 * * * ?) → web-admin Quartz
  → riskRuleBlacklistSyncQuartzTask.sync()
  → ParaClient.riskRuleBlacklistSync()          (rpc 模块新增方法)
  → POST para-server /internal/risk/rule-blacklist-sync
  → para-server 聚合 TBL_RISK_CONTROL_LOG（本域表）
  → 逐卡 BlacklistClient.queryBlackList 查重（rpc 复用，BLACKLIST 域）
  → 未在黑名单 → BlacklistClient.addBlackList(BLACK_SOURCE=01 系统自动)
```

职责边界：聚合判断在 para-server（风控记录/规则/绑定全是 para 域表）；黑名单写入收口在
blacklist-server（addBlackList 幂等，insertIgnoreDuplicate + 操作日志 + 渠道通知）。

### 口径（默认配置，可 properties 覆盖）

| 配置键 | 默认 | 说明 |
|---|---|---|
| `risk.blacklist-sync.group-name` | `黑名单直拉规则组` | 按组名精确识别（组 ID 是环境相关值，不采用） |
| `risk.blacklist-sync.window-days` | `7` | 命中时间窗口（RISK_HIT_TIME ≥ sysdate-N 天） |
| `risk.blacklist-sync.max-add-per-round` | `50` | 单轮加黑上限，超出截断并 warn（自动化敏感动作保险丝） |

- 候选口径：窗口内「同卡 + 同规则」命中次数 ≥ 该规则 RISK_LIMIT_VALUE，CARD_ID 非空。
- 组不存在 / 组内无规则：不报错，返回成功 + 计数 0（空转，防未建组环境告警爆炸）。
- 已在黑名单（queryBlackList.inBlack）：跳过不调 add，避免 BLACKLIST_OPERATE_LOG 重复噪音。
- 加黑失败（非幂等类）：记 error 继续下一卡，汇总 failed 数。
- BLACK_SOURCE=01（系统自动）、BLACK_CAUSE=09（其他，逃票无专属码）、CREATE_BY=riskRuleBlacklistSync、
  REASON=`规则「名称」窗口期命中 N 次（黑名单直拉规则组自动加黑）`。

### 不变量

- 风控记录表（TBL_RISK_CONTROL_LOG）只读不改——审计表「只增不改不删」，本任务不碰 RISK_HANDLE_*。
- 幂等靠黑名单 CARD_ID 唯一键 + 查重前置双保险；任务可重复执行。
- model/rpc 变更均为纯增量（新 DTO 类 + ParaClient 新方法），按 memory §3 豁免条款最小范围
  重打包：仅 web-admin + para-server（rpc 本地 install）。

## 四、测试

- 单测：聚合口径（阈值边界/空组/CARD_ID 为空）、service 编排（mock mapper+BlacklistClient：
  查重跳过/加黑成功/失败继续）、task 响应处理。
- E2E：造数「同卡同规则 7 天内 ≥3 条命中」→ 触发 job → 黑名单新增（BLACKLIST+OPERATE_LOG），
  重复触发验证幂等（skipped，操作日志不重复）；组改名后空转验证。

## 五、风险与回滚

- 误拉风险：窗口/阈值口径错误会误伤正常乘客。保险丝 max-add-per-round + 黑名单页人工可解除
  （BLACKLIST_RELEASED 搬迁机制已备）。任务可 `UPDATE sys_job SET status='1'` 停用即回滚。
- 渠道通知：addBlackList 触发 deliverAddNotify（afterCommit），批量加黑会产生渠道同步流量，
  单轮 50 上限内可控。
