# IT-083 风险规则命中自动加黑定时任务（黑名单直拉规则组）

## 一、背景与目标

「黑名单直拉规则组」（现网 groupId=65，组名跨环境稳定）只收规则定义即「列入黑名单」的直拉规则：
000003 最大允许单边交易数（7 天 ≥3 次）、000002 出站规则（重复出站 ≥3 次）。
当前规则阈值已配（RISK_LIMIT_VALUE=3，用户 2026-11-19 裁定），但「命中 → 拉黑」无自动化链路，
全靠人工看风控记录后手工加黑。本任务补齐该链路。

## 二、方案

调度链完全沿用现有模式：

```
SYS_JOB(job_id=425, 0 5/10 * * * ?) → web-admin Quartz
  → riskRuleBlacklistSyncQuartzTask.sync()
  → ParaClient.riskRuleBlacklistSync()          (rpc 模块新增方法)
  → POST para-server /internal/risk/rule-blacklist-sync
  → para-server 聚合 TBL_RISK_CONTROL_LOG（本域表）
  → 逐卡 BlacklistClient.queryBlackList 查重（rpc 复用，BLACKLIST 域）
  → 未在黑名单 → BlacklistClient.addBlackList(BLACK_SOURCE=01 系统自动)
```

职责边界：聚合判断在 para-server（风控记录/规则/绑定全是 para 域表）；黑名单写入收口在
blacklist-server（addBlackList 幂等，insertIgnoreDuplicate + 操作日志 + 渠道通知）。

### 口径（默认配置，可 properties 覆盖）

| 配置键 | 默认 | 说明 |
|---|---|---|
| `risk.blacklist-sync.group-name` | `黑名单直拉规则组` | 按组名精确识别（组 ID 是环境相关值，不采用） |
| `risk.blacklist-sync.window-days` | `7` | 命中时间窗口（RISK_HIT_TIME ≥ sysdate-N 天） |
| `risk.blacklist-sync.max-add-per-round` | `50` | 单轮加黑上限，超出截断并 warn（自动化敏感动作保险丝） |

- 候选口径：窗口内「同卡 + 同规则」命中次数 ≥ 该规则 RISK_LIMIT_VALUE，CARD_ID 非空。
- 组不存在 / 组内无规则：不报错，返回成功 + 计数 0（空转，防未建组环境告警爆炸）。
- 已在黑名单（queryBlackList.inBlack）：跳过不调 add，避免 BLACKLIST_OPERATE_LOG 重复噪音。
- 加黑失败（非幂等类）：记 error 继续下一卡，汇总 failed 数。
- BLACK_SOURCE=01（系统自动）、BLACK_CAUSE=03（风控规则命中，2026-11-19 用户裁定新增码值，
  字典迁移 `docs/ops/environments/scripts/migration/20261119_black_cause_dict_risk_rule.sql`）、
  CREATE_BY=riskRuleBlacklistSync、
  REASON=`规则[<规则ID>]「名称」窗口期命中 N 次（黑名单直拉规则组自动加黑）`（含稳定规则ID，名称可改名）。

### 不变量

- 风控记录表（TBL_RISK_CONTROL_LOG）只读不改——审计表「只增不改不删」，本任务不碰 RISK_HANDLE_*。
- 幂等靠黑名单 CARD_ID 唯一键 + 查重前置双保险；任务可重复执行。
- model/rpc 变更均为纯增量（新 DTO 类 + ParaClient 新方法），按 memory §3 豁免条款最小范围
  重打包：仅 web-admin + para-server（rpc 本地 install）。

- 单测：`RiskRuleBlacklistSyncServiceImplTest` 4 例全绿（组缺失空转 / 组内无规则空转 /
  加黑-查重跳过-失败继续三分支含 DTO 断言 / 保险丝截断）。
- E2E（测试环境，2026-11-19）：
  1. 造数：CARD_ID=`E2E_BL_001` × 规则 000003 命中 3 条 + × 规则 000002 命中 3 条（窗口内）。
  2. 16:35 轮：candidates=0——造数落库晚于触发点，时序问题非缺陷；手工聚合 SQL 验证应出 2 候选。
  3. 16:45 轮：candidates=2、added=0、failed=2——暴露配置缺口：para-server 是 BlacklistClient
     首个消费方，`service.blacklist.url` 无配置，回落默认主机名 `blacklist-service`（k8s 无此
     Service，DNS 解析失败）。修复见 §五。
  4. 修复后（para-server 2.0.47）直连内部端点：第 1 次 added=1（000003 ADDED）+ skipped=1
     （000002 查重跳过）；第 2 次 added=0 + skipped=2——幂等验证通过。
  5. 16:55 Quartz 自然轮（全链路）：added=0、skipped=2、failed=0；SYS_JOB_LOG 3 条 STATUS=0。
  6. 库表核验：BLACKLIST 1 行（BLACK_SOURCE=01、BLACK_CAUSE=09、CREATE_BY=riskRuleBlacklistSync、
     REASON=`规则「最大允许单边交易数」窗口期命中 3 次（黑名单直拉规则组自动加黑）`、STATUS=ACTIVE）；
     BLACKLIST_OPERATE_LOG 1 条 ADD——查重跳过路径不产生操作日志，符合设计。
  7. E2E 数据已清理（6 条风控命中记录 + 黑名单行 + 操作日志行）。
- **口径补强复验（2026-11-19 17:15，para-server 2.0.48）**：按用户裁定，BLACK_CAUSE 改 03
  （风控规则命中，字典已迁移测试库并重启 web-admin 刷新缓存），REASON 补稳定规则ID。造数复验：
  BLACKLIST 行 BLACK_CAUSE=03、REASON=`规则[000003]「最大允许单边交易数」窗口期命中 3 次（黑名单直拉规则组自动加黑）`；
  二次触发 skipped=2 幂等依旧；E2E 数据已清理。单测断言同步收紧（cause=03 + REASON 含 [000003]）。

## 五、风险与回滚

- 误拉风险：窗口/阈值口径错误会误伤正常乘客。保险丝 max-add-per-round + 黑名单页人工可解除
  （BLACKLIST_RELEASED 搬迁机制已备）。任务可 `UPDATE sys_job SET status='1'` 停用即回滚。
- 渠道通知：addBlackList 触发 deliverAddNotify（afterCommit），批量加黑会产生渠道同步流量，
  单轮 50 上限内可控。
- **配置依赖（E2E 暴露）**：para-server 须配 `service.blacklist.url`，默认
  `http://blacklist-server-internal.itp.svc:8080`（已入 application.properties，与
  fep-alipay/pay-sign/alipay-pay-sign/fep-app 四服务同口径）。**红岛部署时 MUST 按 IT-016 模式
  注入 `SERVICE_BLACKLIST_URL` 环境变量指向 itpb 域黑名单服务**，否则回落测试域名直接不可达。
