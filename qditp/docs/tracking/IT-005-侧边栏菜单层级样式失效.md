# IT-005 综管台侧边栏：一级/二级菜单无字号与背景区分（`<style scoped>` 作用域不匹配，层级样式全为死代码）

> 本处理文档对应 `docs/tracking/问题清单.md` 索引表中 `IT-005` 一行。
> 流程：先在索引表加一行 → 再建本处理文档 → 处理完回填索引「状态 / 处理情况 / 更新」。

## 1. 背景 / 现象

- 发现时间：2026-10-15（业主提出界面优化需求时暴露）
- 发现渠道：用户反馈 —— 「界面优化：一级菜单字体与二级菜单字体作大小区分，与背景颜色」
- 影响范围：综管台（`web`）左侧主菜单的**全部层级视觉呈现**；不影响功能与数据。
- 现象描述：侧边栏一级菜单与二级菜单在**字号**与**背景色**上完全一致，看不出层级。源码 `Sidebar/index.vue` 里其实**已经写了**「一级 15px / 二级 13px + 不同底色」的规则，但界面毫无变化。

## 2. 根因分析

- **根因：Vue SFC `<style scoped>` 只给「本组件模板里渲染的元素」加作用域属性（`data-v-xxx`），
  `Sidebar/index.vue` 针对 `el-menu-item` / `el-sub-menu__title` 写的规则全部落入死代码。**
- 证据链（对编译产物取真值，非推断）：
  - `Sidebar/index.vue` 的作用域 id = `data-v-6ab258c6`（由 `.sidebar-container[data-v-6ab258c6]` 反证，`.sidebar-container` 在该组件模板内）；
  - 但编译后 CSS 里，`.el-menu-item` 实际携带的是 **`data-v-4d78b7c7`**（`SidebarItem.vue` 的 id）；
  - 而 `Sidebar/index.vue` 编译出的选择器是 `.sidebar-container .el-menu .nest-menu .el-menu-item[data-v-6ab258c6]`
    —— 要求 `el-menu-item` 带上 `6ab258c6`，实际却只有 `4d78b7c7` ⇒ **永不匹配**。
- `el-menu-item` / `el-sub-menu__title` 分别由 `SidebarItem.vue` 与 Element Plus 的模板渲染；
  `.scrollbar-wrapper` 是 `el-scrollbar` 的内部元素 —— 三者都不带 `Sidebar/index.vue` 的作用域属性。
- 附带发现（同一根因下的"幽灵规则"）：
  - `> .el-sub-menu > .el-sub-menu__title` 还多一层结构错误 —— `SidebarItem.vue` 的根节点是 `<div>`，
    `el-sub-menu` 并非 `.el-menu` 的直接子元素，子选择器本身也不可能命中；
  - 2026-10-15 早前 IT-001 修复的 `opacity()` 双参语法问题（改为 `v-bind(...) + opacity: 0.9`）
    同样落在这条死规则上 —— **语法正确、但从未生效**（该笔改动本身无实际视觉影响）。
- **真正生效的侧边栏样式在全局文件 `assets/styles/sidebar.scss`**（经 `index.scss` → `main.js` 全局引入，无作用域限制）：
  既有的 `.nest-menu` 背景、hover、min-width 规则都在那里 —— 这也反向印证了"全局才生效"这一判断（该文件里的 `.nest-menu` 规则实测生效）。

## 3. 方案对比

| 方案 | 思路 | 优点 | 缺点 | 风险 |
|------|------|------|------|------|
| 方案A | 把层级样式写进**全局** `assets/styles/sidebar.scss`，并清理 `index.vue` 中的死规则 | 与既有生效路径一致；一处定义、无二义；顺带清掉误导性死代码 | 需动两个文件 | 低 |
| 方案B | 在 `index.vue` 用 `:deep()` 打穿作用域 | 改动集中在一个文件 | 与项目既有 `sidebar.scss` 惯例不一致；`:deep()` 与 `teleported` 子菜单组合易产生新坑 | 中 |
| 方案C | 保持现状 | 零改动 | 需求不达 | 低 |

## 4. 决策与结论

- 选定方案：**方案A**。
- 决策理由：`sidebar.scss` 是侧边栏既有且**已被验证生效**的样式落点（`.nest-menu` 相关规则都在此），
  层级样式放这里无需 `:deep()`、不受作用域约束，且能消灭"规则写了却无效"的二义来源。
- 落地改动：
  1. `assets/styles/variables.module.scss`：新增 `$base-sub-menu-light-bg: #f0f1f5`
     （与既有暗色 `$base-sub-menu-background: #1f2d3d` 的角色一一对应）。
  2. `assets/styles/sidebar.scss`（`#app .sidebar-container` 内）新增层级规则：
     - 一级：`.el-sub-menu__title, .el-menu-item` → `font-size: 15px; font-weight: 600`，不额外铺色（= 侧边栏底色）；
     - 二级：`.nest-menu .el-sub-menu>.el-sub-menu__title, .nest-menu .el-menu-item` → `font-size: 13px; font-weight: 400; background-color: $base-sub-menu-light-bg`；
     - `html.dark` 兜底：暗色下 `sideTheme` 仍可能是 `theme-light`、底色走 `var(--sidebar-bg)`，
       故二级背景另行覆盖为 `var(--el-bg-color-overlay, #1d1e1f)`，避免「浅灰底压深色侧边栏」。
  3. `layout/components/Sidebar/index.vue`：删掉全部死规则（`el-menu-item` / `el-sub-menu__title` / `scrollbar-wrapper` 相关共 6 段），
     仅保留能命中本组件模板元素的 `.sidebar-container`（含 `v-bind(getMenuBackground)`）与 `.el-menu` 两条，
     并在 `<style scoped>` 顶部写明「NEVER 再把层级样式写回本块」。
- **补充改动（同日 16:13 追加，随 `1.2.34` 发布）—— 选中菜单项高亮**：
  被清理的 6 段死规则里，本来就有一条 `.el-menu-item.is-active { background-color: ... }`。
  清掉它之后，选中态只剩 Element Plus 的 `active-text-color`（文字变蓝）、**背景无任何高亮** ⇒
  等于把一个「看起来没生效」的失效规则直接删成「彻底没有」，属清收尾时 MUST 补齐的一环。故补充：
  - `sidebar.scss` 新增（`#app .sidebar-container` 内）：
    - 左侧 **3px 主色指示条**：`.el-menu-item` / `.el-sub-menu__title` 加 `:before`（`position:absolute`，不占布局），
      选中时置 `$menuActiveText`（`#409eff`）—— 三态通用，作为主要识别信号；
    - **底色淡蓝高亮**（带 `!important`）：一级 `rgba(64,158,255,0.10)`；二级本身已有灰底、取更浓一档 `0.16`；
      `theme-dark` / `html.dark` 再提一档 `0.22`（深色侧边栏上 0.10 几乎看不见）。
      加 `!important` 的原因：暗色主题的 `#1f2d3d` 与 `html.dark` 的覆盖规则都没带 `!important`，不加会被按权重压掉；
      `:before` 无同类冲突，故不加。
    - `position: relative` 对两个元素显式重申（Element 本身已设，重申只为让 `:before` 的定位前提自洽可读）。
  - 已知未覆盖：侧边栏**折叠态**下的浮层子菜单由 `el-sub-menu` 的 `teleported` 挂到 body，不在
    `.sidebar-container` 内，故该浮层仍为 Element 默认样式（不影响展开态）。
- 层级判据：`SidebarItem.vue` 把 `class="nest-menu"` 透传到「非顶层」子项的根元素（顶层项不带该类），
  故 `.nest-menu` 之内即二级及更深层 —— 不依赖易错的子选择器链。
- 影响范围 / 关联模块：仅 `web`（综管台前端样式）。后端、数据零改动。
- 附带修正一条既有认知：**`Sidebar/index.vue` 的 `<style scoped>` 对本目录内菜单 DOM 一律无效**，
  后续任何侧边栏菜单样式 MUST 改 `assets/styles/sidebar.scss`。
