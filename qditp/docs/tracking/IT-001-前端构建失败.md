# IT-001 综管台前端源码破损导致包构建长期失败（角色管理删字段未生效）

> 本处理文档对应 `docs/tracking/问题清单.md` 索引表中 `IT-001` 一行。

## 1. 背景 / 现象

- 发现时间：2026-10-15
- 发现渠道：用户要求「综管台管理-角色管理-新增角色界面删除『权限字符』与『角色顺序』项」（同一需求第二次提出，疑因界面上仍能看到这两项）
- 影响范围：`web`（综管台前端）整包**无法构建** ⇒ 2026-10-10 之后任何前端改动都发不出去；线上仍是 2026-10-09 构建的产物（Deployment `web`，`JAR_NAME=web-frontend-1.2.29.zip`）
- 现象描述：
  1. 综管台「角色管理 → 新增角色」对话框界面上仍显示「权限字符」「角色顺序」；
  2. 但源码 `web/src/views/system/role/index.vue` 里这两个字段**早已删除**；
  3. 本机 `npm run build:prod` / `npx vite build` 直接失败。

## 2. 根因分析

排查过程（本机实测）：

1. 对比源码与产物：源码对话框已无「权限字符」「角色顺序」，而产物 `web/dist/static/js/*.js` 中两者仍在 ⇒ 产物是**旧构建**，二者不一致。
2. 实跑 `npx vite build`，逐个暴露三处硬性编译失败（均与本次角色管理需求无关）：
   - `web/src/layout/components/Sidebar/index.vue`：`color: opacity(getMenuTextColor, 0.9)`。
     Dart Sass（`sass-embedded 1.89.1`，`package.json` 锁定版）的 `opacity()` 只接受 1 个参数，双参写法是旧 node-sass 的 `fade()` 别名；**SCSS 编译直接报错**。2026-10-10 提交 `0ebc521`（菜单样式优化）引入。
   - `web/src/views/system/user/index.vue`：`getList()` 函数头被改成孤立的 `function` + `getList().then(() => {`，原函数体被错位搬到后面，批量加载扣费信息块被夹在中间 ⇒ **JS 语法错误**（`Unexpected token, expected "{"`）。2026-10-10 提交 `e313f55`（用户管理优化）引入。
   - `web/src/views/system/role/index.vue`：`handleUpdate()` 中残留断句 `form.value.true, false)`（对话框 open 与菜单树勾选逻辑被毁）⇒ **JS 语法错误**。2026-10-09 删字段时残留；2026-10-12 的「残留清理」只修了数据权限对话框与 `rules`，漏了此处。

根因结论：同一批「前端页面优化」改动在**三处**改坏了源码（两处 JS 语法错、一处 SCSS 语法错），且此后从未成功构建过 ⇒ 前端交付物自 2026-10-09 起冻结，「删字段」这类改动自然一直不生效。

## 3. 方案对比

| 方案 | 思路 | 优点 | 缺点 | 风险 |
|------|------|------|------|------|
| 方案A | 按原语义逐处修复被改坏的函数/规则 | 改动最小、语义可对照 RuoYi 原版与文件内同类写法 | 需逐处确认还原语义 | 低 |
| 方案B | 回退这批提交（`0ebc521` / `e313f55`） | 一定可构建 | 丢掉用户管理扣费信息、菜单样式等有效改动 | 高 |
| 方案C | 只把报错行删掉 | 最快 | 丢语义（如 `getList()` 直接不可用） | 中 |

## 4. 决策与结论

- 选定方案：**方案A（逐处修复）**
- 决策理由：三处都是可明确还原的机械改坏，对照 RuoYi 原版与文件内其它同类写法即可确定正确形态，保留这批改动的有效部分。
- 具体改动（3 个文件）：
  - `web/src/views/system/role/index.vue`：`handleUpdate()` 还原为「写入 form → `open=true` → `nextTick` 逐项勾选菜单树」；`roleSort` 已随字段删除，不再做 `Number()` 转换。
  - `web/src/layout/components/Sidebar/index.vue`：改为 `color: v-bind(getMenuTextColor);` + `opacity: 0.9;`（保留原 0.9 淡化意图，写法符合 Dart Sass）。
  - `web/src/views/system/user/index.vue`：还原 `getList()` 函数结构，扣费信息批量加载放回 `listUser(...).then()` 回调内。
- 影响范围 / 关联模块：仅 `web`（综管台前端）；后端与其它模块零改动。

## 5. 验证与回滚

- 验证方式 / 结果（2026-10-15 本机实测）：
  1. 自写 babel 解析脚本扫 `web/src` 全部 **195** 个 `.vue`/`.js`，语法错误 **0**；
  2. `npx vite build` **exit=0**（`✓ built in 7.70s`）；
  3. 新产物「角色顺序」**全包 0 命中**；「权限字符」仅剩菜单管理页与分配用户页（本次范围外，属正常保留）；
  4. 角色页 chunk 的表单标签只剩 `角色名称 / 状态 / 菜单权限 / 备注`，表格列为 `角色编号 / 角色名称`。
  5. **测试环境端到端实测（2026-10-15 15:31，用户更新后）**：`172.20.211.23:30029`（综管台前端）——
     `index.html` 的 `last-modified` = `2026-10-15 07:29:14 GMT`（= 本机打包时刻 15:29）；
     线上 `index.html` 与本机 `web/dist/index.html` **完全一致**；入口 chunk `/static/js/index-C4OJeEWg.js` md5 与本地**一致**；
     角色页 chunk `/static/js/index-DGfLItc5.js` 与本地**逐字节一致**，内含「添加角色」且**不含「角色顺序」「权限字符」**；
     旧角色页 chunk `/static/js/index-YKpg565w.js` 返回 **404**（旧包已被整体替换）。
- 回滚预案：仅 3 个前端文件，`git checkout -- <文件>` 即回滚（注意：回滚后前端回到**不可构建**状态）。
