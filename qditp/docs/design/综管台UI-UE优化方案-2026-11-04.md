### B. 列表查询页统一模式（最高 ROI）

1. **时间范围显式化** → 新组件 `web/src/components/QueryTimeRange/index.vue`（全局注册名 `query-time-range`）：
   选择器 + `今天 / 近7天 / 近30天 / 全部` 快捷 chip + 一行「当前范围：11-04 00:00 ~ 11-04 10:43」。
   - **`全部` 不是所有页面都能给**：实测 `face-pay/orders`、`gate-txn-pay/offline-stats`、`gate-txn-pay`、`qrcode-txn-detail` 缺时间范围直接 `code=400`，这 5 个页面传 `:allow-all="false"`。
   - 手动只点日期时两端补 `00:00:00 ~ 23:59:59`（`default-time`）——不设的话 `datetimerange` 两端都取 `00:00:00`，「选今天」退化成零长度的瞬间，查出来永远空表。
2. **空状态分支** → 新组件 `web/src/components/EmptyState/index.vue`，实际落成**五支**（比原方案多两支，都是实施中发现会说谎的形态）：
   查询失败（可读原因 + 重试）/ **请先完善查询条件**（本地拦截、还没发请求时不能写成「查询失败」）/ 有筛选无匹配（清空筛选）/ 范围内无记录（**放宽到近 30 天**，按钮直接改写筛选）/ 暂无记录（`plain`，给没有时间概念的用）。
   「已生效筛选条件数」由组件自己从页面的 `filters` 对象里数（排除 `pageNum/pageSize/params/queryType/keyword`），页面不需要再写一个 computed。
3. **筛选回显 + 一键清空**：⚠️ **未做独立 tag 回显**——chip 的「当前范围」已覆盖最容易误判的那一维，其余条件各页已有表单回显；再加一层 tag 属重复信息。
4. **total 常显 / 防抖 / 骨架屏**：`total` 原本就随分页组件常显；防抖与骨架屏**未做**（查询是显式点按钮触发，不存在抖动；骨架屏与 `v-loading` 二选一，改动面大收益小）。

**接入范围**：22 个 `defaultTodayRange` 页面全部接入（`query-time-range` + `empty-state` + `.catch/.finally`），
另 `monitor/service-status`、`monitor/device-heartbeat` 两页接 `empty-state`（`plain`），合计 23 页有 `#empty` 引导。

### C. 首页 → 运营驾驶舱

`web/src/views/index.vue` 原为**空壳**（P8），本轮从零建：

- **系统健康条**（顶部）：`服务 up/total · 设备 online/total · 定时任务数`，任一不满即整条转红，每项可点进对应监控页。
- **今日动态**：当面付订单 / 日票订单 / 票卡交易 / 新注册（按票种合计）/ 日票退款记录，各带**昨日对比**（↑↓→）。
- **卡池余量水位**：按剩余占比升序，<10% 转红、<30% 转橙；分母是「该票种已发出卡号总量（可用+预占+已分配）」，**不是容量上限**（后端没有容量配置，页面上写明）。
- **业务规模**：线路 / 车站 / 生效参数版本 / 基础票价条目 / 密钥域版本 / 黑名单，全部可点下钻。
- **每个指标只落在一个已实测可用的列表端点上**，取它的 `total` 或后端已有的 `summary`，首页不新增聚合端点、不自算业务口径；
  单指标失败只影响自己（显示 `-` 并在页底汇总原因），**不把「-」伪装成 0**。
- **签约笔数不上首页**：没有全局计数端点（实测 `/page/pay-sign/channels` 返回 HTTP 200 + UUID 形态错误码 = 端点不存在），NEVER 用相近接口凑数。
