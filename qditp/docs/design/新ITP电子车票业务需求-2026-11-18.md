## 2. 范围与边界

**本需求包含**：6 页的字段/查询口径对齐、缺失页面补建（闸机异常交易 / 闸机交易）、逻辑卡号精确查询、扣款记录全量台账与补款状态写动作、密钥版本审批历史展示（仅元信息）。

**本需求不包含（明确划线）**：
- **任何密钥材料的页面展示、导出、迁移**——旧两页明文显示是历史缺陷，NEVER 照搬（AGENTS.md §4.2 安全红线）。
- 「新增密钥版本 / 写入密钥材料」——IT-061 已明确不做。
- 密钥下发/设备同步底层链路（key-server 已有）。
- 卡池批次申请/重试/ACC 文件处理（card-pool-server 已有，本需求只补"按卡精确查"视角）。
- 交易/支付链路本身（gate-txn-pay 的扣费、退款、超时费）。

## 3. 功能需求（FR）

### FR-1 地铁 CA 公钥管理（安全对位）

**FR-1.1 数据（目标：`METRO_CA_KEYSTORE`，沿用）**
- 只暴露版本元信息：密钥索引 `keyIdx`、版本号、状态、生效日期、接入方；
- **NEVER 在列表/详情/导出/接口响应中返回密钥值列**（旧 `keyPrivate` 字段在新侧永久不映射）。

**FR-1.2 接口**：沿用 `GET /page/key/versions` 的 CA 分组；不新增写端点；如要展示旧「更新密钥」动作的历史，只显示操作流水元信息（操作人/时间/版本号），不显示密钥值。

**FR-1.3 页面**：`views/trans/key/version` 保持只读元信息；查询条件与旧侧对齐（`keyIdx`/状态/生效日期），但去掉旧 `keyPrivate` 查询框（那是按密钥值反查，属高危能力）。

### FR-2 闸机公钥版本管理（审批历史补齐）

**FR-2.1 沿用现有**：`POST /page/key/agm-version/approval`（20010→20020/20030 白名单 + CAS，IT-061 已复核）；「设备密钥同步」监控页 `/monitor/device-key-sync`。

**FR-2.2 新增版本审批历史只读子表**：在新密钥版本页展示旧侧内嵌子表的语义——版本号、状态、审批备注、操作员、操作时间、审批状态；数据源为现有 key-server 审批流水表（若无则按 D1 决定是否新建**只存元信息**的历史表）。

**FR-2.3 安全**：同 FR-1，NEVER 显示密钥值；「新增版本」按钮明确不做（IT-061 裁定），页面可放置说明文案指向密钥管理流程。

### FR-3 逻辑卡号精确查询（🔴 台账视角缺失）

**FR-3.1 接口**（card-pool-server 新增只读端点）
- `GET /page/card-pools/cards`，参数：`channel`、`status`、`logicCardNo`、`msisdn`、`pageNum/pageSize`。
- 返回：渠道 / 逻辑卡号 / 状态 / 手机号（**脱敏**）/ 发卡时间 / 入库操作人 / 入库时间。
- 与现有 `/page/card-pools/summary`（9 票种余量）并存，不互相替代。

**FR-3.2 数据（决策 D2）**：默认**不迁旧 790,673 条**（含真实手机号，属生产规模敏感数据）；如业主裁定迁移，MUST 只迁卡号/状态/发卡时间/渠道/入库时间，**手机号列脱敏或留空**，且仅在测试环境导入，NEVER 外传。

**FR-3.3 页面**：`/monitor/card-pool` 增加「按卡查询」页签；手机号列默认脱敏展示（中间 4 位掩码），导出时保持脱敏或需二次权限确认（D2）。

**FR-3.4 性能**：79 万级数据按 `LOGIC_CARD_NO` / `MSISDN` 建索引；分页 MUST 服务端执行，NEVER 前端拉全量。

### FR-4 闸机异常交易页补建

**FR-4.1 数据源（先裁定 D3）**：旧页面 0 条，无法从数据反推承载表。默认按**新侧 `GATE_TXN_PAY` 中闸机处理结果异常的记录**实现（复用现有 `/page/gate-txn-pay` 查询服务，新增 `agException` 过滤），NEVER 凭旧表名 `metroMemberCardAgExcHist` 在新库找不存在的表。

**FR-4.2 查询条件（11-18 DOM 实读 10 项）**：`ticketLogicNum` 逻辑卡号、`tikcetTransSeq` 票卡交易序列号（旧拼写错误，**新参数用正确名 `ticketTransSeq`**）、交易类别（下拉）、`deviceId` 设备编码、处理车站（下拉）、闸机处理结果（下拉）、签约通道（下拉）、`startDate/endDate` 处理时间、`startRegDate/endRegDate` 注册时间。

**FR-4.3 列（9 列）**：逻辑卡号 / 交易序列 / 交易类别 / 设备编码 / 处理车站 / 闸机处理结果 / 处理时间 / 签约通道 / 注册时间。

**FR-4.4 导出**：旧页有「数据导出」→ 走 IT-056 异步导出框架，新增执行器与 `EXPORT_TYPE`，上限 20000 行。

### FR-5 扣款记录全量台账 + 补款状态编辑

**FR-5.1 查询能力补齐**：现有 `GET /page/gate-txn-pay` 的用户维度查询基础上，新增台账维度参数——`ticketLogicNum`（旧 `cardNum`）、`ticketTransSeq`（旧 `tikcetTransSeq`）、`merchantOrderNo`、`payTradeNo`、`discountAmount`、`orderDate`；保留现有 `cardId`/`thirdUserId`。

**FR-5.2 异常类型字典 7 值（🔴 与单边页 5 值不同）**

| 旧下拉值（11-18 实读） | 新侧处理 |
|---|---|
| 正常 | 新增枚举值 |
| 单边账(入站) / 单边账(出站) | 对应现有 1/2 |
| 单边入站(人工处理单) / 单边出站(人工处理单) | 对应现有 3/4，与交易管理需求 D4 同源 |
| **双段计费正常订单_行程超时** | 新增枚举；与超时处理 `overtime-handling.md` 的 `5` 语义**可能撞号**，MUST 先核对 |
| **进站免检** | 新增枚举 |

> 前端下拉文案用旧侧中文，value 与新枚举一一对应；**NEVER 把「正常/进站免检」当单边**（会错判退款口径）。

**FR-5.3 「编辑补款状态」写动作（决策 D4）**：旧列表有此操作（图标 `title="编辑补款状态"`），具体字段与状态迁移未取到（点击属写操作，本轮未点）。默认**不实现**，只登记；若 D4 裁定补建，另起 FR-5.3a：定义补款状态枚举 + `POST /page/gate-txn-pay/{orderNo}/supplement-status`，白名单 + CAS + 操作留痕。

**FR-5.4 导出**：旧「数据导出」→ 复用 IT-056 异步导出框架；13.6 万条 MUST 服务端分页 + 异步，NEVER 同步全量下载。

**FR-5.5 详情下钻**：复用现有 `debit-detail` 隐藏路由；旧详情字段（30+，见交易管理详情字段全集 §4.4）已覆盖，无需新页。

### FR-6 闸机交易管理页补建（决策 D5）

**FR-6.1 数据源**：旧 0 条，无法反推。默认按新侧 `GATE_TXN_PAY` 的闸机维度实现，复用现有查询服务，新增按 `deviceId`/`lineCode`/`stationCode`/`transactionType` 过滤（需现查表是否有对应列，见 D5）。

**FR-6.2 查询条件**：通知渠道 / 交易类别 / 通知票卡 / 上次票卡（4 个下拉，字典待补）+ `metroMemberCardNum` 逻辑卡号 + `startDate/endDate` 交易日期。

**FR-6.3 列（11 列）**：通知渠道 / 交易类别 / 通知票卡 / 上次票卡 / 逻辑卡号 / 交易序列 / 交易线路 / 交易车站 / 交易设备 / 交易金额 / 交易日期。

**FR-6.4 边界**：与 `/user-operation/txn-detail`（用户维度）并存，不合并——旧侧两者是不同菜单，维度不同。

## 4. 非功能需求（NFR）

- **NFR-1 安全红线（最高优先）**：CA/AGM 密钥值 NEVER 出现在前端页面、接口响应、导出文件、日志、需求文档与截图中；旧侧明文展示是历史缺陷，NEVER 对标补齐。密钥相关代码改动 MUST 提示人工安全合规复核（AGENTS.md §4.2）。
- **NFR-2 兼容性**：key-server 的 `/page/key/versions`、`/agm-version/approval`、`/device-sync/list` 与 card-pool-server 的 `/page/card-pools/*` 路径不变；gate-txn-pay 新增参数向后兼容（可空）。
- **NFR-3 个人信息**：手机号（msisdn）默认脱敏存储与展示；导出含手机号时需二次权限或脱敏（D2）；含真实卡号/手机号的旧数据仅测试环境使用，NEVER 外传。
- **NFR-4 Oracle 陷阱**：可空 MyBatis 参数 MUST 显式 `jdbcType`；NEVER `WHERE 1=1`（Druid 注入检测）；79 万/13.6 万级分页走索引，服务端执行。
- **NFR-5 序列化**：新增 DTO 放 `model`，Fastjson2；NEVER Jackson/Gson。
- **NFR-6 状态机**：补款状态若补建（D4），用枚举+迁移表+`canTransitTo`，配 `*WhitelistTest`，NEVER 散落 `if` 比状态字符串。
- **NFR-7 导出**：统一走 IT-056 异步导出框架，上限 20000 行；不新增同步下载链路。
- **NFR-8 审计**：所有新增写操作记操作人/时间/前后状态；密钥审批沿用 IT-061 审计口径；审计 IP 恒 `127.0.0.6`（IT-064）属基础设施层，本需求不处理但验收时标注。
