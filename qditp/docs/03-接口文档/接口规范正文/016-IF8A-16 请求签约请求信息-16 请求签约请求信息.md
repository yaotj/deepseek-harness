# IF8A-16 请求签约请求信息

> **接口编号**: IF8A-16
> **接口类型**: 请求类（APP 主动调用）
> **接口路径**: `/ci/app/requestSignInfo`
> **请求方式**: POST
> **消费端**: 地铁 APP
> **提供端**: pay-sign-server（支付签约服务）
> **源码位置**: `pay-sign-server/src/main/java/com/chinasofti/huateng/paysign/controller/ci/app/PaySignController.java`
> **整理时间**: 2026-07-28

---

## 一、接口功能

请求签约调用 SDK 所需的签名信息。APP 调用此接口获取支付平台 SDK 启动参数，用于拉起支付渠道签约页面。

**注意**：
- 地铁 APP 入口：`/ci/app/requestSignInfo`，固定签约渠道为 `METRO_APP`
- 支付宝出行入口：`/channel/addContract`，固定签约渠道为 `ALIPAY`，采用同步确认模式

---

## 二、请求参数

### 2.1 请求示例（地铁 APP）

```json
{
  "thirdUserId": "2088000123456789",
  "displayAccount": "13800138000",
  "payChannelCode": "03",
  "requestSignSeq": "SEQ123456789"
}
```

### 2.2 请求字段定义

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| thirdUserId | String | 是 | 第三方用户ID | `2088000123456789` |
| displayAccount | String | 是 | 显示账号（手机号/支付宝账号） | `13800138000` |
| payChannelCode | String | 是 | 支付渠道编码（03=支付宝，04=微信） | `03` |
| requestSignSeq | String | 是 | 签约流水号（请求号） | `SEQ123456789` |

### 2.3 字段校验规则

1. `thirdUserId` 不能为空
2. `displayAccount` 不能为空
3. `payChannelCode` 不能为空
4. `requestSignSeq` 不能为空
5. 同一 `thirdUserId` + `paymentVendor` 不能重复签约

## 三、响应参数

### 3.1 响应示例（地铁 APP）

```json
{
  "retCode": "0000",
  "retMsg": "成功",
  "requestStartSdkInfo": "{\"alipay\":{\"appId\":\"...\",\"pid\":\"...\"}}"
}
```

### 3.2 响应示例（支付宝出行-同步确认）

```json
{
  "retCode": "0000",
  "retMsg": "成功",
  "requestStartSdkInfo": null
}
```

### 3.3 响应字段定义

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| retCode | String | 是 | 返回码 | `0000` |
| retMsg | String | 是 | 返回消息 | `成功` |
| requestStartSdkInfo | String | 否 | SDK 启动参数（JSON），支付宝出行同步确认时为空 | `{"alipay":{...}}` |

### 3.4 错误码说明

| 错误码 | 含义 | 说明 |
|--------|------|------|
| 0000 | SUCCESS | 成功 |
| 9999 | FAIL | 系统异常 |
| 8001 | INVALID_PARAM | 参数无效 |
| 8002 | ALREADY_SIGNED | 该用户已签约此支付渠道 |

## 四、业务流程

### 4.1 地铁 APP 签约流程

**调用链路**：
```
APP
  → fep-app-server (/ci/app/requestSignInfo)
    → pay-sign-server (/ci/app/requestSignInfo)
      → PaySignServiceImpl.requestSignInfo()
        → 1. 参数校验
        → 2. 校验是否已签约（查询 APP_PAY_SIGN_INFO）
        → 3. 调用支付平台 contract 接口获取 SDK 参数
        → 4. 返回 SDK 参数
```

**业务逻辑**：

1. **参数校验** - 校验 `thirdUserId`、`displayAccount`、`payChannelCode`、`requestSignSeq` 是否为空
2. **重复签约检查** - 根据 `thirdUserId` 和 `paymentVendor` 查询 `APP_PAY_SIGN_INFO`，如果已签约直接返回错误
3. **调用支付平台** - 组装签约参数，调用支付平台 `/api/v1/contract/contract` 接口，获取 SDK 启动参数
4. **返回结果** - 返回 `requestStartSdkInfo`，包含支付宝/微信 SDK 参数，**不写入本地签约表**

**关键代码**：
```java
// PaySignController.java:21-26
@PostMapping("/requestSignInfo")
public RequestSignInfoResult requestSignInfo(@RequestBody RequestSignInfoReqDTO request) {
    log.info("接收到请求签约信息报文: {}", request);
    // 地铁APP专属入口，固定签约渠道为 METRO_APP
    return paySignService.requestSignInfo(request, SignChannelEnum.METRO_APP.getCode());
}
```

### 4.2 支付宝出行签约流程（同步确认）

**调用链路**：
```
支付宝 APP
  → fep-alipay-server (/channel/addContract)
    → pay-sign-server (/channel/addContract)
      → PaySignServiceImpl.alipayTripRequestSignInfo()
        → 1. 参数校验
        → 2. 校验是否已签约
        → 3. 同步确认：直接写入签约主表
        → 4. 写入流水表
        → 5. 返回成功
```

**业务逻辑**：

1. **参数校验** - 校验 `thirdUserId`、`channel`、`agreementCode`、`channelUserAccount` 是否为空
2. **重复签约检查** - 根据 `thirdUserId` 和 `paymentVendor` 查询 `APP_PAY_SIGN_INFO`
3. **同步确认签约** - 直接写入 `APP_PAY_SIGN_INFO` 表，状态为 `SIGNED`，**不调用支付平台**
4. **写入流水表** - 记录 `ALIPAY_TRIP_REQUEST_SIGN_INFO` 操作流水
5. **返回结果** - 返回成功，不返回 SDK 参数

**关键代码**：
```java
// PaySignAlipayTripController.java:63-68
@PostMapping("/addContract")
public RequestSignInfoResult addContract(@RequestBody AlipayTripAddContractReqDTO request) {
    log.info("接收到支付宝添加签约信息报文: {}", request);
    // 支付宝出行专属入口，固定签约渠道为 ALIPAY
    return paySignService.alipayTripRequestSignInfo(request);
}
```

## 五、数据模型

### 5.1 APP_PAY_SIGN_INFO（签约主表）

支付宝出行签约成功后写入此表。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| REQUEST_SIGN_SEQ | VARCHAR2(128) | 签约流水号（主键）= 支付宝 agreementCode |
| THIRD_USER_ID | VARCHAR2(128) | 第三方用户ID |
| SIGN_STATUS | VARCHAR2(32) | 签约状态：SIGNED |
| SIGN_CHANNEL | VARCHAR2(32) | 签约渠道：ALIPAY |
| PAYMENT_VENDOR | VARCHAR2(32) | 支付渠道：05（支付宝出行） |
| CARD_ID | VARCHAR2(128) | 卡ID |
| CARD_TYPE | VARCHAR2(64) | 卡类型 |
| PAY_ACCOUNT_ID | VARCHAR2(128) | 支付账号ID |
| PAY_AGREEMENT_NO | VARCHAR2(256) | 支付协议号 |
| DISPLAY_ACCOUNT | VARCHAR2(256) | 显示账号（支付宝用户ID） |
| SIGN_TIME | TIMESTAMP | 签约时间 |
| TERMINATION_TIME | TIMESTAMP | 解约时间 |

## 八、注意事项

1. **地铁 APP 签约**：异步模式，返回 SDK 参数，由 APP 端拉起签约页面
2. **支付宝出行签约**：同步确认模式，直接写入签约表，返回成功
3. **重复签约检查**：同一 `thirdUserId` + `paymentVendor` 只能签约一次
4. **签约状态**：支付宝出行签约成功后状态为 `SIGNED`，无需后续回调确认
5. **流水记录**：所有签约操作都会记录到 `APP_PAY_SIGN_REQUEST` 流水表
