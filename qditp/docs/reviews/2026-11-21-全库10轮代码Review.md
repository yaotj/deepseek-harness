## 第 2 轮 · 事务与并发幂等

**[中→已降级·仅报告] 事务内远程支付预下单 + 吞异常**
- `collect-ticket-server/.../service/impl/TicketCollectServiceImpl.java:111`：`requestPaymentInfo` 标 `@Transactional(rollbackFor=Exception.class)`，第 148 行同步远程 `collectPayClient.requestPayForJson(...)`，第 158 行才落本地库，第 167-172 行 `catch(Exception)` 仅打日志后 return → 长事务 + 异常吞掉照常提交，可能留"支付中"脏状态。
- 改法：远程调用移出事务边界；失败路径显式 `setRollbackOnly()` 或抛出。
- **2026-11-22 更新**：模块已归档（从未部署、无流量），此项为死代码风险，严重度由「中」降为「低」，无需人工复核。

**[中][需人工复核·仅报告] 签约回调事务吞异常**
- `pay-sign-server/.../service/impl/SignResultCallbackHandler.java:52`：`receiveSignResult` 事务内第 94 行 insert 签约信息、第 102 行写审计、第 104 行同步 `publishEvent`；第 113-118 行 catch 仅 log + fillError 后 return → 不回滚，签约行/审计/事件可能不一致。
- 改法：catch 显式抛异常或 `setRollbackOnly()`；事件改 `@TransactionalEventListener(AFTER_COMMIT)`。**资金链路，未改。**

- 未发现成片问题：整体幂等普遍用"唯一索引 + DuplicateKeyException"，状态机普遍枚举 + `canTransitTo/isTerminal` 白名单，`@Scheduled` 重试带 CAS + 退避。

## 第 3 轮 · 安全与敏感信息

**[严重→已降级·仅报告] 支付回调验签 fail-open**
- `collect-ticket-server/.../util/PaySignUtils.java:52-54`：`paycenterPublicKey` 为空（`@Value` 默认空串，第 25 行）时 `log.warn` 后 `return true`。该 `verify()` 是支付结果通知 `verifyPayNotifySign()` 的校验入口（`TicketCollectServiceImpl.java:408` 作为放行条件）。若公钥未注入，任何伪造的成功回调都能通过验签推进"已支付" → 资损。**核验状态：已逐行确认属实。**
- **2026-11-22 更新**：该模块从未部署、无流量，源码已整体归档到 `archive/abandonedservices/collect-ticket-server`，根 pom 已移除。此项为**死代码风险，无线上资损暴露**，严重度由「严重」降为「低」，无需人工复核。保留记录仅供归档代码追溯。
- 改法：公钥为空视为配置错误，启动期 fail-fast 或 `verify()` 直接 `return false`（fail-closed）。**支付验签红线，未改，务必人工复核并核查各环境公钥注入情况。**

**[严重][需人工复核·仅报告] SM2 密钥生成失败分支打印完整私钥/公钥坐标**
- `acc-security-server/.../util/sm2/SM2.java:313`：`x[0]` 或 `y[0]` 为 `0x00`（约 1/256 概率）时 `log.warn` 打印 `d`（私钥标量）/`x`/`y` 十六进制。该方法被 `SM2SMUtil.java:60` 生产调用，日志落 PVC `app-logs-v2`。**核验状态：已逐行确认属实。**
- 改法：删除 d/x/y 明文，仅留非敏感定位信息。**密钥红线，未改，需人工复核密钥用途与日志留存范围。**

- SQL 注入未发现：mapper `${}` 仅见代码生成器 `${sql}` 与 RuoYi `${params.dataScope}`，未见拼接用户输入。
