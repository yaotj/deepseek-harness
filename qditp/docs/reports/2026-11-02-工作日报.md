## 一、今日完成工作

**1. 微基线对齐变更全量发版测试环境（23 个服务）**
把 10-27 完成的 micro 公共组件对齐成果（JVM 诊断端点、Prometheus 指标自愈、Tomcat 最大连接数对齐、内建文档）应用到测试环境并逐一验证。每个服务均完成：版本号末位 +1 → 本机构建 jar → 推 Harbor → 滚动发版 → **Pod 内 `/app.jar` 的 md5 与本地构建逐字节比对**（避开 containerd imageID 是 config digest 的不可比陷阱）→ 健康检查。最终 **23/23 服务全部健康 UP**（face-pay-server 于下午补发 1.0.89，见第 4 节）。

**2. 发版现场排掉四颗地雷（详见问题清单 IT-040 更正 / IT-036 / IT-037）**
- **数据库默认地址陷阱（IT-036）**：10-20 的提交把 23 个模块的数据库默认值改成了红岛地址，而测试环境 15 个应用只配了"点号风格"的环境变量、没配下划线占位符环境变量——新程序包一上就当静默连接红岛库，启动卡死且因无就绪探针而"假就绪"。已为 15 个应用补注 4 项 `DB_*` 环境变量（对齐 para-server 的双通道模式）全部恢复。
- **端口错位拉锯（IT-040 更正）**：4 个应用的部署配置里用环境变量钉着旧端口（9100/9111/9112/9113），与改过的服务端口 8080 冲突，谁后改谁生效、服务反复黑洞。已把线上环境与仓库部署 YAML（11 个文件）统一对齐到 8080，以后再套 YAML 不会再被改回。
- **镜像名与目录名不一致（IT-037）**：打包脚本的名称映射表因服务器 bash 版本过旧从未生效，6 个服务按目录名推会推错镜像仓库。本次发版已按正确镜像名绕行推送，脚本层修复已登记待办。
- **打包即炸的 YAML 重复键**：collect-pay 的配置文件有两个同名顶层键，新程序包启动即退出（Python 的 YAML 检查查不出这类问题，Java 严格解析才炸）。已合并重复块、重出 1.1.92 并复验健康。

**3. 发版后功能验证**
- 22 个服务 `/monitor/health` 全通；`/monitor/getObjectCountTop`（POST + JSON 体）实测返回 JVM 对象 TopN，诊断端点可用。
- 多个服务 `/actuator/prometheus` 确认自定义监控指标（`web_mvc_timeout_cnt_total`、`web_running_total`、`web_running_max_cnt`）在线——此前"凌晨清理任务误杀指标"的缺陷修复已随发版生效。
