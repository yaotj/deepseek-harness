### 2.1 `QRCODE_STATUS.CODE_STATUS` —— 13 个取值，全部来自 `model/.../ticket/enums/QRCodeStatusEnum.java:13~49`

| 取值 | 枚举名 | 含义 |

| `05` | `EXIT` | 已出站 |
| `06` | `EXIT_OVERTIME` | 超时出站 |

- `03 → 04 / FF / 81`

- `05 → 04 / FF / 81`、`06 → 04 / FF / 81`、`02 → 04 / 81`
- `08 → 04 / 05 / 06 / 81`、`09 → 04 / 05 / 06 / 81`

### 2.2 目标状态怎么推导出来 —— `GateCodeStatusResolver`

`resolveCodeStatus(trxType, excessFareType, adviceOpt)`（`ticket-server/.../gate/GateCodeStatusResolver.java:71`），**三级优先级，顺序即优先级**（`:61-64`）：

1. `adviceOpt`（IF5A-03 BOM 建议操作）→ `ADVICE_OPT_TABLE`（`:23-27`）
   - `SUPPLEMENT_ENTRY` → `04`
   - `FREE_UPDATE_020`、`FREE_UPDATE` → `08`
   - `PAID_UPDATE` → `09`
2. `excessFareType`（IF8A-04 APP 自助补站类型）→ `EXCESS_FARE_TYPE_TABLE`（`:30-32`）
   - `TrxTypeCodeEnum.ENTRY`（`01`）→ **`81`** 补进站
   - `TrxTypeCodeEnum.EXIT`（`02`）→ **`80`** 补出站
3. `trxType`（闸机交易类型）→ `TRX_TYPE_TABLE`（`:35-40`）
   - `01` → `04`、`02` → `05`、`03`（`EXIT_OVERTIME`）→ `06`、`ENTRY_FAIL` → `FF`、`ABNORMAL` → `70`

三级都没命中 → 兜底 `ticket.default-code-status`，**默认 `03`**（`:67`），并打一条 WARN「IF1A-01 状态码解析未匹配任何规则」（`:93`）。

### 2.3 日票 / 多日计次票在检票链路里的分支 —— `GateDailyTicketCoordinator`

- **进站**：`checkEntryAllowed`（`ticket-server/.../gate/GateDailyTicketCoordinator.java:103`）。
  只有 `TrxTypeCodeEnum.isEntryTxn(trxType)` **且** `CardTypeCodeEnum.isDailyTicket(resolvedCardType)` 才走（`:105-108`），否则直接放行。
  调 `dailyTicketClient.entryCheck(cardId)`（`:111`）；被拒时把 `retCode` 置成 `TicketErrorCodeEnum.QR_CODE_NOT_FOUND`、`retMsg` 用下游原文（`:114-115`），返回 `false` 终止检票。
- **出站扣次**：`markUsedOnExit`（`:124`）。⚠️ **`trxType` 用的是精确等值 `TrxTypeCodeEnum.EXIT.getCode()`（`:125`）**，只认 `"02"`。
  调 `dailyTicketClient.markUsed(cardId, null, null, lastHandleStationCode, handleStationCode)`（`:131-135`）；
  `technicalFailure()` 直接 return（`:136`）、业务拒绝只打 ERROR 后 return（`:139-143`）；
  成功后才发 §3.63 通知 `appNotifyService.notifyCountingTicketTimes(request, DAILY_TICKET_TIMES_PER_TRIP)`（`:146`）。
- **应答字段**：`countingTimes` 由 `resolveCountingTimes`（`:150`）给（日票卡种 = `DAILY_TICKET_TIMES_PER_TRIP`，否则常量 `COUNTING_TIMES_NOT_DAILY_TICKET`）；`countingFlag` 由 `resolveCountingFlag`（`:156`）给；票号由 `applyDailyTicketFields`（`:162`）查 `queryDailyTicketInfo` 后写入 `response.ticketCode`（`:177`），查失败只 WARN、不翻检票结果（`:172-174`）。

### 2.6 超时（与本目录 Test_011 / 024 直接相关）

**唯一入口是 `docs/business/overtime-handling.md`，接这类用例 MUST 先读它。** 四条不可回退的事实（`AGENTS.md` §2.2.2）：

1. 甲方唯一可执行的超时条款只覆盖**多日计次票**；TS9 与 R6 里 `超时费` / `逾站` / `在站时间` 全部零命中；`overtimeAmount` 出现在 **AGM → ITP** 的上送报文里 ⇒ **规格中不存在「要求 ITP 计算超时费」的条款**（离线码是唯一例外）。

3. 「线网最高票价」全仓 grep 零命中，para-server 无此参数也无 RPC 方法。
4. `ITP.EXP` 第 11 段「订单异常类型」与 IF8A-05 那套 `0`~`5` 撞号，规格自身两套编码。

## 五、日志判据速查

| 想确认什么 | 服务 | 搜什么 |
|---|---|---|
| IF1A-01 收到了、状态怎么解析的 | ticket-server | `IF1A-01 解析状态码`、`IF1A-01 状态码解析结果`、`IF1A-01 状态码解析未匹配任何规则`（`GateCodeStatusResolver.java:72 / 83 / 93`） |
| 日票进站是否被拒 | ticket-server | `IF1A-01 日票进站校验通过` / `IF1A-01 日票进站校验拒绝`（`GateDailyTicketCoordinator.java:118 / 113`） |
| 出站扣次成功没有 | ticket-server | `IF1A-01 日票出站处理完成` / `IF1A-01 日票出站标记被拒`（`:145 / :140`） |
| 返回给闸机的字段 | ticket-server | `IF1A-01 返回 ticketResponse 字段`（`GateResponseAssembler.java:59`） |
| 转给扣费的字段 | ticket-server | `IF1A-01 扣费请求关键字段`（`GateTxnPayRequestAssembler.java:37`） |
| 扣费订单快照 | gate-txn-pay-server | `IF1A-01 构建 GateTxnPay 订单快照`（`GateTxnPayServiceImpl.java:261`） |
| 真实卡类型查询失败（会导致签约信息 / companionFlag 缺失） | ticket-server | `IF1A-01 查询真实卡类型异常`（`GateCardTypeEnricher.java:122`） |

看日志 MUST 走 `scripts/klog.sh <服务名> [关键字] [行数]`（`AGENTS.md` §8），本机 `kubectl logs` 必然失败。
**按 traceId 检索前先确认目标模块开了 tracing**：`ticket-server` / `fep-dev-server` / `fep-app-server` / `industry-data-server` / `blacklist-server` **都不在**那 8 个已开名单里（`AGENTS.md` §2.2.1），它们的 `%X{traceId}` 恒为空。
