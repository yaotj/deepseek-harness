## 三、实证结论

### E1 ⚠️⚠️ 真缺陷（P0，比 `05` A2 记的范围大得多）：`resolvedCardType` 取的是**签约渠道**，不是卡类型 ⇒ IF1A-01 的整条日票 / 计次票分支从未生效

**代码定位（唯一一行）**：
```java
// ticket-server/.../gate/GateTicketHandler.java:92
String resolvedCardType = CardTypeMapping.toIssueCardType(request.getSignChannelCode());
```
`getSignChannelCode()` 是**签约渠道编码**（本轮上送 `03`）。`CardTypeMapping.toIssueCardType("03")`：
`03` 既不在 `ISSUE_CARD_TYPES`、`CardPoolTicketType.fromAccTicketType("03")` 也不命中
⇒ 走 `CardTypeMapping.java:61` 的兜底 `return normalized`，**原样返回 `"03"`**。
而 `CardTypeCodeEnum.isDailyTicket("03")` = **false**（`CardTypeCodeEnum.java:79-86` 只认 `0445`/`0446`/`0447`/`0448`）。

该变量被喂给**三处**：
- `GateTicketHandler.java:94` → `checkEntryAllowed(..., resolvedCardType)` ⇒ **日票进站校验恒跳过**
- `GateTicketHandler.java:116` → `markUsedOnExit(request, resolvedCardType)` ⇒ **出站扣次恒跳过**（与 `trxType` 是 `02` 还是 `03` **无关**）
- `GateTicketHandler.java:121` → `fillSuccessResponse(..., resolvedCardType)` ⇒ `countingTimes` / `countingFlag` / `ticketCode` 恒取「非日票」分支

**实测证据（同一笔交易内的自相矛盾，这是最硬的一条）**：
- `GateCardTypeEnricher.applyFreeRideAmountReset` 打出 `IF1A-01 免扣费, cardType=0445` ⇒ 它用的 `actualCardType` 是 **`0445`**，`isDailyTicket` 为 **true**
- 同一笔的应答里 `countingTimes=0` / `countingFlag=N` / `ticketCode=null` ⇒ coordinator / responseAssembler 侧 `isDailyTicket` 为 **false**
- 两个判断在同一次请求里结论相反 ⇒ 两者拿的**不是同一个变量**：前者是 enricher 查 account 得到的真实卡种，后者是 `:92` 用 `signChannelCode` 算出来的 `"03"`

**库侧证据**：日票实例 `ACTUAL_TIMES` / `TRANS_SEQ` / `FIRST_USE_TIME` / `TICKET_STATUS` / `UPDATE_TIME` **一次进站 + 一次出站后全部零变化**，`DAILY_TICKET_USAGE_LOG` 0 行；
**链路证据**：两笔请求的日志里对 `daily-ticket-server`（30027）**零次 RPC**。

**与 `AGENTS.md` §2.2.2 / `05` A2 的关系 —— 必须更正**：
那条 P0 记的是「`GateDailyTicketCoordinator.java:125` 精确等值只认 `02`，所以 `trxType=03` 不扣次」。
`:125` 那个精确等值**确实存在**（代码没变），但它**根本轮不到生效** —— 因为 `:126` 的 `isDailyTicket(resolvedCardType)` 已经先返回 false。
**本轮用 `trxType=02` 打的一笔同样一次都没扣。** 所以：
- 原 P0 的**结论方向是对的**（计次票会免费乘车），但**成因与范围都记小了**：不是「只有超时出站漏」，而是**全部出站都漏**；
- 修 `:125` 那个等值**不能修好这条链路**，必须先修 `:92`。

⚠️ **本目录不裁决怎么修**（改 `:92` 用 `request.getCardType()`？还是在 enricher 之后重取？涉及调用顺序 —— `:94` 的 `checkEntryAllowed` 在 `:99` 的 `applyActualCardType` **之前**，此刻 `request.getCardType()` 还是闸机上送值），交开发定。

## 五、没验到的项与原因（逐条，不含糊）
