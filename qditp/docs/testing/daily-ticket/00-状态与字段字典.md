# 状态与字段字典

取值均来自代码字面量与生产库实际数据（2026-09-09 抽样 36 单订单 / 9 条实例 / 7 条退款单）。项目多数模块用 String 字面量而非枚举，改动前必须全局 grep。

## DAILY_TICKET_ORDER

`ORDER_STATUS` × `PAY_STATUS` 实测组合（其余组合未出现，不代表不合法）：

- `CREATED` + `INIT` — 下单后未支付。**库里 29/36 条是这个状态**，说明未支付订单不会自动过期或取消
- `PAYING` + `PAYING` — 已发起支付、等回调
- `PAID` + `PAID` — 支付成功终态
- `REFUNDING` + `PAID` — 退款中
- `REFUNDED` + `PAID` — 已退款。注意 **`PAY_STATUS` 退款后不回滚**，判断"是否已退款"只能看 `ORDER_STATUS`
- `PAY_FAILED` + `FAIL` — 代码里有（`DailyTicketServiceImpl.java:143`），库中暂无样本

支付发起的状态流转用**白名单 + 乐观锁**，实测 SQL：

```
update DAILY_TICKET_ORDER set ... ORDER_STATUS='PAYING', PAY_STATUS='PAYING'
where ORDER_NO=? and ((ORDER_STATUS='CREATED' and PAY_STATUS='INIT')
                   or (ORDER_STATUS='PAYING' and PAY_STATUS='PAYING'))
```

`affectedRows=0` 时返回 `订单状态已变更，请查询支付结果`（`DailyTicketServiceImpl.java:157`）。

关键字段：

- `TICKET_PRICE` / `PAY_AMOUNT` — 单位**分**。`PAY_AMOUNT` 下单时为 null，回调成功才写入
- `PAY_SCENE` — 由 `channelType` 映射：`1`→`app`，`2`→`wap`（`resolveScene`）
- `PAY_CHANNEL_CODE` — `03` 支付宝（主用）、`04` 有历史样本
- `CARD_TYPE` / `SHOW_TYPE` — 实测组合 `45/12`（一日票）、`46/13`（三日票）、`48/15` 与 `48/51,52,53,55`（单次票 / 臻宝游青岛系列）
- `THIRD_USER_ID` — **下单时为 null，支付时才回填**；`USER_ID` 下单即写入。两者取值相同（如 `00522949`）
- `TRADE_NO` / `PAYMENT_ORDER_NO` — 回调时都写网关 `orderNo`（实测同值，如 `287539830177300480`）

## DAILY_TICKET_INSTANCE

- `TICKET_STATUS` — `ACTIVATED`（激活未用）、`USED`（已首次使用）。库中仅这两种
- `ACC_NOTICE_STATUS` — `INIT`（未通知 ACC）、`SUCCESS`。**`ACTIVATED` 的 4 条全是 `INIT`**，通知 ACC 只在首次使用后触发
- `ACTUAL_TIMES` — 一日/三日票为 **`-99`**（不限次的哨兵值），单次票为 `1`
- `PERIOD` — 有效天数，一日票 1、三日票 3
- `CARD_NUM` — 逻辑卡号，16 位，来自 card-pool-server 预占
- `CARD_ISSUE` 恒为 `5412`，`CODE_TICKET_TYPE` 恒为 `0441`（抽样内无例外）
- `COUNTING_START` / `COUNTING_END` — **13 位毫秒时间戳的数值列，不是日期类型**，写用例断言时别当 DATE 比较
- `TICKET_CODE` — 19 位数字串，与订单号无关系

## DAILY_TICKET_REFUND

- `REFUND_STATUS` — `WAIT_VERIFY`（待核验，已激活票）、`REFUNDING`、`REFUNDED`
- `REFUND_TYPE` — `00` 未激活直退、`01` 已激活需核验
- `VERIFY_AFTER_TIME` — 仅 `REFUND_TYPE=01` 有值，实测为创建时间 +5 天
- `REFUND_ORDER_NO` — 格式 `RF` + 时间戳 + 订单尾号；**早期 4 条为 null**（`WAIT_VERIFY` 阶段尚未生成）
- `PLATFORM_REFUND_NO` — 抽样 7 条**全为 null**，含已 `REFUNDED` 的那条

## DAILY_TICKET_PAY_LOG

`BIZ_TYPE` 实测出现 `PAY`、`CALLBACK`。`RESULT_CODE` / `RESULT_MSG` 在 `PAY` 行为 `0` / `成功`，**在 `CALLBACK` 行为 null**（见 03 页 D-003）。
