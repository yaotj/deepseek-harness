## DailyTicket_Test_009 日票激活

**接口** `/app/dailyTicket/updateTicket`（if8a_67，`AppDailyTicketController.java:80`）

**前置** 订单 `PAID/PAID`，且 `DAILY_TICKET_INSTANCE` 中该订单尚无行

**预期**（`DailyTicketServiceImpl.java:484` 起）
- 向 card-pool-server 预占逻辑卡号 → 落 `DAILY_TICKET_INSTANCE` → 确认预占，三步顺序不可颠倒
- 实例行：`TICKET_STATUS=ACTIVATED`、`ACC_NOTICE_STATUS=INIT`、`CARD_NUM` 16 位、`ACTIVATE_TIME` 非空、`FIRST_USE_TIME` / `COUNTING_END` / `ACC_NOTICE_TIME` 均为 null
- `PERIOD` 与票种一致（一日票 1、三日票 3）；`ACTUAL_TIMES` 一日/三日票为 `-99`、单次票为 `1`
- `COUNTING_START` 是 13 位毫秒时间戳数值

**卡池异常分支**（`DailyTicketServiceImpl.java:578` 起，需人为造场景）
- 池空 → `逻辑卡号池暂无可用卡号，请稍后重试`（WARN 日志）
- 票种被拒 → `票种配置错误，无法发卡`（ERROR 日志，属配置或程序缺陷）
- 远端故障 → `发卡服务暂不可用，请稍后重试`

**关注点** 实例落库后若确认预占失败，代码**故意不归还卡号**（`:546` 注释），靠 card-pool 预占超时回收兜底。断言时不要期望卡号被释放。

**结果** 未执行（2026-09-09 测试只到支付成功）。

## DailyTicket_Test_014 退款幂等与前置校验

三个子场景，都在生成退款单之前拦截（`DailyTicketServiceImpl.java:256-269`）：

- **重复退款**：同一订单第二次调退款 → 返回已有退款单的处理结果，`DAILY_TICKET_REFUND` 仍只有 1 行
- **未支付订单退款**：订单 `CREATED/INIT` → `订单未支付成功，不允许退款`
- **缺原支付订单号**：`PAYMENT_ORDER_NO` 为空时会先主动查一次网关刷新，仍为空则 `原支付订单号缺失，不允许退款`

**结果** 未执行。
