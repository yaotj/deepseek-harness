# B17 审计 IP 恒 127.0.0.6 · 根因诊断（2026-11-06）

## 现象

综管台「操作员监控 / 操作日志」页 IP 列恒显示 `127.0.0.6`，误导运维以为是本机操作。

## 链路还原（实测）

```
用户浏览器
   │  真实 IP（如 10.x.x.x）
   ▼
外部负载均衡 / Istio Ingress
   │
   ▼
nginx Pod（K8s 内，注入 istio-proxy sidecar）
   │  $remote_addr = sidecar 地址（127.0.0.6）
   │  proxy_set_header X-real-ip $remote_addr        ← 写死 sidecar 地址
   │  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for
   ▼
web-admin Pod（K8s 内，注入 istio-proxy sidecar）
   │  应用拿到的 request.getRemoteAddr() = sidecar 地址
   │  request.getHeader("x-real-ip")     = 127.0.0.6（实测日志确认）
   ▼
LogAspect.java:96 → IpUtils.getIpAddr(request)
   │  优先读 x-forwarded-for，但链里第一个就是 sidecar 地址
   ▼
SYS_OPER_LOG.OPER_IP = 127.0.0.6
```

## 实测证据

1. `MoreInterceptor.logRequest()`（`resource/micro/web/.../MoreInterceptor.java:103-104`）：
   ```java
   String ip = request.getRemoteAddr();          // 127.0.0.6
   String realIp = request.getHeader("x-real-ip"); // 127.0.0.6
   ```
   web-admin 日志实测：`client=127.0.0.6 real-client=127.0.0.6`（10/10 条一致）。

2. `LogAspect.java:96` 已调用 `IpUtils.getIpAddr(request)`（`web-server/web-framework/.../LogAspect.java`），
   而 `IpUtils` 优先读 `x-forwarded-for` 并取第一个 IP——但链里第一个就是 sidecar 地址，
   所以**后端代码逻辑正确，但输入数据本身就是错的**。

3. `nginx.conf` 每个 location 都设了 `proxy_set_header X-real-ip $remote_addr`，
   而 nginx 自己的 `$remote_addr` 是它的 sidecar 地址（nginx 也跑在 Pod 里）。

## 根因

**nginx 与 web-admin 都在 K8s Pod 内且都注入了 istio-proxy sidecar**，
真实用户 IP 在更外层（外部负载均衡 / Istio Ingress）就被 sidecar 覆盖，
nginx 拿到的 `$remote_addr` 已是 sidecar 地址，再传给 web-admin 时已经是脏值。

## 修复方向（基础设施层，非后端代码）

| 方案 | 改动 | 影响面 |
|---|---|---|
| A. nginx 从 XFF 最左取真实 IP | 改 `nginx.conf`：`set_real_ip_from` + `real_ip_header X-Forwarded-For` + `real_ip_recursive on` | 仅 nginx Pod 配置 |
| B. Istio Ingress 层配 `externalTrafficPolicy: Local` | 改 Istio Ingress Gateway 配置 | 集群级 |
| C. sidecar 配置 `holdApplicationUntilProxyStarts` + 正确 XFF 处理 | 改 Pod annotation / sidecar 配置 | 集群级 |
| D. 接受现状，UI 诚实标注 | 前端加「内网代理」徽标 | 仅前端 |

**推荐 A**：nginx 侧开启 `real_ip` 模块，从 XFF 链里递归取真实 IP。
但**前提**是 XFF 链里确实有真实 IP——需先抓包确认外层是否传了真实 IP。

## 本轮结论

**后端代码不需要改**（`IpUtils` + `LogAspect` 已正确）。
修复属基础设施层，按 AGENTS.md §4.2 安全红线 + §5.2 第 2 步，需业主确认方向后单独实施。
**UI 侧维持方案 §二·D 的诚实降级立场**（不加徽标，避免用 UI 断言不可验证的事实）。
