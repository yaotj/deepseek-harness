## 3. 表设计（新建 GRAYLIST_RISK，PLAT 域）

```sql
CREATE TABLE GRAYLIST_RISK (
  ID NUMBER(22) GENERATED BY DEFAULT AS IDENTITY NOT NULL,
  CARD_ID VARCHAR2(32 CHAR) NOT NULL,          -- 旧 userId
  RULE_ID VARCHAR2(16 CHAR),                   -- 旧 riskRuleId 编码（可空：存量只有规则名）
  RULE_NAME VARCHAR2(100 CHAR) NOT NULL,       -- 旧 riskRuleId 名称（存量实际值）
  RISK_TIMES NUMBER(10),                       -- 旧 riskRuleIdTimes 发生次数
  RISK_LAST_TIME TIMESTAMP(6),                 -- 旧 riskOccursLastDate
  MANAGER_ID VARCHAR2(64 CHAR),                -- 旧 managerId
  UPDATE_TIME TIMESTAMP(6),                    -- 旧 updateDate
  REG_TIME TIMESTAMP(6),                       -- 旧 regDate 入库时间
  MIGRATE_BATCH VARCHAR2(32 CHAR),             -- 迁移批次标记，便于回滚
  CONSTRAINT pk_graylist_risk PRIMARY KEY (ID),
  CONSTRAINT uk_graylist_risk_card_rule UNIQUE (CARD_ID, RULE_NAME)
);
CREATE INDEX idx_glrisk_card ON GRAYLIST_RISK(CARD_ID);
CREATE INDEX idx_glrisk_rule ON GRAYLIST_RISK(RULE_NAME);
```
> 与已生成的 `import-A-faithful-GRAYLIST_LEGACY.sql` 字段等价，仅表名/列名按新系统命名规范微调；明天可直接复用生成器改表名重跑。

## 8. 附：旧黑名单 vs 新系统对标（供决策参考，不在本次灰名单计划内）

旧黑名单（20:14 实扫，3 条）与新系统 `BLACKLIST` 表（两阶段解除机制）的差异：

| 维度 | 旧系统 | 新系统现状 |
|---|---|---|
| 查询条件 | 逻辑卡号 / 审批状态(待审批·已审批·已停用) / 管理编码 | cardId / thirdUserId / status / channelSync / createTime |
| 表格列 | 逻辑卡号(可点击跳详情) / 审批状态 / 管理编码 / 更新时间 / **操作(编辑)** | 卡ID / 三方用户ID / 状态 / 渠道同步 / 拉黑原因 / 解除原因 / 创建时间 / **操作(新增/解除拉黑)** |
