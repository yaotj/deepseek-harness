### A1 Test_005 线网参数「需分多行显示」未实现（⚠️，原表唯一标问题的参数管理条目）

## B 类 — 观察点与排查判据

### B1 三类「只在 Oracle 运行时炸、且被包成 HTTP 200」的查询缺陷（综管台查询页报错的头号成因）

三条同族陷阱，**编译、单测、`xmllint` 全都发现不了**（`AGENTS.md` §5.1）：

| 形态 | 日志关键字 | 触发条件 | 已发生实例 |
|---|---|---|---|
| SQL 正文写了 `--` / `/* */` 注释 | `sql injection violation ... comment not allow` | 该语句每次都失败 | `PayTxnDetailMapper.updatePayCallback`（2026-08-25 修） |
| `where 1 = 1` + 全部谓词都是可选 `<if>` | `sql injection violation ... select alway true condition not allow` | **只在「筛选条件全空」那一支**（= 前台首次进页面） | `UserItpRegInfoMapper.countGroupByCardType`（注册量统计，2.0.73 修） |
| 子查询起了驼峰别名、外层 `<where>`/`order by` 却引物理列名 | `ORA-00904: "O"."CREATE_TIME"` 之类 | `order by` 不在 `<if>` 里 ⇒ **任何筛选组合都失败** | `DailyTicketOrderMapper.selectRefundOrders`（日票退款页，1.0.35 修） |

排查判据：
1. 页面显示「查询失败」且响应是 HTTP 200 + UUID 形态错误码 ⇒ **一定去服务端日志取原文**，`AGENTS.md` §8 列了 5 种成因（事务内 RPC 超时 / `service.*.url` 指向自身 / 路径无 handler / SQL 被 Druid 拒 / 入参反序列化失败），**NEVER 套用上次结论**。
2. `ORA-00904` 报的表别名若是**子查询自己的别名**，就是第三类；修法是外层引别名，**NEVER 去动子查询里的 `as`**（`resultType` 映射依赖它）。
3. 因此本知识库在多条用例里都放了「不选任何条件的默认加载」这一支（002a / 023a / 032 断言 2 / 036a）——**那一支才是会踩的那一支**。
4. 达梦环境关掉了 WallFilter（`dm.properties:5`），**这类缺陷只在 Oracle 上暴露**。

**2026-09-22 回归结果：四个回归点全部通过，三类陷阱本轮零复现。**
- 002a（`/page/base-fare` 全空条件）→ `code=200`，para 日志无 `select alway true condition not allow`；
- 023a（`/page/user/itp/search` 不带条件）→ `code=400` 明确文案，属业务前置校验、根本没走到 SQL；
- 032（`/page/user/itp/reg-stats` 不带日期）→ `code=200`，日志 SQL 原文显示**无条件那一支不产出 `WHERE`** ⇒ 2.0.73 的 `<where>` 修复在 **2.0.77** 上仍在位；
- 036a（`/page/daily-ticket/refund/orders` 不带筛选）→ `code=200`、`total=135`，日志无 `ORA-00904` ⇒ 1.0.35 的「外层引别名」修复在 **1.0.61** 上仍在位。
另实测到**同族的第四种「HTTP 200 掩盖错误」形态**：缺必填 `@RequestParam` 与空 body 的 POST 也返 UUID retCode（见 B12），排查时同样只能靠日志原文区分。

### B2 Test_012 定时任务的判据：`SYS_JOB_LOG`，不是 `QRTZ_*`

- Quartz 用**内存 JobStore**（`web-server/web-quartz/.../config/ScheduleConfig.java` 整个文件被注释、也没有 `spring.quartz.job-store-type`）⇒ `QRTZ_JOB_DETAILS` / `QRTZ_TRIGGERS` **恒 0 行，这不等于任务没跑**。
- `SYS_JOB_LOG` 自 web-admin 1.1.18 起是「开始即入库（`STATUS='2'`）、收口再回写（`'0'`/`'1'`）」，`CREATE_TIME` = 任务开始时刻，`JOB_MESSAGE` 带 `traceId=`。
- 依赖字典：`sys_dict_data` 的 `sys_common_status` 必须有 `2=进行中`，否则前台 `web/src/views/monitor/job/log.vue:112` 状态列**空白且后端不报错**。
- 运行中直接 INSERT/UPDATE `sys_job` **不生效**（`@PostConstruct` 全量加载），必须重启或界面里改一次保存；`misfire_policy=3` ⇒ 重启期间错过的调度**不补跑**。
- **web-admin MUST 单副本**，否则每个副本各跑一份。
- **2026-09-22 实测**：`sys_job` **28 条**、`SYS_JOB_LOG` **40548 条**，最新一条「黑名单解除通知补偿」`status=0` 且 `jobMessage` 带 `traceId=` ⇒ 判据链完整可用；**字典依赖项闭合** —— `SYS_DICT_DATA.sys_common_status` 三项齐全（`0=成功/primary`、`1=失败/danger`、`2=进行中/warning`、`DICT_CODE=100`），前台「进行中」不会渲染成空白。
