**可验证断言**
1. 查询：`code=200`，`data` 是 `Map`，含 `list` + `total`（`FacePayOrderPageController.java:69~74` 显式塞的两个键）。可选筛选：`orderNo` / `payCenterOrderNo` / `payCenterChannelOrderNo` / `deviceId` / `channel` / `bizType` / `orderStatus` / `beginTime` / `endTime`（`:47~57`）。

4. 退款按钮可用条件（前端 `face-pay/order/index.vue:179~180`）：
   `orderStatus ∈ {PAID, FULFILLED, FULFILL_FAILED} && refundStatus ∉ {SUCCESS, PARTIAL}`
   且按钮带 `v-hasPermi=['trans:face-pay:refund']`（`:75`）。
5. 日志留痕：退款前打「运营端发起当面付退款, orderNo=..., operatorId=...」（`:92`），可作为执行证据。

**⚠️ 原表备注的代码侧定位（落 `06` A4）—— 两页退款判据确实不一致**

| 维度 | 当面付订单（Test_038） | 扣费信息 / 用户订单（Test_026） |
|---|---|---|
| 判据字段 | `orderStatus` + `refundStatus` | `debitStatus` + `totalAmount` + `cardType` |
| 可用状态集 | `PAID` / `FULFILLED` / `FULFILL_FAILED` | `SUCCESS` / `PROCESSING` |
| 已退过的单 | `refundStatus` 为 `SUCCESS`/`PARTIAL` 即灰 | **不看退款状态**，只看扣费状态与金额 |
| 票种限制 | 无 | 排除 `0445`/`0446`/`0447`/`0448` |
| 金额 | 全额，后端算 | **可改，支持部分退** |
| 按钮权限 | 有 `v-hasPermi=['trans:face-pay:refund']` | **无 `v-hasPermi`**（`debit-detail/index.vue:53`） |
| 代码位置 | `face-pay/order/index.vue:179~180` | `debit-detail/index.vue:163~165` |

「保持一致」到底以哪边为准**需业务裁决**，不在此裁定。但有两点是明确的技术缺口，无论按哪边统一都要补：
- 扣费页**缺按钮权限控制**（任何能进页面的账号都能退款）；
- 扣费页**不看退款状态**（重复退款的拦截只能靠后端，前端不灰显 → Test_026a 第 ④ 条必须实测）。

## Test_039 密钥版本查看

密钥管理 / 密钥查询 / 密钥版本查看 ｜ ✅ 通过

**三元组**
- 前端：`/user-operation/key-version`（种子 `zongguantai-menu.sql:14`，**挂在「用户管理」目录 2071 下**，与原表写的「用户管理→密钥版本查看」一致；页面 `web/src/views/trans/key/version/index.vue`，权限 `trans:key:version:query`）
- 后端：`GET /page/key/versions`（`key-server/.../controller/page/KeyPageController.java:14,24`，返回 `List<KeyVersionView>`，实现 `KeyVersionQueryServiceImpl`）
- 模块：key-server（NodePort 30015），主表 `METRO_AGM_KEY_VERSION`、`METRO_CA_KEYSTORE`、`METRO_MEMBER_STATIC_KEY`（对应三个 mapper）

**可验证断言**
1. `code=200`，`data` 是数组，按密钥域给出 AGM / CA / HCE 三组的当前版本、接入方、生效日期。
2. **只读、且不含密钥材料**：断言响应里**没有**密钥本体 / 密文字段（`KeyVersionView` 只承载版本元信息）。这条是安全断言，**回填时 NEVER 贴响应原文**，只写「无密钥材料字段」。
3. 与库对齐：每组的版本号等于对应表里当前生效行的版本；某一域无数据时该组应缺省或计 0，**不应整个接口报错**。
4. 该端点无写操作、无鉴权 —— 属只读信息泄露面（版本与接入方），记入 `06` A8 的范围但风险低。

**执行方式**
① `curl -s "http://172.20.211.23:30015/page/key/versions"`
② DB
```sql
SELECT * FROM METRO_AGM_KEY_VERSION ORDER BY 1;
SELECT * FROM METRO_CA_KEYSTORE ORDER BY 1;
SELECT * FROM METRO_MEMBER_STATIC_KEY ORDER BY 1;
```
（**只看版本 / 接入方 / 生效日期列，NEVER SELECT 密钥列、NEVER 回显其值**，`AGENTS.md` §5.2 敏感配置红线）
③ `scripts/klog.sh key-server ERROR 200`

**结果**：2026-09-22 **PASS（安全断言成立）**。`GET :30015/page/key/versions` → `code=200`，返回 `AGM_KEY(providerId=01, currentVersion=34, status=20020 审批通过)` 与多行 `CA_KEYSTORE(currentVersion=01/02…, status=1 使用中)`。**断言 2 成立：响应里没有任何密钥材料字段**，只有版本 / 接入方 / 状态 / 生效日期。某一域无数据时接口仍 `200`（断言 3 成立）。⚠️ 该端点无鉴权（A8 同缺口，泄露面为密钥版本与接入方）。证据见 [07](07-执行记录-2026-09-22.md) §二。
