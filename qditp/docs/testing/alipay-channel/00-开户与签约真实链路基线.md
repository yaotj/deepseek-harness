## 五、本次发现的问题

1. **`ALIPAY_REG_LOG` 永远不记响应**。`AlipayAccountServiceImpl.buildAlipayRegLog`（同文件 :340~:358）只 set 了 `requestBody` / `resultCode` / `resultMsg`，`setResponseSeq` / `setResponseBody` 全仓库无调用方；mapper 侧 `AlipayRegLogMapper.xml:35~64` 的 INSERT 有这两列、绑的是 null，且该 XML **只有 insert 没有 update**，没有补写机会。排查开户失败时**不要指望这两列**，只能看服务日志。
2. **pay-sign-server 侧的支付宝签约是死代码**。`PaySignAlipayTripController` → `PaySignServiceImpl:76` → `ContractDomainServiceImpl:46` → `PaySignWorkflow.alipayTripRequestSignInfo`（`pay-sign-server/.../service/impl/PaySignWorkflow.java:180~240`，写 `APP_PAY_SIGN_INFO` + `APP_PAY_SIGN_REQUEST`，`OPERATION_TYPE='ALIPAY_TRIP_REQUEST_SIGN_INFO'`）这一整条，唯一客户端封装 `rpc/.../paySign/PaySignClient.java:157` `alipayTripAddContract` **全仓库零调用方**。库里那 26 行就是它 6 月留下的。**是删还是留作后续收口的预留入口，待裁决。**
3. **`ALIPAY_PAY_LOG.TRANS_TIME` 是 `VARCHAR2` 且格式不统一**，实测三种值并存：null、`2026-07-28 16:59:55`、裸毫秒 `1785229085685`。写入端 `PayLogBuilder`（`alipay-pay-sign-server/.../service/impl/PayLogBuilder.java:25~54`）不赋值，只有 `PaymentQueryService`（:84~:124 查询、:200~:212 回调）把支付中心返回值**原样落库、不做归一**。而 `AlipayPayLogMapper.xml` 的 :178 / :181 / :208 / :211 用 `TO_DATE(TRANS_TIME,'YYYY-MM-DD HH24:MI:SS')` 做时间范围过滤——遇到毫秒串会 `ORA-01861`，运营后台按时间查询会整条 SQL 失败（**代码推断，未实测**）。
4. **`AlipayContractServiceImpl.addContract` 在 `@Transactional` 内发起两次 RPC**，违反 `AGENTS.md` §5.2。本次数据量小没暴露，压测或对端变慢时会复现行锁长持有。`updatePaymentChannel` 的返回值在 :105 有显式检查，这一处写法是对的。
