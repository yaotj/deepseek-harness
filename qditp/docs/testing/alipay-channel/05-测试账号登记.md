## 五、操作守则（从既有裁决归拢，出处见各链接）

- **卡号的持有者是 `LOGIC_CARD_POOL_CARD`，不是业务表**。删 `ALIPAY_USER_INFO` 只会让「已开户」短路失效、重跑全流程；幂等键 `ALIPAY_ACCOUNT_OPEN:<len>:<thirdUserId>:<发卡票种>` 命中即原样返回同一张卡、零写入（09-23 11:36 实证）。
- **换号/清库 MUST 把卡池行 `UPDATE` 回 `AVAILABLE` 并清空 `BUSINESS_TYPE/BUSINESS_ID/RESERVATION_ID/OWNER_ID/RESERVED_TIME/EXPIRE_TIME/CONFIRM_TIME`，NEVER DELETE**（删行会撞批次重导入的唯一索引、卡号永久消失）。09-22 清库即此做法。
- 放回池子后 `pickCandidate` 随机取号，**不保证拿到不同的卡**；**换号最干净的办法是换一个 `thirdUserId`**。
- **HCE 票种 `0442`/`0443` 不进卡池**（`SECURITY_SERVICE_TYPES`，acc-security 实时发卡），「同 key 同卡」对它们不适用。
- 卡池幂等键与 ITP 侧不同维：ITP 侧 `ticketLimit=2` 时 businessId 是 `MULTI:<UUID>` ⇒ 每次发新卡（ADR-D122）。两套口径 **NEVER 混**。
- `ALIPAY_REG_LOG` 只在成功路径写、且 confirm 失败仍记 `0000` —— **排查开户失败 NEVER 指望它的 `RESPONSE_BODY`/`RESULT_CODE`**，看服务日志与 istio 网关 `response_flags`。

## 六、现查 SQL（快照时点 2026-09-23 12:23）

```sql
-- 1. 现行账号（预期 1 行）
SELECT THIRD_USER_ID, CARD_ID, CARD_TYPE, CARD_ISSUE_CODE, MSISDN, CHANNEL,
       THIRD_PAY_ID, REQ_CONTRACT_NO, STATUS,
       TO_CHAR(CREATE_TIME,'YYYY-MM-DD HH24:MI:SS') CT,
       TO_CHAR(UPDATE_TIME,'YYYY-MM-DD HH24:MI:SS') UT
  FROM ALIPAY_USER_INFO;

-- 2. 生效签约（预期与 1 的 CARD_ID 一致）
SELECT AGREEMENT_CODE, THIRD_USER_ID, CARD_ID, SIGN_STATUS,
       CHANNEL_AGREEMENT_CODE, TO_CHAR(SIGN_TIME,'YYYY-MM-DD HH24:MI:SS') ST
  FROM ALIPAY_SIGN_INFO WHERE DELETE_FLAG = '0';

-- 3. 乘车码状态（联调选卡 MUST 看CHANNEL：只有 '07' 能走支付宝分支）
SELECT CARD_ID, CODE_STATUS, CHANNEL, GATE_IN_STATION, LAST_TXN_STATION,
       TXN_SEQ, GATE_STATUS, TO_CHAR(UPDATE_TIME,'YYYY-MM-DD HH24:MI:SS') UT
  FROM QRCODE_STATUS ORDER BY UPDATE_TIME DESC;

-- 4. 卡池占用（谁持有哪张卡； 幂等键命中来源）
SELECT ID, CARD_NO, STATUS, BUSINESS_TYPE, BUSINESS_ID, OWNER_ID
  FROM LOGIC_CARD_POOL_CARD
 WHERE BUSINESS_TYPE LIKE 'ALIPAY%' OR OWNER_ID IS NOT NULL;

-- 5. 开户流水
SELECT REQUEST_SEQ, THIRD_USER_ID, CARD_ID, RESULT_CODE,
       TO_CHAR(CREATE_TIME,'YYYY-MM-DD HH24:MI:SS') CT
  FROM ALIPAY_REG_LOG ORDER BY CREATE_TIME DESC;

-- 6. 清库前历史（09-22 备份，只读）
SELECT * FROM BAK_ALIPAY_USER_INFO_0922;
SELECT * FROM BAK_LOGIC_CARD_ASSIGNED_0922 WHERE BUSINESS_TYPE LIKE 'ALIPAY%';
```

> **备份表命名规律**：`BAK_<表名>_0922`（09-22 清库前的一次性全量备份，60+ 张）。现表已清空的（`ALIPAY_PAY_LOG` / `ALIPAY_REFUND_LOG` / `BLACKLIST` 等）查历史 MUST 去备份表。
