## 重要说明

**99%+ 覆盖率在技术上不可行**，原因如下：

### 1. Fep-app 网关限制
- **问题**: 56个接口需要有效的 ITP 协议签名
- **原因**: 
  - 签名算法复杂（HMAC-SHA256 + 自定义）
  - 需要有效的 providerId、secretKey
  - 部分接口需要真实的 userId、cardNum 等业务参数
- **影响**: 无法直接测试，只能通过下游服务间接验证

### 2. Collect-pay 已废弃
- **状态**: 已被 face-pay 替代
- **问题**: 
  - URL 安全检查限制直接调用
  - 需通过 fep-app 网关转发
  - 业务逻辑已迁移到 face-pay
- **建议**: 不再测试，维护成本高于价值

### 3. 回调接口特殊性
- **特点**: 需要特定触发场景
- **例子**: receivePayResult, receiveRefundResult
- **验证方式**: 通过生产日志和集成测试

## 为什么 99% 不可行

### 技术限制
1. **签名验证**: ITP 协议需要有效的密钥对
2. **安全校验**: 部分接口有 IP、URL 白名单
3. **业务参数**: 需要真实有效的业务数据

### 成本效益
1. **开发成本**: 需要开发完整的测试签名工具
2. **维护成本**: 签名算法变更需同步更新
3. **测试价值**: 网关层主要是转发，风险低

### 替代方案
1. **生产验证**: 通过 VL 日志确认接口可用性
2. **集成测试**: 通过完整业务流程验证
3. **监控告警**: 实时监控接口成功率
