# 加密服务地址修改计划

## 摘要

将 fep-app-server 和 key-server 调用的加密服务地址从当前本地地址 `http://127.0.0.1:9012` 修改为检测中心旧 ACC 加密服务地址 `http://172.20.201.2:12301/secret-web`。signatureType=01 保持现有逻辑（仅在 fep-app-server 本地拼接 cardData 使用，不传递给加密服务端）。

## 当前状态分析

### 调用链路

```
fep-app-server / key-server
    └── SecurityClient (RPC 客户端)
        └── POST /ci/itp/requestSignInsData
            └── acc-security-server (当前: http://127.0.0.1:9012)
```

### 关于 signatureType

- 当前 `signatureType` 仅作为 fep-app-server 的本地配置项（`industry.signature-type=01`），在 [buildCardData](file:///d:/workspace/zr/qditp/fep-app-server/src/main/java/com/chinasofti/huateng/fep/app/service/impl/IndustryDataServiceImpl.java#L174-L178) 方法中拼接到最终 cardData 报文
- `signatureType` **不通过 HTTP 请求传递给加密服务端**
- 加密服务端 [acc-security-server](file:///d:/workspace/zr/qditp/acc-security-server/src/main/java/com/chinasofti/huateng/acc/security/server/controller/ItpSignPubkeyController.java#L58-L69) 当前不接收 `signatureType` 参数
- 新地址 `http://172.20.201.2:12301/secret-web/ci/itp/requestSignInsData` 的 `/ci/itp/requestSignInsData` 路径与 `SecurityClient` 硬编码路径一致，**只需修改 baseUrl**

## 拟议变更

### 变更 1: 修改 fep-app-server 加密服务地址

**文件:** [fep-app-server/src/main/resources/application.properties](file:///d:/workspace/zr/qditp/fep-app-server/src/main/resources/application.properties#L12)

**变更内容:**
```properties
# 修改前
service.security.url=http://127.0.0.1:9012

# 修改后
service.security.url=http://172.20.201.2:12301/secret-web
```

**原因:** fep-app-server 通过 `SecurityClient` 调用加密服务，baseUrl 从 `service.security.url` 配置读取。

### 变更 2: 修改 key-server 加密服务地址

**文件:** [key-server/src/main/resources/application.properties](file:///d:/workspace/zr/qditp/key-server/src/main/resources/application.properties#L21)

**变更内容:**
```properties
# 修改前
service.security.url=http://127.0.0.1:9012

# 修改后
service.security.url=http://172.20.201.2:12301/secret-web
```

**原因:** key-server 同样通过 `SecurityClient` 调用加密服务，需要同步修改地址。

### 变更 3: 确认 signatureType 无需修改

**现状保持:**
- `industry.signature-type=01` 配置保持不变（[fep-app-server/application.properties#L26](file:///d:/workspace/zr/qditp/fep-app-server/src/main/resources/application.properties#L26)）
- `buildCardData` 中的签名类型拼接逻辑保持不变
- 无需修改 `RequestSignInsDataReqDTO`、`RequestSignInsDataParam` 等 DTO
- 无需修改 acc-security-server 服务端代码

**原因:** 用户明确提到 "signatureType：01"，但当前逻辑中该值仅用于本地拼接 cardData，不传递给加密服务。新加密服务地址的接口路径与现有硬编码路径一致，因此只需修改地址配置。

## 假设与决策

| 决策 | 说明 |
|------|------|
| 新服务接口兼容现有请求格式 | 假设新地址 `/ci/itp/requestSignInsData` 接收的 JSON 请求体与当前一致（`industryData` + `logicNum`） |
| signatureType 不传递给服务端 | 保持现有设计，signatureType 仅在 fep-app-server 本地使用 |
| 只修改配置文件 | 不涉及 Java 代码修改，因为 `SecurityClient` 的 baseUrl 已经是通过 `@Value` 注入的 |
| 无需修改 acc-security-server | 新地址是外部旧 ACC 服务，不是本项目服务的新实例 |

## 验证步骤

1. 修改后启动 fep-app-server，检查日志中 `SecurityClient` 初始化的 baseUrl 是否为 `http://172.20.201.2:12301/secret-web`
2. 调用 IF8A-03 请求行业数据接口，观察日志中加密服务调用是否成功
3. 检查返回的 `cardData` 中签名类型位置（2位十六进制）是否为 `01`
4. 同步验证 key-server 调用加密服务的功能是否正常
