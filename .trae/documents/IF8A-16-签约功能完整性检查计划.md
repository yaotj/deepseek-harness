# IF8A-16 请求签约信息功能完整性检查计划

## 一、Summary

检查 IF8A-16 请求签约信息接口的完整实现，确认签约功能是否闭环。用户提供的请求参数中 `payChannelCode=0802`，需要验证系统是否支持该编码，以及整个签约流程（请求签约 -> 签约回调 -> 通知APP）是否完整。

### 2.3 发现的问题

**问题1：payChannelCode=0802 不被支持**

[pay-sign-server PaySignServiceImpl.normalizeVendor()](file:///d:/workspace/zr/qditp/pay-sign-server/src/main/java/com/chinasofti/huateng/paysign/service/impl/PaySignServiceImpl.java) 只做 trim，没有编码映射。本地兜底 SDK 生成只支持 `03`（支付宝）和 `04`（微信）。

传入 `0802` 时：
- 网关调用：透传 `paymentVendor=0802`，若网关未配置则失败
- 本地兜底：不匹配 `03` 或 `04`，返回空字符串 `""`
- 最终结果：`请求支付签约接口失败`

**问题2：支付平台网关 URL 为空**

[pay-sign-server application.properties](file:///d:/workspace/zr/qditp/pay-sign-server/src/main/resources/application.properties) 中 `pay.sign.gateway-url=` 为空，意味着网关调用会直接跳过，只能走本地兜底逻辑。

## 三、Proposed Changes

### 3.1 添加 payChannelCode 编码映射（支持 0802）

**文件：** `d:\workspace\zr\qditp\pay-sign-server\src\main\java\com\chinasofti\huateng\paysign\service\impl\PaySignServiceImpl.java`

**What：** 修改 `normalizeVendor` 方法，添加 `0802` -> `03`（支付宝）的映射。

**Why：** 用户传入的 `payChannelCode=0802` 是支付宝支付的标准编码，需要映射为内部使用的 `03`。

**How：**
```java
private String normalizeVendor(String payChannelCode) {
    if (!StringUtils.hasText(payChannelCode)) {
        return null;
    }
    String code = payChannelCode.trim();
    // 0802 = 支付宝支付
    if ("0802".equals(code)) {
        return "03";
    }
    // 0803 = 微信支付（预留）
    if ("0803".equals(code)) {
        return "04";
    }
    return code;
}
```

### 3.2 验证本地兜底 SDK 参数生成

**文件：** `d:\workspace\zr\qditp\pay-sign-server\src\main\java\com\chinasofti\huateng\paysign\service\impl\PaySignServiceImpl.java`

**What：** 检查 `buildLocalSdkInfo` 方法生成的支付宝 SDK 参数是否符合用户预期。

用户预期的返回：
```
alipays://platformapi/startapp?appId=60000157&appClearTop=false&startMultApp=YES&sign_params=...
```

当前代码生成的格式：
```java
"alipays://platformapi/startapp?appId=" + alipayAppId 
    + "&appClearTop=false&startMultApp=YES&sign_params=" + encode(signParams)
```

其中 signParams 包含：app_id, third_user_id, display_account, request_sign_seq, return_url, auth_code

这与用户提供的实际返回格式一致，**无需修改**。

### 3.3 验证回调链路完整性

回调链路已完整实现：
1. `receiveSignResult` 接收支付平台回调
2. 更新签约状态（SUCCESS -> SIGNED，其他 -> NOT_SIGNED）
3. 通知 APP（`app.notify.sign-result-url`）

**无需修改**。
