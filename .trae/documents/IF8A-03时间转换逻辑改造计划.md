# IF8A-03 请求行业数据时间转换逻辑改造计划

## 一、Summary

IF8A-03 请求行业数据接口中，`buildUnsignedIndustryData` 方法使用 `toFourByteHexByBizTime` 将 `GATE_IN_TIME` 和 `LAST_TXN_TIME` 转换为十六进制时间戳。当前逻辑要求时间字符串必须为 14 位标准格式（yyyyMMddHHmmss），但 QR_CODE_STATUS 表中的这两个字段可能为 `0` 或其他非标准格式，导致转换失败或抛出异常。需要修改时间转换逻辑，兼容非标准时间值。

## 二、Current State Analysis

### 2.1 当前时间转换逻辑

**文件：** `d:\workspace\zr\qditp\fep-app-server\src\main\java\com\chinasofti\huateng\fep\app\service\impl\IndustryDataServiceImpl.java`

```java
private String toFourByteHexByBizTime(String bizTime) {
    if (StringUtils.hasText(bizTime) && bizTime.trim().length() == 14) {
        LocalDateTime dateTime = LocalDateTime.of(
                Integer.parseInt(bizTime.substring(0, 4)),
                Integer.parseInt(bizTime.substring(4, 6)),
                Integer.parseInt(bizTime.substring(6, 8)),
                Integer.parseInt(bizTime.substring(8, 10)),
                Integer.parseInt(bizTime.substring(10, 12)),
                Integer.parseInt(bizTime.substring(12, 14)));
        return toFourByteHexByDateTime(dateTime);
    }
    return toFourByteHexByDateTime(LocalDateTime.now());
}
```

### 2.2 问题分析

当前逻辑：
- 如果 `bizTime` 为 `null` 或空字符串 -> 返回当前时间
- 如果 `bizTime` 长度不为 14 -> 返回当前时间
- 如果 `bizTime` 为 `0`、`00000000000000`、`0000000000` 等非标准格式 -> 返回当前时间

**问题：** 当数据库中 `GATE_IN_TIME` 和 `LAST_TXN_TIME` 为 `0` 时，`firstNonBlank` 方法会返回 `"0"`，然后 `toFourByteHexByBizTime("0")` 会因为长度不为 14 而返回当前时间。这可能导致时间戳不一致的问题。

更关键的是，如果传入类似 `"00000000000000"` 这样的 14 位字符串，会尝试解析为 `LocalDateTime.of(0, 0, 0, 0, 0, 0)`，这会抛出 `DateTimeException`。

### 2.3 调用链路

```java
String qrHandleDate = toFourByteHexByBizTime(firstNonBlank(qrStatus.getLastTxnTime(), qrStatus.getGateInTime()));
```

`firstNonBlank` 会优先返回 `lastTxnTime`，如果为空则返回 `gateInTime`。如果两者都是 `0` 或空，返回 `null`，然后 `toFourByteHexByBizTime(null)` 返回当前时间。

## 三、Proposed Changes

### 3.1 修改 toFourByteHexByBizTime 方法

**文件：** `d:\workspace\zr\qditp\fep-app-server\src\main\java\com\chinasofti\huateng\fep\app\service\impl\IndustryDataServiceImpl.java`

**What：** 增强 `toFourByteHexByBizTime` 方法，增加对非标准时间值（如全 0、长度不为 14、解析异常）的兼容处理。

**Why：** 数据库中 `GATE_IN_TIME` 和 `LAST_TXN_TIME` 可能为 `0`、`00000000000000` 等非标准值，需要安全处理。

**How：**
```java
private String toFourByteHexByBizTime(String bizTime) {
    if (!StringUtils.hasText(bizTime)) {
        return toFourByteHexByDateTime(LocalDateTime.now());
    }
    String trimmed = bizTime.trim();
    // 兼容非标准时间值：全0、长度不为14、无法解析的情况
    if (trimmed.length() != 14 || isAllZeros(trimmed)) {
        return toFourByteHexByDateTime(LocalDateTime.now());
    }
    try {
        LocalDateTime dateTime = LocalDateTime.of(
                Integer.parseInt(trimmed.substring(0, 4)),
                Integer.parseInt(trimmed.substring(4, 6)),
                Integer.parseInt(trimmed.substring(6, 8)),
                Integer.parseInt(trimmed.substring(8, 10)),
                Integer.parseInt(trimmed.substring(10, 12)),
                Integer.parseInt(trimmed.substring(12, 14)));
        return toFourByteHexByDateTime(dateTime);
    } catch (Exception e) {
        log.warn("业务时间解析失败, bizTime={}, 使用当前时间", trimmed);
        return toFourByteHexByDateTime(LocalDateTime.now());
    }
}

private boolean isAllZeros(String value) {
    if (!StringUtils.hasText(value)) {
        return true;
    }
    for (char c : value.toCharArray()) {
        if (c != '0') {
            return false;
        }
    }
    return true;
}
```

## 四、Assumptions & Decisions

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 全0处理 | 返回当前时间 | 全0表示无有效时间记录 |
| 长度不为14 | 返回当前时间 | 非标准格式无法解析 |
| 解析异常 | 返回当前时间并记录日志 | 防止异常中断业务流程 |
| 默认值 | 当前时间 | 与现有逻辑保持一致 |
