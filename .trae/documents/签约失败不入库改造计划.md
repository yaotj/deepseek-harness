# 签约失败不入库改造计划

## 一、Summary

修改 IF8A-16 请求签约信息接口，确保只有在签约成功（生成有效 SDK 参数）时才将数据入库。如果签约失败（如 buildRequestStartSdkInfo 返回空），则不保存记录到数据库，避免后续重复调用时因数据不一致导致唯一约束冲突。

## 二、Current State Analysis

### 2.1 当前代码流程

**文件：** `d:\workspace\zr\qditp\pay-sign-server\src\main\java\com\chinasofti\huateng\paysign\service\impl\PaySignServiceImpl.java`

```java

    RequestSignInfoResult response = new RequestSignInfoResult();
    try {

            // ... 返回错误，但记录已入库

        response.setRequestStartSdkInfo(sdkInfo);
        return response;
    } catch (Exception e) {
        // ...
    }
}
```

### 2.2 问题分析

当前 `saveSignInfo(signInfo)` 在 `buildRequestStartSdkInfo` 之前执行，即使后续生成 SDK 参数失败，记录也已经入库。这导致：
1. 签约失败的记录占用数据库空间
2. 后续再次调用时，如果编码映射不一致（如 0802 vs 03），可能触发唯一约束冲突

## 三、Proposed Changes

### 3.1 调整 saveSignInfo 调用位置

**文件：** `d:\workspace\zr\qditp\pay-sign-server\src\main\java\com\chinasofti\huateng\paysign\service\impl\PaySignServiceImpl.java`

**What：** 将 `saveSignInfo` 调用移到 `buildRequestStartSdkInfo` 成功之后，只有生成有效 SDK 参数时才入库。

**Why：** 确保只有签约成功的数据才入库，失败时不留脏数据。

**How：**
```java
@Override
@Transactional(rollbackFor = Exception.class)
public RequestSignInfoResult requestSignInfo(RequestSignInfoReqDTO request) {
    RequestSignInfoResult response = new RequestSignInfoResult();
    try {
        String validMsg = validateRequestSignInfo(request);
        if (validMsg != null) {
            fillError(response, PaySignErrorCodeEnum.INVALID_PARAM, validMsg);
            writeLog("REQUEST_SIGN_INFO", request != null ? request.getThirdUserId() : null, 
                request != null ? request.getRequestSignSeq() : null, 
                request != null ? normalizeVendor(request.getPayChannelCode()) : null, request, response);
            return response;
        }

        String paymentVendor = normalizeVendor(request.getPayChannelCode());
        
        // 先尝试生成 SDK 参数
        String sdkInfo = buildRequestStartSdkInfo(request, paymentVendor);
        if (!StringUtils.hasText(sdkInfo)) {
            fillError(response, PaySignErrorCodeEnum.SYSTEM_ERROR, "请求支付签约接口失败");
            writeLog("REQUEST_SIGN_INFO", request.getThirdUserId(), request.getRequestSignSeq(), 
                paymentVendor, request, response);
            return response;
        }
        
        // SDK 参数生成成功后再入库
        PaySignInfo signInfo = getOrInitSignInfo(request.getRequestSignSeq(), paymentVendor);
        signInfo.setRequestSignSeq(request.getRequestSignSeq());
        signInfo.setThirdUserId(request.getThirdUserId());
        signInfo.setPaymentVendor(paymentVendor);
        signInfo.setDisplayAccount(request.getDisplayAccount());
        signInfo.setContractStatus(STATUS_SIGNING);
        saveSignInfo(signInfo);

        fillSuccess(response);
        response.setRequestStartSdkInfo(sdkInfo);
        writeLog("REQUEST_SIGN_INFO", request.getThirdUserId(), request.getRequestSignSeq(), 
            paymentVendor, request, response);
        return response;
    } catch (Exception e) {
        log.error("处理请求签约信息异常", e);
        fillError(response, PaySignErrorCodeEnum.SYSTEM_ERROR, PaySignErrorCodeEnum.SYSTEM_ERROR.getMsg());
        writeLog("REQUEST_SIGN_INFO", request != null ? request.getThirdUserId() : null, 
            request != null ? request.getRequestSignSeq() : null, 
            request != null ? normalizeVendor(request.getPayChannelCode()) : null, request, response);
        return response;
    }
}
```

## 四、Assumptions & Decisions

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 入库时机 | SDK 生成成功后 | 只有成功才需要记录 |
| 失败处理 | 不入库，直接返回错误 | 避免脏数据 |
| 日志记录 | 无论成败都记录 | 便于排查问题 |

## 五、Verification Steps

1. 编译验证 pay-sign-server
2. 测试场景：
   - SDK 生成成功 -> 记录入库
   - SDK 生成失败 -> 记录不入库
   - 重复调用（同一 requestSignSeq）-> 正常更新，不报错
