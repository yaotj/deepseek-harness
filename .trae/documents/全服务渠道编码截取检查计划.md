# 全服务渠道编码截取逻辑检查结果

## 一、Summary

经全面搜索所有 13 个服务，确认渠道编码（payChannelCode/paymentVendor/channelCode）的截取/映射情况。

## 二、检查结果

### 2.1 存在截取逻辑的服务

| 服务 | 文件 | 方法 | 截取逻辑 | 说明 |
|------|------|------|----------|------|
| **fep-app-server** | [IndustryDataServiceImpl.java](file:///d:/workspace/zr/qditp/fep-app-server/src/main/java/com/chinasofti/huateng/fep/app/service/impl/IndustryDataServiceImpl.java) | `resolveSignChannelCode` | `substring(0, 2)` | 对签约渠道编码取前2位 |

### 2.2 无截取逻辑的服务（11个）

| 服务 | 说明 |
|------|------|
| account-server | 未使用相关字段 |
| ticket-server | 未使用相关字段 |
| blacklist-server | 未使用相关字段 |
| acc-security-server | 仅有通用工具类 substring，无渠道编码相关 |
| acc-es-server | 仅有报表报文定长拆解，无渠道编码相关 |
| acc-secure-server | 未使用相关字段 |
| key-server | 仅有密钥处理相关 substring |
| collect-pay-server | 使用字段但无截取/映射 |
| collect-ticket-server | 使用字段但无截取/映射 |
| online-server | 仅用于测试场景判断 |
| **pay-sign-server** | **normalizeVendor 仅做 trim，无截取** |

### 2.3 编码映射情况

| 服务 | 文件 | 映射逻辑 |
|------|------|----------|
| wallet-server | WalletSignServiceImpl.java | 03=支付宝, 04=微信 |
| wallet-server | WalletContractServiceImpl.java | 03/04/06/07/0B |
| pay-sign-server | PaySignServiceImpl.java | **仅 trim，无映射** |

### 2.4 0802/0803 映射情况

**整个项目中未找到 0802 -> 03 或 0803 -> 04 的任何映射逻辑。**

## 三、结论

1. **fep-app-server 的 IndustryDataServiceImpl** 中存在 `substring(0, 2)` 截取，但仅用于 IF8A-03 请求行业数据接口的签约渠道编码处理，与 IF8A-16 请求签约信息无关。

2. **pay-sign-server 的 normalizeVendor** 方法确实没有做截取，只是简单的 trim。传入 `0802` 会原样返回 `0802`。

3. **buildLocalSdkInfo** 只支持 `03`（支付宝）和 `04`（微信），传入 `0802` 会返回空字符串，导致签约失败。

4. **整个项目中没有任何服务将 0802 映射为 03**。

## 四、建议修改

需要在 pay-sign-server 的 `normalizeVendor` 方法中添加截取映射逻辑，使 `0802` 能被正确识别为支付宝（03）。
