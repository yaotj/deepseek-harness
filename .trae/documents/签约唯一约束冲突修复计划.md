# 签约唯一约束冲突修复计划

## 摘要

修复 pay-sign-server 中 `requestSignInfo` 接口重复调用时触发的 `ORA-00001: 违反唯一约束条件 (QDITP.UK_APP_PAY_SIGN_INFO_USER_VENDOR)` 错误。问题根因是 `normalizeVendor` 方法未对 `payChannelCode`（如 `0802`）进行归一化映射，导致第一次调用使用原始值 `0802` 入库，第二次调用使用映射值 `03`，MERGE 语句的 `ON` 条件不匹配，从而走 INSERT 分支触发唯一约束冲突。

## 当前状态分析

### 问题根因

**文件:** [PaySignServiceImpl.java](file:///d:/workspace/zr/qditp/pay-sign-server/src/main/java/com/chinasofti/huateng/paysign/service/impl/PaySignServiceImpl.java#L1049-L1051)

```java
private String normalizeVendor(String payChannelCode) {
    return StringUtils.hasText(payChannelCode) ? payChannelCode.trim() : null;
}
```

当前 `normalizeVendor` 仅做 trim 处理，未进行编码映射。当请求传入 `payChannelCode=0802` 时：

* 第一次调用：`paymentVendor = "0802"`，MERGE 时数据库中无 `0802` 记录，INSERT 成功

* 第二次调用：`paymentVendor = "0802"`（相同），MERGE 时匹配到已有记录，UPDATE 成功

但日志显示冲突发生在 `requestSignInfo` 方法第 152 行（`saveSignInfo` 调用处），说明实际场景中 `paymentVendor` 的值在两次调用间发生了变化。

```java
private PaySignInfo getOrInitSignInfo(String requestSignSeq, String paymentVendor) {
    PaySignInfo signInfo = null;
    if (StringUtils.hasText(requestSignSeq)) {
        // 先按 requestSignSeq + paymentVendor 查询
        signInfo = paySignInfoMapper.selectBySeq(requestSignSeq, paymentVendor);
        if (signInfo == null) {
            // 如果查不到，可能数据库中存储的是原始编码，只按 requestSignSeq 查询
            signInfo = paySignInfoMapper.selectBySeq(requestSignSeq, null);
            if (signInfo != null) {
                // 更新 paymentVendor 为映射后的值
                signInfo.setPaymentVendor(paymentVendor);
            }
        }
    }
    if (signInfo == null) {
        signInfo = new PaySignInfo();
        signInfo.setRequestSignSeq(requestSignSeq);
        signInfo.setPaymentVendor(paymentVendor);
        signInfo.setContractStatus(STATUS_NOT_SIGNED);
    }
    return signInfo;
}
```

### MERGE SQL 分析

```sql
MERGE INTO APP_PAY_SIGN_INFO t
USING (
    SELECT ? AS REQUEST_SIGN_SEQ, ? AS PAYMENT_VENDOR, ...
) s
ON (t.REQUEST_SIGN_SEQ = s.REQUEST_SIGN_SEQ AND t.PAYMENT_VENDOR = s.PAYMENT_VENDOR)
WHEN MATCHED THEN UPDATE SET ...
WHEN NOT MATCHED THEN INSERT ...
```

唯一约束 `UK_APP_PAY_SIGN_INFO_USER_VENDOR` 定义在 `(REQUEST_SIGN_SEQ, PAYMENT_VENDOR)` 上。

### 冲突场景

假设第一次调用时 `paymentVendor="0802"`（原始值），入库成功。第二次调用时如果 `normalizeVendor` 返回了不同的值（如 `"03"`），则：

1. `getOrInitSignInfo("seq", "03")` → `selectBySeq("seq", "03")` 返回 null
2. `selectBySeq("seq", null)` 返回已有记录（paymentVendor="0802"）
3. `signInfo.setPaymentVendor("03")` 更新内存对象
4. `saveSignInfo` 执行 MERGE，`ON` 条件为 `REQUEST_SIGN_SEQ="seq" AND PAYMENT_VENDOR="03"`
5. 数据库中已有 `("seq", "0802")`，不匹配 `("seq", "03")`
6. MERGE 走 INSERT 分支，触发唯一约束冲突

## 拟议变更

### 变更 1: 修复 normalizeVendor 方法，添加编码映射

**文件:** [PaySignServiceImpl.java](file:///d:/workspace/zr/qditp/pay-sign-server/src/main/java/com/chinasofti/huateng/paysign/service/impl/PaySignServiceImpl.java#L1049-L1051)

**变更内容:**

```java
// 修改前
private String normalizeVendor(String payChannelCode) {
    return StringUtils.hasText(payChannelCode) ? payChannelCode.trim() : null;
}

// 修改后
private String normalizeVendor(String payChannelCode) {
    if (!StringUtils.hasText(payChannelCode)) {
        return null;
    }
    String code = payChannelCode.trim();
    if (code.length() >= 2) {
        String prefix = code.substring(0, 2);
        if ("08".equals(prefix)) {
            String suffix = code.length() >= 3 ? code.substring(2, 3) : "";
            if ("2".equals(suffix)) {
                return "03";
            }
            if ("3".equals(suffix)) {
                return "04";
            }
        }
        if ("03".equals(prefix) || "04".equals(prefix)) {
            return prefix;
        }
    }
    return code;
}
```

**原因:** 确保 `0802` 始终映射为 `03`，避免同一请求因编码不一致导致 MERGE 走 INSERT 分支。
