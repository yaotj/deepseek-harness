## 三、请求方式问题

### 3.1 代码实现

控制器方法统一使用 `@ModelAttribute` 接收参数：

```java
// TVM
public JSONObject requestGenSjtOrder(@ModelAttribute BaseRequestDTO baseRequest)

// BOM
public JSONObject requestPayment(@ModelAttribute BaseRequestDTO baseRequest)
```

`@ModelAttribute` 通常用于表单数据（`application/x-www-form-urlencoded`）或查询参数绑定。

### 3.2 测试请求

测试使用 JSON Body 发送请求：

```json
{
  "charset": "UTF-8",
  "deviceId": "11220701",
  "format": "json",
  "providerId": "02",
  "signType": "00",
  "timestamp": "20240426062455",
  "bizData": "{...}"
}
```

### 3.3 兼容性说明

在 Spring Boot 2.x+ 中，如果项目中配置了 Jackson 消息转换器，`@ModelAttribute` **可能**可以绑定 JSON 请求体。但这不是标准用法，建议：

1. **方案一（推荐）：** 修改测试工具，使用 `application/x-www-form-urlencoded` 格式发送
2. **方案二：** 修改代码，将 `@ModelAttribute` 改为 `@RequestBody`

## 六、修复建议

### 6.1 路径问题（必须修复）

**临时方案：** 修改测试请求路径，添加前缀：
```
/itptvm/ci/tvm/...
/itpbom/ci/bom/...
```

**长期方案：** 如果测试工具无法修改，可以考虑在控制器上添加无前缀的映射（但会增加维护成本）。

### 6.2 请求方式问题（建议修复）

**推荐方案：** 确认 Spring Boot 的 `HttpMessageConverters` 配置，确保 `@ModelAttribute` 可以解析 JSON Body。如果不能，需要：

```java
// 方案1：修改为 @RequestBody
public JSONObject requestGenSjtOrder(@RequestBody BaseRequestDTO baseRequest)

// 方案2：或保持 @ModelAttribute，但测试端使用 form-data 发送
```

### 6.3 测试数据完善建议

| 接口 | 建议补充的测试场景 |
|------|--------------------|
| `requestGenSjtOrder` | `singleTicketType=1` 时不需要 entry/exitStationCode |
| `requestPayment` | paymentCode=ALIPAY/WEIXIN 等不同渠道 |
| `notiBusResult` | optResult=SUCCESS 的业务成功场景 |
| `notiTakeTicketFailResult` | errorCode=2101（二维码超时）场景 |
