### 1.7 签约结果确认方式

**设计决策**：支付宝渠道采用**同步确认**模式，与地铁APP的异步回调模式不同。

| 渠道 | 签约结果确认方式 | 说明 |
|------|----------------|------|
| 地铁APP | 异步回调 | 支付平台回调 `/app/receiveSignResult`，更新 `APP_PAY_SIGN_INFO` |
| 支付宝 | **同步确认** | `/channel/addContract` 返回成功即视为签约成功，**不需要后续回调** |

**原因**：根据《青岛地铁-ITP与APP接口规范》，支付宝侧未定义签约结果回调接口（如 `/notify/receiveSignResultFromAlipay`），因此采用同步确认。

**实现要点**：
- `PaySignServiceImpl.requestSignInfo()` 执行成功后，`SIGN_STATUS` 直接设置为签约成功状态
- `SIGN_TIME` 记录为当前时间
- 无需实现 `/alipayTrip/receiveSignResult` 回调接口
- 解约同样采用同步确认模式

/**
 * 支付宝出行-添加签约信息。
 * <p>
 * 支付宝渠道完全独立，不需要对接支付平台的签约接口。

**处理流程：**
1. 校验参数（`thirdUserId`、`channel`、`agreementCode`、`channelUserAccount`）
2. 检查是否已签约（`paySignInfoMapper.selectByUserAndVendor`）
3. **不调用支付平台**，直接写入 `APP_PAY_SIGN_INFO`（`SIGN_CHANNEL = 'ALIPAY'`、`SIGN_STATUS = 'SIGNED'`）
4. 写入流水表 `APP_PAY_SIGN_REQUEST`（`OPERATION_TYPE = 'ALIPAY_TRIP_REQUEST_SIGN_INFO'`）
5. 返回成功响应（`requestStartSdkInfo = null`）

## 五、支付宝签约信息字段映射详表

### 5.1 总体映射关系

支付宝出行签约信息统一写入现有 `APP_PAY_SIGN_INFO` 表和 `APP_PAY_SIGN_REQUEST` 表，通过 `SIGN_CHANNEL = 'ALIPAY'` 区分渠道。

| 支付宝接口 | 对应签约表 | 签约渠道 | 映射入口 | 确认方式 |

### 5.4 签约结果确认方式

> **重要**：支付宝渠道采用**同步确认**模式，与地铁APP的异步回调模式不同。
> 
> - **地铁APP**：`/app/receiveSignResult` 接收支付平台回调，异步更新签约状态
> - **支付宝**：`/channel/addContract` 返回成功即视为签约成功，**不需要后续回调确认**

#### 同步确认逻辑

支付宝添加签约信息时，`PaySignServiceImpl.alipayTripRequestSignInfo()` 执行流程：

1. 校验参数（`thirdUserId`、`channel`、`agreementCode`、`channelUserAccount`）
2. 检查是否已签约（`selectByUserAndVendor`）
3. **不调用支付平台**，直接写入 `APP_PAY_SIGN_INFO`（`SIGN_CHANNEL = 'ALIPAY'`、`SIGN_STATUS = 'SIGNED'`）
4. 写入流水表 `APP_PAY_SIGN_REQUEST`（`OPERATION_TYPE = 'ALIPAY_TRIP_REQUEST_SIGN_INFO'`）
5. 调用 account 服务补充支付通道（`THIRD_PAY_ID`、`REQ_CONTRACT_NO`）
6. 返回成功响应（`requestStartSdkInfo = null`）

此时 `SIGN_STATUS` 直接设置为签约成功状态，`SIGN_TIME` 记录为当前时间。

**关键特性**：支付宝渠道完全独立，不需要对接支付平台的签约接口，记录成功即视为签约成功。

##### 调用 account 服务补充支付通道

签约成功后，`PaySignServiceImpl` 会调用 account 服务完成两件事：

| 步骤 | account 方法 | 映射关系 | 说明 |
|------|-------------|---------|------|
| 1 | `requestAddPayChannel` | `channelUserAccount` -> `THIRD_PAY_ID`<br>`agreementCode` -> `REQ_CONTRACT_NO` | 添加支付通道到 `APP_USER_PAY_CHANNEL` |
| 2 | `requestSetDefaultPayChannel` | `channel` -> `CHANNEL` | 将该支付通道设为默认支付通道 |

account 服务会同步更新 `USER_ITP_REG_INFO` 表中的 `THIRD_PAY_ID`、`CHANNEL`、`REQ_CONTRACT_NO`。

#### 无需回调的原因

根据《青岛地铁-ITP与APP接口规范》，支付宝侧未定义签约结果回调接口（如 `/notify/receiveSignResultFromAlipay`），因此采用同步确认。

| 回调 DTO 字段 | 字段类型 | 签约表字段 | 映射规则 | 说明 |
|--------------|---------|-----------|---------|------|
| `requestSignSeq` | String | `REQUEST_SIGN_SEQ` | 直接映射 | 签约流水号 |
| `thirdUserId` | String | `THIRD_USER_ID` | 直接映射 | 第三方用户ID |
| `signStatus` | String | `SIGN_STATUS` | 直接映射 | 签约状态 |
| `cardId` | String | `CARD_ID` | 直接映射 | 卡ID |
| `cardType` | String | `CARD_TYPE` | 直接映射 | 卡类型 |
| `payAccountId` | String | `PAY_ACCOUNT_ID` | 直接映射 | 支付账号ID |
| `payAgreementNo` | String | `PAY_AGREEMENT_NO` | 直接映射 | 支付协议号 |
| `displayAccount` | String | `DISPLAY_ACCOUNT` | 直接映射 | 展示账号 |
| — | — | `SIGN_TIME` | 回调时间 | 签约时间 |
| — | — | `SIGN_CHANNEL` | 固定 `ALIPAY` | 签约渠道 |

### 5.7 数据隔离与查询

#### 渠道隔离

支付宝签约数据与地铁APP签约数据通过 `SIGN_CHANNEL` 字段隔离：

```sql
-- 查询支付宝所有签约信息
SELECT * FROM APP_PAY_SIGN_INFO WHERE SIGN_CHANNEL = 'ALIPAY';

-- 查询支付宝所有解约请求
SELECT * FROM APP_PAY_SIGN_REQUEST WHERE SIGN_CHANNEL = 'ALIPAY';

-- 查询支付宝签约流水
SELECT * FROM APP_PAY_SIGN_LOG WHERE PAYMENT_VENDOR = 'ALIPAY';
```

#### 联合查询示例

```sql
-- 查询支付宝用户签约及解约记录
SELECT 
    info.REQUEST_SIGN_SEQ,
    info.THIRD_USER_ID,
    info.SIGN_STATUS AS 签约状态,
    info.SIGN_TIME AS 签约时间,
    req.SIGN_STATUS AS 解约状态,
    req.TERMINATION_TIME AS 解约时间
FROM APP_PAY_SIGN_INFO info
LEFT JOIN APP_PAY_SIGN_REQUEST req 
    ON info.REQUEST_SIGN_SEQ = req.REQUEST_SIGN_SEQ 
    AND info.THIRD_USER_ID = req.THIRD_USER_ID
WHERE info.SIGN_CHANNEL = 'ALIPAY'
  AND info.THIRD_USER_ID = '第三方用户ID';
```
