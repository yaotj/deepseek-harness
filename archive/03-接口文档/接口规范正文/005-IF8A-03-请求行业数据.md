# IF8A-03 请求行业数据

> **接口编号**: IF8A-03
> **接口类型**: 请求类（APP 主动调用）
> **接口路径**: `/ci/app/requestIndustryData`
> **请求方式**: POST
> **消费端**: 地铁 APP
> **提供端**: industry-data-server（行业数据服务）
> **上游服务**: fep-app-server（RPC 转发）
> **源码位置**: `industry-data-server/src/main/java/com/chinasofti/huateng/industry/controller/IndustryDataController.java`
> **整理时间**: 2026-07-28

---

## 一、接口功能

请求二维码行业数据接口。APP 调用此接口获取二维码行业数据，用于生成乘车二维码。

**注意**：此接口在项目中有多个实现：
- `industry-data-server` - 标准行业数据服务
- `fep-alipay-server` - 支付宝出行行业数据

---

## 二、请求参数

### 2.1 请求示例

```json
{
  "thirdUserId": "2088000123456789",
  "cardId": "CARD123456789",
  "cardType": "03"
}
```

### 2.2 请求字段定义

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| thirdUserId | String | 是 | 第三方用户ID | `2088000123456789` |
| cardId | String | 是 | 地铁会员卡号 | `CARD123456789` |
| cardType | String | 是 | 卡类型编码（03=二维码，04=HCE） | `03` |
| upgradeAreaType | String | 否 | 补站类型（01=补进站，02=补出站） | `01` |
| upgradeStationCode | String | 否 | 补站车站代码 | `0101` |
| upgradeReason | String | 否 | 更新原因预留 | - |
| upgradeDateTime | String | 否 | 更新操作时间（YYYYMMDD24mmss） | `20260728100000` |

### 2.3 字段校验规则

1. `thirdUserId` 不能为空
2. `cardId` 不能为空
3. `cardType` 不能为空
4. 用户必须已开户注册
5. 用户状态不能为解约审核中

---

## 三、响应参数

### 3.1 响应示例

```json
{
  "retCode": "0000",
  "retMsg": "成功",
  "industryData": "encrypted_industry_data",
  "qrCodeUrl": "https://..."
}
```

### 3.2 响应字段定义

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| retCode | String | 是 | 返回码 | `0000` |
| retMsg | String | 是 | 返回消息 | `成功` |
| industryData | String | 否 | 行业数据（加密） | `encrypted_industry_data` |
| qrCodeUrl | String | 否 | 二维码地址 | `https://...` |

### 3.3 错误码说明

| 错误码 | 含义 | 说明 |
|--------|------|------|
| 0000 | SUCCESS | 成功 |
| 9999 | FAIL | 系统异常 |
| 8001 | INVALID_PARAM | 参数无效 |
| 8004 | USER_NOT_REGISTERED | 用户未注册 |
| 8006 | CARD_ID_MISMATCH | 卡号不一致 |
| 8007 | PARTNER_ERROR | 合作伙伴验证失败 |
| 8008 | USER_UNDER_REVIEW | 用户解约审核中 |

## 四、业务流程

### 4.1 调用链路

```
APP
  → fep-app-server (/ci/app/requestIndustryData)
    → IndustryDataClient.requestIndustryData()
      → industry-data-server (/ci/app/requestIndustryData)
        → IndustryCardDataServiceImpl.requestIndustryData()
          → 1. 参数校验
          → 2. 查询 QRCodeStatus 获取当前状态
          → 3. 构建行业卡数据（INDUSTRY_CARD_DATA）
          → 4. 推送至 ACC/行业服务
          → 5. 返回行业数据
```

### 4.2 业务逻辑

1. **参数校验** - 校验 `thirdUserId`、`cardId`、`cardType` 是否为空
2. **查询票卡状态** - 根据 `cardId` 查询 `QRCODE_STATUS` 获取当前状态
3. **构建行业卡数据** - 根据 `QRCODE_STATUS` 构建 `INDUSTRY_CARD_DATA` 数据
4. **推送至 ACC** - 推送至 ACC/行业服务供闸机/终端下发到手机
5. **返回结果** - 返回行业卡数据、状态、二维码地址等

## 七、注意事项

1. **行业数据加密**：行业数据经过 ACC 加密后返回给 APP
2. **二维码有效期**：二维码生成后有有效期限制，过期需重新请求
3. **补站处理**：`upgradeAreaType`/`upgradeStationCode` 用于自助补站场景
4. **HCE 与二维码**：HCE 卡（03/04）和二维码卡的行业数据格式可能不同
