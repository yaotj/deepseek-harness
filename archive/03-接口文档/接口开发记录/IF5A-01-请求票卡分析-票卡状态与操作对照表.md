# IF5A-01 请求票卡分析 - 票卡状态与操作对照表

## 1. 接口基本信息

| 项目 | 内容 |
|------|------|
| **接口地址** | `POST /ci/bom/requestCardDataAnalyse` |
| **接口说明** | 后付费二维码票分析 |
| **请求参数** | providerId、msisdn、cardId、updateType |
| **应答参数** | retCode、retMsg、providerId、cardIssueDate、msisdn、cardId、cardStatus、lastLineCode、lastStationCode、lastUpdateDate、lastTransAmout、lastTikcetTransSeq、adviceOpt、managerCode、transAmount |

---

## 2. 核心字段定义

| 字段 | 代码 | 含义 |
|------|------|------|
| **付费区标 (updateType)** | `00` | 非付费区（TVM/人工窗口前） |
| | `01` | 付费区（闸机内） |
| **车票状态 (CODE_STATUS)** | `03` | 默认/初始状态 |
| | `04` | 已进站（付费区内） |
| | `05` | 已出站 |
| **特殊站点编码** | `FFFF` | 表示未进站/未出站（空值占位） |
| **建议操作 (adviceOpt)** | `000` | 无需更新 |
| | `018` | 补进站（无法出站） |
| | `006` | 补出站（最低票价，无法进站） |
| | `005` | 20分免费进站更新（无法进站） |

## 3. 票卡状态与操作关系全景矩阵表

### 3.1 非付费区 (updateType = 00)

| 业务场景 | 票卡当前状态 | 闸机表现 | 建议操作 (adviceOpt) | BOM操作员可执行操作 | 费用 (transAmount) | FFFFF处理规范 |
|---------|------------|---------|-------------------|------------------|-----------------|-------------|
| **正常进站** | 行程已闭环，状态正常 | ✅ 开闸 | `000` | 无需操作 | 免费 | 基准场景；若 `lastStationCode=FFFF` 但状态正常，视为新卡/数据重置，不影响进站 |
| **🔹 同站20分钟内折返** | 有本次进站记录，且进出同站、时间 ≤ 20min | ❌ 拒进/拒出 | `005` | 免费更新：清除进站标记，复位票卡 | 0 (免费) | 🔴 **FFFF 拦截**：若 `lastStationCode=FFFF`，禁止返回 `005`，降级为人工核实模式，防止误免费放行 |
| **历史缺出站** | 有历史进站记录，无对应出站记录 | ❌ 拒进 | `006` | 补出站：按规则扣除最低票价或实际票价 | 扣费 | 🔴 **FFFF 计费降级**：若 `lastStationCode=FFFF`，无法计算实际票价，强制按线网最低票价扣费，BOM 需显示"⚠️ 站点未知，按最低票价计费"提示 |
| **其他异常** | 黑名单/挂失/过期等 | ❌ 拒进 | 其他异常码 | 拦截/引导购票 | - | 票卡级异常，与 FFFF 无关；但若同时存在 FFFF，优先处理票卡级异常 |

### 3.2 付费区 (updateType = 01)

| 业务场景 | 票卡当前状态 | 闸机表现 | 建议操作 (adviceOpt) | BOM操作员可执行操作 | 费用 (transAmount) | FFFFF处理规范 |
|---------|------------|---------|-------------------|------------------|-----------------|-------------|
| **正常出站** | 有完整本次进-出匹配 | ✅ 开闸 | `000` | 无需操作 | 免费 | 基准场景；`FFFF` 不应出现在此状态的 `lastStationCode` 中，若出现需记录告警日志 |
| **🔹 本次缺进站** | 无本次进站记录（尾随进站等） | ❌ 拒出 | `018` | 补进站：询问并补录进站站点 | 扣费 | 🔴 **FFFF 防脏数据**：若 `lastStationCode=FFFF`，BOM 补进站下拉框禁止预填任何值，强制操作员手动选择有效站点，提交按钮置灰直至选择完成 |
| **乘车超时** | 付费区内停留超规定时限 | ❌ 拒出 | 超时异常码 | 超时补票：收取超时费 | 扣费 | 与 FFFF 无直接关联，但若 `lastStationCode=FFFF` 且需追溯进站时间，以 `lastUpdateDate` 为准，不依赖站点信息 |

## 4. FFFF 全链路处理要点

### 4.1 后端分析逻辑前置校验

所有涉及 `lastStationCode` 的业务判断（尤其是 005 同站判断、006 计费计算），必须先执行 `"FFFF".equalsIgnoreCase(lastStationCode)` 校验，通过后再进入正常业务分支，未通过则走降级/人工兜底分支。

### 4.2 BOM 前端交互强约束

FFFF 场景下，所有自动化操作按钮必须禁用或增加二次确认弹窗，所有金额展示必须附带"站点未知"警示标识，杜绝操作员误操作导致的资损或客诉。

### 4.3 大小写兼容与日志标记

FFFF 校验必须忽略大小写（兼容 `ffff`、`FfFf` 等变体），同时在 BOM 操作日志和服务端分析日志中增加 `WARN_STATION_FFFF` 标记，便于后续数据统计与问题追溯。

### 4.4 接口文档显式声明

在接口契约中明确 FFFF 的语义、触发场景及处理要求，避免上下游系统对占位符的理解不一致。

## 6. 边界情况与返回码

| 场景 | 返回码 | 返回消息 |
|------|--------|---------|
| 请求参数为空 | `8001` | `cardId不能为空` / `adviceOpt不能为空` 等 |
| 卡号不存在 | `8004` | `没有账号卡片数据` |
| 不支持的 adviceOpt | 错误码 | `不支持的操作类型` |
| 成功 | `0000` | `成功` |

## 9. 发行方用户信息查询逻辑

| 发行方 | providerId | 用户信息查询路径 | msisdn 来源 | cardIssueDate 来源 |
|--------|-----------|-----------------|------------|------------------|
| 地铁 App | `01/02/03` 等 | `account-server` → `queryCardTypeByCardId` → `queryUserInfo` | `QueryUserInfoResult.msisdn` | `QueryUserInfoResult.regTms` |
| 支付宝 | `07` | `account-server` → `queryCardTypeByCardId` → `alipay-account-server` → `selectByThirdUserId` | `AlipayUserInfoDTO.phone` | 空（支付宝暂无注册时间） |

**注意**：`msisdn` 优先使用请求参数中的值作为回退：
```java
String msisdn = defaultString(request.getMsisdn(), "");
```
