## 4. 数据验证SQL

### 4.1 验证票卡状态更新

```sql
-- 查询票卡状态
SELECT CARD_ID, CODE_STATUS, GATE_IN_TIME, GATE_IN_STATION, LAST_TXN_TIME, LAST_TXN_STATION, TXN_SEQ, UPDATE_TIME
FROM QRCODE_STATUS
WHERE CARD_ID = 'TEST001';

-- 验证要点：
-- 1. CODE_STATUS 是否更新为预期值（04/05）
-- 2. GATE_IN_STATION 在补进站时是否更新
-- 3. LAST_TXN_STATION 在补出站时是否更新
-- 4. GATE_IN_TIME / LAST_TXN_TIME 是否更新为 upgradeDateTime
-- 5. TXN_SEQ 是否保持不变
-- 6. UPDATE_TIME 是否更新为当前时间
```

### 4.2 验证交易明细

```sql
-- 查询交易明细
SELECT ID, CARD_ID, TRX_TYPE, HANDLE_STATION_CODE, TRX_AMOUNT, OVERTIME_AMOUNT, 
       LAST_TICKET_STATUS, TICKET_TRANS_SEQ, CREATE_TIME
FROM QRCODE_TXN_DETAIL
WHERE CARD_ID = 'TEST001'
ORDER BY CREATE_TIME DESC;

-- 验证要点：
-- 1. TRX_TYPE 是否为 01（补进站）或 02（补出站）
-- 2. HANDLE_STATION_CODE 是否为 upgradeStationCode
-- 3. TRX_AMOUNT 是否为 0（Phase 1）
-- 4. OVERTIME_AMOUNT 是否为 0
-- 5. LAST_TICKET_STATUS 是否为操作前的 CODE_STATUS
-- 6. TICKET_TRANS_SEQ 是否与 QRCODE_STATUS.TXN_SEQ 一致
-- 7. CREATE_TIME 是否为当前时间
```

### 4.3 验证无脏数据

```sql
-- 验证失败场景无数据写入
SELECT COUNT(*) as detail_count
FROM QRCODE_TXN_DETAIL
WHERE CARD_ID = 'TEST006' AND CREATE_TIME > SYSTIMESTAMP - 1/24;

-- 预期结果：detail_count = 0
```

## 7. 注意事项

1. **测试数据隔离**：使用 TEST 前缀的卡号，避免与生产数据冲突
2. **数据清理**：每次测试前后执行清理 SQL，保证测试环境干净
3. **状态码匹配**：补站后 codeStatus 映射：01→04, 02→05
4. **交易类型匹配**：补进站 TRX_TYPE='01', 补出站 TRX_TYPE='02'
5. **金额固定**：Phase 1 阶段 TRX_AMOUNT 固定为 0，OVERTIME_AMOUNT 固定为 0
6. **时间格式**：upgradeDateTime 格式为 YYYYMMDDHH24MISS（14位）
7. **FFFH处理**：当前版本不检查 FFFFF，直接按 codeStatus 判断
8. **08/09/10状态**：统一返回"请到服务台处理"，不写数据库

## 8. 问题排查

| 问题 | 可能原因 | 排查方法 |
|------|---------|---------|
| 返回 8001 但预期成功 | codeStatus 与 upgradeAreaType 不匹配 | 查询 QRCODE_STATUS 确认当前状态 |
| 数据库无更新 | 参数校验失败 | 检查请求参数是否完整 |
| 交易明细未生成 | 状态校验失败 | 查看日志确认是否在 allowedTypes 判断阶段返回 |
| 状态更新错误 | upgradeAreaType 映射错误 | 确认 01→04, 02→05 映射关系 |
